CNA-BUG-203: SdlGpu_2D_HeadlessDriver forces headless mode under the x11 video driver that the SDL_GPU constructor refuses for it

On non-Windows hosts the SDL_GPU headless registrations reuse the ordinary test environment (SDL_VIDEODRIVER=x11 by default), but SdlGpu_2D_HeadlessDriver also sets CNA_SDLGPU_TEST_FORCE_HEADLESS=1, which the constructor accepts only under dummy or offscreen.

Affected contract
The <code>SdlGpu_2D_HeadlessDriver</code> CTest (SDLGPU-102) and the <code>CNA_SDLGPU_TEST_VIDEO_DRIVER</code> cache option

Expected behaviour

SDLGPU-102's registration comment: run "the canonical, unchanged Game-based Texture2D/SpriteBatch scene with a normal platform window ... while replacing only SDL_gpu presentation with the renderer-owned virtual backbuffer". A routinely registered CTest should pass in the default configuration of the host it is registered for.

Actual behaviour at TARGET

In modules/renderers/sdl-gpu/examples/CMakeLists.txt, CNA_SDLGPU_TEST_VIDEO_DRIVER defaults to x11 on Linux-like hosts, making CNA_SDLGPU_TEST_ENVIRONMENT SDL_VIDEODRIVER=x11;DISPLAY=...;WAYLAND_DISPLAY=; on non-Windows hosts CNA_SDLGPU_HEADLESS_TEST_ENVIRONMENT is the same string. SdlGpu_2D_HeadlessDriver appends CNA_SDLGPU_TEST_FORCE_HEADLESS=1. SdlGpuRenderer::SdlGpuRenderer throws "CNA_SDLGPU_TEST_FORCE_HEADLESS=1 requires the SDL dummy or offscreen video driver" whenever the switch is set, a window exists (the 2D test is a Game) and SDL_GetCurrentVideoDriver() is not dummy or offscreen. With a display present the test fails at device creation; without one, ProbeGpuDisplayAvailable skips it. Only a configuration with CNA_SDLGPU_TEST_VIDEO_DRIVER=dummy or offscreen can pass it.

Evidence

CNA's own record executed it: SdlGpu_2D_HeadlessDriver is in PSG-0009's list of classic SDL_GPU failures (private compositor, one Radeon 780M under RADV) and remains among the 26 failures of the latest recorded run (STREETS-0008). That the forced-headless refusal is the cause is by reading at 009d40f5; the failing run's log is not in the tree. The same record names 24 further failing classic SDL_GPU tests that are not analysed here: SdlGpu_BackbufferFormat, SdlGpu_ConstructorExceptionSafety, SdlGpu_Deferred_Scissor, SdlGpu_DepthBias, SdlGpu_DepthlessCube_SpriteBatchCompatibility, SdlGpu_DrawLineTopology, SdlGpu_EasyGLOracle_depthstencilstate_stencil_twosided, SdlGpu_EasyGLOracle_draw_range_validation, SdlGpu_EasyGLOracle_surface_format_throws, SdlGpu_Parity_compressed_cube, SdlGpu_Parity_compressed_cube_fallback, SdlGpu_Parity_dual_texture_terms, SdlGpu_RenderState, SdlGpu_RenderTargetCube_Formats, SdlGpu_RenderTargetCube_MsaaMip, SdlGpu_RenderTarget_SetData, SdlGpu_SwapchainRecovery, SdlGpu_Texture2D_FormatMatrix, SdlGpu_Texture2D_FormatMatrixFallback, SdlGpu_TextureCube_FormatMatrix, SdlGpu_TextureCube_FormatMatrixFallback, SdlGpu_TextureFilterMipContract, SdlGpuIndexedDrawRangeTest.MutatingSourceBuffersAfterQueuingDoesNotChangeQueuedDraws and SdlGpuIndexedDrawRangeTest.RejectsIndexedRangesOutsideTheBoundBuffers. The 26th, SdlGpu_OcclusionQuery_Limitation, is analysed under CNA-BUG-012.

Focused reproduction

# Not executed for this entry. A Linux SDL_GPU build with tests and the default CNA_SDLGPU_TEST_VIDEO_DRIVER (x11), on a host with a display:
ctest --test-dir <sdl-gpu build> -R '^SdlGpu_2D_HeadlessDriver$' --output-on-failure
# A build configured with -DCNA_SDLGPU_TEST_VIDEO_DRIVER=offscreen is expected to pass it.

Current tests

SdlGpu_HeadlessGraphicsDevice uses the same environment but creates its device without a window, so the refusal does not apply; SdlGpu_2D runs the same scene without the switch. Nothing checks that a registration setting CNA_SDLGPU_TEST_FORCE_HEADLESS=1 also selects an isolated video driver.

Regression test

Give the forced-headless registrations an isolated driver on non-Windows hosts (for example SDL_VIDEODRIVER=offscreen;DISPLAY=;WAYLAND_DISPLAY= in CNA_SDLGPU_HEADLESS_TEST_ENVIRONMENT) and re-run the classic ^SdlGpu set to confirm the test leaves the failure list.

Blast radius

Test evidence for SDL_GPU on Linux-like hosts: one routinely registered CTest fails for a configuration reason and inflates the recorded failure count, and the forced-headless presentation path itself goes unexercised there. On Windows the headless registrations select SDL's dummy driver and are unaffected.

Workaround

Configure with -DCNA_SDLGPU_TEST_VIDEO_DRIVER=offscreen (or dummy) when running the headless SDL_GPU tests.
