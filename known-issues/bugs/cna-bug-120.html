CNA-BUG-120: ContentManager::LoadXnbAssetUntyped refuses LZ4, which LoadXnbAsset<T> decodes

The untyped decoder behind EffectMaterial external references throws for MonoGame LZ4 payloads that the typed load path decodes. Its missing compressed-header guard was fixed on 2026-10-22.

Affected contract
ContentReader::ReadExternalReference() (untyped, CNAEXT; @throws ContentLoadException if the referenced compiled asset cannot be loaded) via ContentManager::LoadUntypedXnbReference / LoadXnbAssetUntyped

Expected behaviour

The untyped decoder decodes exactly like LoadXnbAsset<T> (ContentManager.hpp): MonoGame LZ4 payloads are decoded with DecompressXnbLz4Payload.

Actual behaviour at TARGET

The LZ4 branch of LoadXnbAssetUntyped (ContentManagerUntyped.cpp) throws ContentLoadException "uses MonoGame's Lz4 compression, which CNA does not yet support", while the typed decoder decodes it with DecompressXnbLz4Payload. So an EffectMaterial parameter that references an LZ4 texture fails, although Load<Texture2D> of the same file succeeds.

Source locations

  • modules/content/src/Xna/ContentManagerUntyped.cpp — ContentManager::LoadXnbAssetUntyped - LZ4 refused
  • modules/content/include/Microsoft/Xna/Framework/Content/ContentManager.hpp — ContentManager::LoadXnbAsset - the typed decoder with DecompressXnbLz4Payload
  • modules/content/src/Xna/ContentManager.cpp — ContentManager::ReadXnbHeader - the shared header checks (the fixed half)
  • modules/content/src/Xnb/EffectMaterialContentTypeReaders.cpp — ExternalReferenceReader::Read

Evidence

Checked by reading at c6dec91f; not executed.

Narrowed at c6dec91f: 583af2a5e (CNA-DEMOS-ISSUE-039/045) moved the header checks into the shared ContentManager::ReadXnbHeader, which both loaders call: it refuses a totalLength outside [10, file size] and, for a compressed file, one below 14 before the size field is read, so the 10-13-byte over-read this entry also described is gone (ContentManagerXnbTest.UntypedCompressedHeaderRefusesBeforeReadingBeyondTheFile and UntypedExternalReferencesWrapEveryTruncatedHeader in ContentManagerXnbTests.cpp). The LZ4 refusal is unchanged.

Focused reproduction

Illustrative; not compiled.

// Content/params.xnb: an EffectMaterial / Dictionary<string, object> whose value is an\n// external reference to "tex"; Content/tex.xnb = tests/assets/xnb/monogame/windows/lz4/white-1.xnb.\nauto values = content.Load<std::map<std::string, std::any>>("params");\n// ContentLoadException "... Lz4 compression, which CNA does not yet support",\n// although content.Load<Graphics::Texture2D>("tex") decodes it.

Current tests

EffectMaterialContentTypeReaderTests.cpp (ExternalReferenceReaderPreservesReferencedTextureCubeConcreteType) uses an uncompressed fixture, and the new untyped header tests cover truncation only; no test sends an LZ4 asset through an untyped reference.

Regression test

A case beside the existing one: the same dictionary referencing the LZ4 fixture tests/assets/xnb/monogame/windows/lz4/white-1.xnb must yield a Texture2D.

Blast radius

Only untyped external references, which today means ExternalReferenceReader inside EffectMaterial parameter dictionaries. Typed references (ReadExternalReference<T>) and direct Load<T> calls use LoadXnbAsset<T> and are unaffected.

Workaround

Keep textures referenced by EffectMaterial content uncompressed or LZX-compressed.
