CNA-BUG-187: modules/renderers/CMakeLists.txt enters the shared D3D and GDI helper directories only when DIRECTX11/12 or GDI is the default

Before its per-family loop the file adds common/d3d, and the GDI configuration of software, only when the default renderer matches, so a Windows multi-renderer build with DIRECTX11, DIRECTX12 or GDI as a non-default member lacks the targets it links.

Affected contract
<code>CNA_GRAPHICS_RENDERERS</code> multi-renderer builds on Windows that <code>cmake/RendererCombinations.cmake</code> accepts

Expected behaviour

A set accepted by cna_validate_renderer_combination builds. The loop's own comment says each family must be entered with its own identity re-established regardless of which member is the default, and docs/runtime-renderer-selection.md lists the only refused sets (PORTABLEGL beside real GL, GDI beside SOFTWARE, cross-platform pairs).

Actual behaviour at TARGET

Two helper entries sit before the loop and read CNA_GRAPHICS_RENDERER, which at that point names the default: add_subdirectory(common/d3d) only if it is DIRECTX11 or DIRECTX12, and add_subdirectory(software) (the GDI configuration that publishes CNA_GDI_SOFTWARE_SOURCES and defines cna_renderer_software_headers) only if it is GDI. The loop then enters directx11 and directx12, which link cna_renderer_d3dcommon PUBLIC and whose public headers include D3DCommon headers, and gdi, which calls cna_add_renderer(${CNA_GDI_SOFTWARE_SOURCES}) and links cna_renderer_software_headers. With DIRECTX9;DIRECTX11 (default DIRECTX9) or DIRECTX11;GDI (default DIRECTX11), the non-default family refers to a target that was never created and compiles without the headers it includes; neither set is refused by the combination rules.

Source locations

  • modules/renderers/CMakeLists.txt — pre-loop guards for common/d3d and the GDI software configuration; the per-family loop
  • modules/renderers/directx11/CMakeLists.txt — links cna_renderer_d3dcommon PUBLIC
  • modules/renderers/directx12/CMakeLists.txt — links cna_renderer_d3dcommon PUBLIC
  • modules/renderers/common/d3d/CMakeLists.txt — defines cna_renderer_d3dcommon
  • modules/renderers/gdi/CMakeLists.txt — cna_add_renderer(CNA_GDI_SOFTWARE_SOURCES) and cna_renderer_software_headers
  • modules/renderers/software/CMakeLists.txt — GDI branch publishing CNA_GDI_SOFTWARE_SOURCES and cna_renderer_software_headers
  • cmake/RendererCombinations.cmake — cna_validate_renderer_combination accepts these sets

Evidence

Checked by reading at 009d40f5; no Windows multi-renderer build was configured. CMake treats a target_link_libraries item that names no target as a plain library name, so the D3D case would surface as a compile error (missing D3DCommon include root) or a link error rather than as a clear configure message; the GDI case loses the shared CPU-2D sources and the Software include root. No CI job or CNA record builds a Windows multi-renderer set; the verified sets in docs/runtime-renderer-selection.md are all non-Windows.

Focused reproduction

# Not executed for this entry (needs a Windows toolchain).
cmake -S . -B build -DCNA_GRAPHICS_RENDERER=DIRECTX9 -DCNA_GRAPHICS_RENDERERS="DIRECTX9;DIRECTX11"
cmake --build build

Current tests

CnaRendererDefaultSelection_* and scripts/check_renderer_combinations.py check membership and the rule lists, not that every accepted set configures. CI's multi-renderer sets are HEADLESS;SOFTWARE;STUB, OPENGL33;VULKAN;SOFTWARE;HEADLESS and the Emscripten browser set.

Regression test

Move both helper entries into the loop (enter common/d3d when any member is DIRECTX11 or DIRECTX12, the GDI software configuration when GDI is a member), and configure DIRECTX9;DIRECTX11 and DIRECTX11;GDI once on the Windows cross-compile lane.

Blast radius

Windows multi-renderer builds whose default is not the DIRECTX11, DIRECTX12 or GDI member. Single-renderer builds, and sets in which that member is the default, are unaffected; no non-Windows family uses these helpers.

Workaround

Make the DIRECTX11, DIRECTX12 or GDI member the default of the set, or build those renderers separately.
