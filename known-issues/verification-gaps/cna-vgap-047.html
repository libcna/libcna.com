CNA-VGAP-047: Test strength is never measured automatically: no coverage build, no fuzzing campaign, and the Direct2D mutation checker only dry-runs

No workflow or CMake option enables coverage instrumentation, the libFuzzer-capable harnesses are not CTests and run in no campaign, and direct2d_mutation_check.py runs only as --dry-run in a manual workflow.

Affected contract
CNA's test-strength instruments: coverage, fuzzing, mutation checking

Expected behaviour

Instruments that CNA has built to measure its tests are run often enough to produce current numbers.

Actual behaviour at TARGET

No workflow and no file under cmake/ adds --coverage or configures gcov, lcov, gcovr or llvm-cov; cnaext-coverage.md records one --coverage build of 2026-08-18. Harnesses.cmake builds cna_compiled_effect_fuzzer, cna_xna_model_fuzzer and cna_xna_intermediate_fuzzer and states they are not registered as CTests; the C ABI fuzz sources are an object library only (c-api CMakeLists). Only deterministic fuzz-named GoogleTests run. d3d-windows-ci.yml (manual) runs direct2d_mutation_check.py with --dry-run, which checks only that each mutation's anchor still applies; the --run mode that rebuilds and requires the targeted test to fail is never automated.

Source locations

  • cmake/Harnesses.cmake — fuzzer targets, not registered as CTests
  • modules/c-api/CMakeLists.txt — cna_c_api_fuzz_targets object library
  • docs/cnaext-coverage.md — the one recorded coverage build
  • scripts/direct2d_mutation_check.py — --dry-run versus --run
  • .github/workflows/d3d-windows-ci.yml — manual dry-run invocation

Regression test

A scheduled coverage job, a scheduled short fuzzing campaign per harness with a corpus, and a scheduled --run of the mutation checker.
