Which sharp-runtime revision goes with each tag

Since 0.1.0 the build checks the sibling's declared version: the root {{src:CMakeLists.txt}} adds whatever checkout CNA_SHARP_RUNTIME_ROOT points at (default ../sharp-runtime), and {{src:cmake/DependencyVersions.cmake}} accepts sharp-runtime 0.1.0 or a later 0.1.x; see {{page:deep-dives/sharp-runtime/components-and-consumption.html#revision|which sharp-runtime a CNA build uses}}. The check compares versions, not commits, so it cannot tell sharp-runtime’s v0.1.0 tag from its later next commits, which still declare 0.1.0; the 0.1.0 changelog records the exact commit verified with the release (c20373bae5be1f02d1fe2fa33c4cbba8ad05e4a0, tag v0.1.0). For alpha.1 nothing was checked; the “Dependency pins” part of its changelog entry in {{src:CHANGELOG.md}} records the revision it was developed against:

sharp-runtime  625476d5b5fff5fa89f392c3c9af8638ff237692  (develop, 2026-08-19)

To rebuild alpha.1 against that recorded sibling, check the commit out in a separate worktree and point the option at it, instead of moving the sibling directory. The following commands are illustrative and were not executed:

git -C sharp-runtime worktree add ../sharp-runtime-alpha1 625476d5b5fff5fa89f392c3c9af8638ff237692
cmake -S cna -B cna/build -DCNA_SHARP_RUNTIME_ROOT="$PWD/sharp-runtime-alpha1"

The third-party submodules need no such step. The gitlinks of third_party/SDL, third_party/SDL_mixer, third_party/draco and vendor/googletest are identical at alpha.1, at 0.1.0 and at the snapshot; the snapshot no longer has the third_party/SDL_image submodule, which nothing in CNA used. So git submodule update --init selects the same third-party revisions for every row of the table above. This was checked with git ls-tree at the three commits.
