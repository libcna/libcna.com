"Backend" in CNA's own identifiers

The selectable graphics implementation is a renderer: the option is CNA_GRAPHICS_RENDERER, the enum is GraphicsRendererType and the implementations live under {{tree:modules/renderers|modules/renderers}}. In CNA's own identifiers, "backend" usually names something else: an internal service implementation behind a device or network interface. Examples are ICompassBackend and IMotionBackend for the sensors (implemented on Android by AndroidCompassBackend and AndroidMotionBackend), IVibrateBackend for vibration, and ENetBackend for SystemLink networking ({{src:modules/net/include/CNA/Internal/Net/ENetBackend.hpp|ENetBackend.hpp}}).

Two graphics enums in the core module keep the older word. GraphicsBackendCategory ({{src:modules/core/include/CNA/GraphicsBackendCategory.hpp|GraphicsBackendCategory.hpp}}: Native, TranslationLayer, Software, Web, Diagnostic) and GraphicsBackendMaturity (Production, Supported, Experimental, Historical, Deprecated) classify a renderer. For example, getGraphicsBackendCategory(GraphicsRendererType) returns the category of the given renderer. They are descriptors, not a second selection axis; see {{page:development/internals/graphics/backends.html|the renderer internals}}. A source search for "backend" therefore finds both meanings. A search for "renderer" finds only the graphics one.
