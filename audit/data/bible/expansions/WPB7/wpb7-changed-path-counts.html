What "6,383 changed paths" counts

The 6,383 figure comes from git diff --shortstat v0.1.0 3b43bd86 with Git's default rename detection. That count treats each detected rename as one path. For a range this large, Git skips exhaustive rename detection and prints a diff.renameLimit warning. At these two commits Git's default name-status listing contains 587 additions, 4,083 deletions, 1,700 modifications and 13 renames. git diff --no-renames --name-status counts every rename as a deletion plus an addition and lists 6,396 records (600 / 4,096 / 1,700). Both figures are correct. The first counts files as Git pairs them; the second counts paths that appeared or disappeared. A comparison with another range should use the same flag and state it: from v0.1.0-alpha.1 to the snapshot the same commands give 10,273 (3,058 / 4,823 / 2,359 / 33 renames) and 10,306 records. (The previous snapshot, c6dec91f, gave 6,302 and 10,670 by the same commands.)
