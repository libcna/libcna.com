Where the renderer maximum comes from

GraphicsDevice::GetMaxTextureDimension() forwards to IGraphicsRenderer::GetMaxTextureDimension() ({{src:modules/graphics/include/CNA/Internal/Renderers/Common/IGraphicsRenderer.hpp|IGraphicsRenderer.hpp}}). The interface default returns 16384. Its header comment justifies the value as Direct3D feature level 11_0's REQ_TEXTURE2D_U_OR_V_DIMENSION and the value that real Vulkan, Metal and desktop GL implementations report, and calls it guaranteed on every native API the project targets. It is a rationale, not a guarantee every family's API makes: an OpenGL ES 3.0 or WebGL 2 implementation is required to offer only 2048. At this snapshot one family overrides it, and only to return the same value.

FamilyWhat GetMaxTextureDimension() returns
FNA3DThe interface default, returned explicitly. FNA3D has no maximum-texture-size query, and the source comment argues that inventing a narrower number would reject textures the renderer can create ({{src:modules/renderers/fna3d/src/Fna3dRenderer.cpp|Fna3dRenderer.cpp}})

Every other family inherits the constant, including the three EasyGL identities, DIRECTX9, SDL_GPU, WEBGPU and SOFTWARE. No family queries the device for this value, so on every family it is a documented assumption rather than a device fact: a GL or GLES device with a smaller GL_MAX_TEXTURE_SIZE still reports 16384, as the header comment's "no renderer currently needs a tighter or looser override" implies.

The profile ceiling (2048 under Reach, 4096 under HiDef) is checked first. For that reason the renderer maximum limits an ordinary Texture2D only when a family reports less than its profile allows. The value matters most in two other places:

  • Content and stream loading. The XNB Texture2D and SpriteFont readers check declared sizes against it ({{src:modules/content/src/Xnb/Texture2DContentTypeReader.cpp|Texture2DContentTypeReader.cpp}}). The DDS decoder behind DDSFromStreamEXT refuses a larger header before it decodes anything ({{src:modules/graphics/src/Xna/Texture2D.cpp|Texture2D.cpp}}).
  • Capability profile. The profile publishes the value as RendererLimit::MaxTextureDimension and marks it known whenever it is non-negative ({{src:modules/graphics/src/Xna/GraphicsDevice.cpp|GraphicsDevice.cpp}}). On an inheriting family, a "known" 16384 is therefore the interface default and was not reported by the device.

The practical rule: on every family, FNA3D included, treat the answer as an upper bound that the driver may still refuse. Checked by reading the sources above at c6dec91f and re-checked at 3b43bd86; not executed.
