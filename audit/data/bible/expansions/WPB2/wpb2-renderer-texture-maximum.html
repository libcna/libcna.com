Where the renderer maximum comes from

GraphicsDevice::GetMaxTextureDimension() forwards to IGraphicsRenderer::GetMaxTextureDimension() ({{src:modules/graphics/include/CNA/Internal/Renderers/Common/IGraphicsRenderer.hpp|IGraphicsRenderer.hpp}}). The interface default returns 16384. Its header comment gives the reason: 16384 is the single-axis ceiling guaranteed on every native API CNA targets, namely Direct3D 11/12 feature level 11_0's REQ_TEXTURE2D_U_OR_V_DIMENSION and the value that real Vulkan, Metal and GL implementations report. At this snapshot two families override it.

FamilyWhat GetMaxTextureDimension() returns
VULKANThe physical device's maxImageDimension2D, clamped to int (0 before a physical device has been selected) ({{src:modules/renderers/vulkan/src/VulkanRenderer.cpp|VulkanRenderer.cpp}})
FNA3DThe interface default, returned explicitly. FNA3D has no maximum-texture-size query, and the source comment argues that inventing a narrower number would reject textures the renderer can create ({{src:modules/renderers/fna3d/src/Fna3dRenderer.cpp|Fna3dRenderer.cpp}})

Every other family inherits the constant, including the five EasyGL identities, DIRECTX9, DIRECTX11, DIRECTX12, SDL_GPU, WEBGPU, METAL and SOFTWARE. None of them overrides the method, so on those families the value is a documented assumption rather than a device query: a GL or GLES device with a smaller GL_MAX_TEXTURE_SIZE still reports 16384. The same header comment also says that "no renderer currently needs a tighter or looser override"; Vulkan's device query above shows that this sentence is out of date.

The profile ceiling (2048 under Reach, 4096 under HiDef) is checked first. For that reason the renderer maximum limits an ordinary Texture2D only when a family reports less than its profile allows. The value matters most in two other places:

  • Content and stream loading. The XNB Texture2D and SpriteFont readers check declared sizes against it ({{src:modules/content/src/Xnb/Texture2DContentTypeReader.cpp|Texture2DContentTypeReader.cpp}}). The DDS decoder behind DDSFromStreamEXT refuses a larger header before it decodes anything ({{src:modules/graphics/src/Xna/Texture2D.cpp|Texture2D.cpp}}).
  • Capability profile. The profile publishes the value as RendererLimit::MaxTextureDimension and marks it known whenever it is non-negative ({{src:modules/graphics/src/Xna/GraphicsDevice.cpp|GraphicsDevice.cpp}}). On an inheriting family, a "known" 16384 is therefore the interface default and was not reported by the device.

The practical rule: on VULKAN, treat the answer as a device fact. On every other family, FNA3D included, treat it as an upper bound that the driver may still refuse. Checked by reading the sources above at b0e97bb1; not executed.
