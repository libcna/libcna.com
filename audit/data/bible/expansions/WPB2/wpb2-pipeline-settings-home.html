Where the effects keep their settings

Each extension holds its own parameters; there is no shared settings object, and no accessor on GraphicsDevice returns one. CRTEffect stores scanline, curvature, vignette and mask intensity (each setter clamps to 0..1) and a CRTMaskType (None, ApertureGrille or ShadowMask), and writes them as the uniforms uCrtParams and uMaskType in OnApply (CRTEffect.cpp). DepthEffect stores a DepthEffectMode and a DitherMode and writes uDepthParams; for the two palette modes it builds two small palette textures on first use (the 216-entry web-safe palette for Palette256 and the 16-entry EGA palette for Palette16) and binds one as uPalette at texture slot 1 (DepthEffect.cpp). AsciiPostProcessEffect stores a cell size (8 by 8 by default) and an AsciiQuantizeMode whose initial value comes from the CNA_ASCII_MODE environment variable (Color unless it reads blackwhite, in any case). DebugDraw keeps only its open batch and the depth-test mode. That placement is a deliberate application of the compile-time boundary described above. GraphicsDevice is an XNA type compiled in every build, while these types exist only when CNA_CNAEXT is on. A device member of one of them would give an XNA type a member whose type exists only under a compile option.

The C routes mirror the same ownership: the CRT and colour-depth routes in graphics_ext.h get and set the parameters of an ordinary CNA_EffectHandle, and the ASCII and DebugDraw routes use handles of their own. Checked by reading at b0e97bb1.
