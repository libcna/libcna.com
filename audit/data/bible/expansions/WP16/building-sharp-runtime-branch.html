sharp-runtime too old: the messages to look for

Since 0.1.0, CNA reads the version the sibling declares right after adding it and stops with the git checkout that fixes a mismatch (another minor line, a pre-release of the required version, or a checkout too old to declare a version at all). A checkout from well before sharp-runtime’s 0.1.0 release can fail even earlier, inside sharp-runtime’s own CMake: CNA hands its component closure to the sibling in SHARP_RUNTIME_COMPONENTS, and an old registry rejects the first name it does not know. Reading both repositories (the failing configure was not run), that message has the form:

CMake Error at …/sharp-runtime/cmake/SharpRuntimeComponents.cmake:<line> (message):
  Unknown Sharp Runtime component 'Resources'. Available components: Core.Base, …, All

Resources is reported first because it precedes Xml.Serialization in CNA's list ({{src:cmake/SharpRuntimeConsumption.cmake}}); sharp-runtime 0.1.0 and later provide both. The fix is the one above: git -C ../sharp-runtime checkout next for this snapshot (or v0.1.0 for the 0.1.0 release), then reconfigure. How the component selection works on both sides is on {{page:deep-dives/sharp-runtime/components-and-consumption.html#revision|sharp-runtime components and consumption}}.
