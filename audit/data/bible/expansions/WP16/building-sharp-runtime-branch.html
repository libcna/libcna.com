sharp-runtime on the wrong branch: the message to look for

When the sibling directory exists but is sharp-runtime's main or develop branch, the configure stops inside sharp-runtime's own CMake, before CNA prints its sharp-runtime shape message. CNA hands its component closure to the sibling in SHARP_RUNTIME_COMPONENTS, and the sibling's registry rejects the first name it does not know. Reading both repositories (the failing configure was not run), the message has the form:

CMake Error at …/sharp-runtime/cmake/SharpRuntimeComponents.cmake:<line> (message):
  Unknown Sharp Runtime component 'Resources'. Available components: Core.Base, …, All

Resources is reported first because it precedes Xml.Serialization in CNA's list ({{src:cmake/SharpRuntimeConsumption.cmake}}); both exist only on sharp-runtime's next branch. The fix is the one above: git -C ../sharp-runtime checkout next (or clone with -b next), then reconfigure. How the component selection works on both sides is on {{page:deep-dives/sharp-runtime/components-and-consumption.html#revision|sharp-runtime components and consumption}}.
