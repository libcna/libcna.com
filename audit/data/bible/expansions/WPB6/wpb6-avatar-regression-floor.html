The avatar visual review, the visual regression and the acceptance command

The renderer comparison above comes from tools/avatar_builder/avatar_review.py, which renders review sheets through the real renderer (cna_avatar_review) and through a CPU preview. It is an image review, not a gate: no CTest registration or workflow runs it, and the figures quoted are CNA's own records, not re-measured for this page.

The gate is the checked-in visual regression in {{tree:tools/avatar_builder/regression}}: 36 views of nine described avatars and of three CreateRandom avatars from a fixed seed, covering both body types, a range of heights, builds, skin tones, face presets, hairstyles, facial hair, glasses, headwear, makeup, earrings on three ear shapes, hand accessories and outfits, from several angles and close-ups, in several animations including the deepest crouch. Its manifest.json is a cna_avatar_review job list and golden/ holds the renders on SOFTWARE, the canonical renderer. The CTest entry GamerServices_AvatarVisualRegression (labels avatar, visual; it needs Python 3 with Pillow and a display) draws them with the build's default renderer and compares each with its golden, SOFTWARE strictly and every other renderer within the differences measured between renderers (TOLERANCES in {{src:tools/avatar_builder/avatar_visual_regression.py|avatar_visual_regression.py}}). It also fails when a view is missing or the manifest no longer matches the catalog revision and catalog.json hash of the checkout. It replaced the earlier speckle-count script scripts/avatar_visual_regression_check.py, which CNA no longer carries.

One command says whether Avatar v3 is whole in a build tree ({{src:docs/avatars.md}}):

python3 tools/avatar_builder/avatar_acceptance.py <build-tree> [--all-renderers | --renderer X ...] [--service ../cna-gamer-services-server]

It refuses a checkout with uncommitted changes or a catalog submodule off its recorded commit (unless told to run anyway, and then names no validated commit), builds every binary it runs from that commit, checks that the catalog, generator, codec, CMake and documentation agree, runs the avatar tests listed in tools/avatar_builder/acceptance_tests.json on each renderer and the visual regression on each renderer that draws, and measures the catalog library's size, the link footprint of a game without avatars and the first, next and reused avatar load times against budgets. CNA's Debug figures for revision 5 are a 22.3 MB deflated catalog library (46.0 MB of files), the first avatar of a process in about 370–410 ms, the next in about 140–210 ms, and an avatar a renderer still draws reused in about 0.3 ms; an avatar and its textures are released once nothing draws them. Those are CNA's records, not measured here.
