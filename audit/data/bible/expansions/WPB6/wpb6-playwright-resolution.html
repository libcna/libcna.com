Running the browser runner by hand: how Playwright is found

CNA's browser runner, {{src:scripts/run_browser_tests.mjs|run_browser_tests.mjs}}, serves a built Emscripten test page and reports its verdict; the C ABI's browser probe, the CTest CApi_WasmBrowserProbe, runs through it. It is an ES module, and Node's ES-module resolver ignores NODE_PATH, while Playwright is usually installed globally rather than inside the repository. The runner therefore builds a CommonJS loader with createRequire(import.meta.url) and tries NODE_PATH and two fixed global module directories before it falls back to an ordinary require; it accepts PLAYWRIGHT_CHROMIUM as the path of a replacement Chromium executable. --check-playwright runs no page and only reports whether Playwright resolves, and the C API's CMake uses exactly that answer to decide whether it registers the probe or a skip, so the build and the run cannot disagree about what is resolvable.

Without such a replacement the runner launches Playwright's own headless Chromium. A missing browser download is therefore an environment failure, not a renderer result. Checked by reading at c6dec91f and re-checked at 3b43bd86; not executed.
