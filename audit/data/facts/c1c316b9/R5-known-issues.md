## 1. Method

**Reading CNA.** CNA was read only through Git objects: `git -C …/cna show|log|diff|grep` at B and T, and the read-only extracted tree `~/.cache/libcna-com/cna-target`, whose stamp is exactly T. No CNA code or script was executed. That includes `check_no_posix_setenv.py`, whose pattern was re-implemented for CNA-BUG-275.

**Mechanical pass over all 328 published entries.** Each entry's `sources` paths and its `{{src:}}`/`{{tree:}}` tokens were compared with T. A directory counts as present when any file of T lies under it.
- 31 entries name a path that is absent at T.
- 188 name a path changed in B..T, either directly or a file under a named directory.
- 109 name nothing that changed.

Every published field was also scanned:
- for retired-renderer spellings, using `check_retired_renderers.strong_pattern` over the set derived from CNA at T. 22 entries were hit.
- for Win32/X11/Wayland/D3D12 wording. 38 entries were hit.

For every entry with a changed path, the commits B..T that touched its paths were listed with `git log B..T -- <paths>`.

**Verification pass.** The entries were verified in three groups, all against the code at T:

| Group | Entries | Who |
|---|---|---|
| Missing source paths, retired-renderer or platform wording, Platforms, Input | 69 | this lead |
| Graphics & renderers, Models & glTF, Audio & media, Content, Math (changed only) | 64 | verifier B |
| Documentation, Testing, Core, Build & CI, Diagnostics, Networking, C API, Storage (changed only) | 93 | verifier C |

The verifiers worked to a written brief, and the lead reviewed every non-carry verdict before integrating it.

For each entry the diff and the relevant commits were read, and then the code and tests at T. The bar was the same as R9:
- A commit title is never proof.
- PROVEN FIXED needs the fixing commit, the code path at T and, where one exists, the test that pins it.
- OBSOLETE needs the removing commit and the code that is gone at T.
- An entry that named several renderers or platforms, of which only some were retired, was edited or narrowed to the survivors, not retired.

The 102 entries whose sources did not change were checked as follows:
- Every source change of the delta in their subsystems was reviewed. In math, storage, media, phone, net and content these are few; for example `modules/math/CMakeLists.txt` now builds with `-ffp-contract=off`, which does not touch any named code.
- A sample of entries was re-read.
- A global scan of all published text checked for the following, and corrected each hit:
  - references to retired entry ids;
  - file names that do not exist at T, which turned up `D3D12SpriteBatch.cpp` in CNA-BUG-006 and a test name in CNA-BUG-111 that never existed;
  - stale ABI and count figures.

**Public-text rules applied:**
- No retired renderer identity appears in any spelling. That includes lower-case "canvas", file names of the retired renderer, and "Direct3D 12" as a CNA renderer. SDL_gpu's own Direct3D 12 driver is still named where it is the subject (CNA-BUG-094, CNA-VGAP-025).
- Win32, X11 and Wayland never appear as CNA platform implementations. Windows, X11 or Wayland as environments reached through SDL3 remain, and so does CMake's `WIN32` host variable.
- Executed or observed statements stay attributed to the commit where they happened.
- Nothing was invented. Confidence values were left as they were, except where an entry now rests on a CNA record (`recorded-by-cna` for the new CNA-PLAT-016 and CNA-PLAT-018).

**How the edits were applied.** Every change goes through `patches-adversarial.json`, so stable ids are never renumbered or reused:
- **Original entries:** `entries[key].set` / `append`. When a field is replaced in full, any older `append` of that field is dropped, because the full value already contains it.
- **Reclassified entries:** keyed by their id before reclassification (CNA-PLAT-008 → GAP-067, CNA-PLAT-010 → GAP-068).
- **Audit-added entries:** edited inside their `added[]` element: NEW-PIN-01 (BUG-275), NEW-AUDIT-03 (BUG-253), NEW-AUDIT-05 (VGAP-056), NEW-AUDIT-15 (BUG-262), NEW-AUDIT-20 (BUG-264) and NEW-AUDIT-30 (BUG-273).
- **Fold survivors:** their evidence was set without the folded paragraph, which the fold re-appends. The folded duplicates' summaries were patched so that the re-appended text is current: CNA-VGAP-043 into 026, VGAP-045 into 023, VGAP-048 into 025 and VGAP-050 into GAP-013.
- **Retirements:**
  - original entries go under `retired`;
  - the reclassified CNA-GAP-069 goes under the new `retired_reclassified`, keyed CNA-PLAT-015.
- **New entries:** appended to `added` as NEW-PIN2-01..04, after every existing added entry.

A check script compared every intended field value with the merged `issues-source.json`, after applying the repin to the intended value, and found 0 differences. It also confirmed:
- every append is present exactly once;
- every carried entry differs from its b0e97bb1 text only by the repin.

**Repin.** The `repin` step b0e97bb1 → c1c316b9 moves "read at", "checked by reading … at" and "verified against" wording to c1c316b9. Every published entry was re-verified at T by the process above, so it applies to all of them, as R9's step did. The step keeps three kinds of phrase at b0e97bb1:
- `Re-verified at b0e97bb1`: the Phase 4 re-verification notes stay history;
- `at revisions before b0e97bb1` (CNA-VGAP-008);
- `at the b0e97bb1 snapshot`: counts measured at that commit (CNA-BUG-273, CNA-BUG-275).

Statements about something executed or observed at 009d40f5 were already protected by the first step, and stay attributed. A scan of the merged text found no execution verb bound to b0e97bb1. The one leftover of the previous move, CNA-BUG-041's "not run at b0e97bb1 (the audit's run at b0e97bb1 …)", was corrected to "the audit run at 009d40f5". `verified_against` in `data/known-issues.json` is set by `public_entry()` to the TARGET for every entry, and `validate` requires it. That is consistent only because every entry was re-verified.
