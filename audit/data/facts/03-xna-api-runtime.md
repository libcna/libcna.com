## Per-area changes (only what is verified in TARGET code)

### Framework core and math
- **Game clock is now XNA's, not FNA's** (owner decision, `47035d0d8`, 2026-08-27): the first `Update` runs with `ElapsedGameTime = TimeSpan.Zero`; `TotalGameTime` is the time *before* the step, so it advances after `Update` returns, in both fixed and variable modes. Measured on the real XNA runtime. `modules/runtime/src/Game.cpp:653-670` (fixed path: `hasUpdatedOnce_ ? TargetElapsedTime_ : Zero` at `:657`, total advanced after `Update` at `:668`), `:700-722` (variable path). CHANGED. **Caveat (SAME as BASE):** the Emscripten frame body `Game::EmscriptenMainLoopCallback` (`Game.cpp:1072-1130`) has its own fixed-step accumulator (250 ms clamp; `IsFixedTimeStep = false` is not honoured; `TotalGameTime` is advanced *before* `Update`; first update gets a full step), so the XNA clock rule applies to the native `Tick()` path only.
- `GraphicsDeviceManager` default presentation mode is now `Letterbox` (was `FixedHeightDynamicWidth`): `Viewport` is the backbuffer size whatever the window's shape (XNA/FNA behaviour). `modules/runtime/src/GraphicsDeviceManager.cpp:66`; `getPreferredPresentationModeProperty/setPreferredPresentationModeProperty` (CNAEXT) `GraphicsDeviceManager.hpp:236-242`; commit `f13701188`. `GameWindow::getCurrentOrientationProperty` now follows the drawn surface, not the OS window (`0285061fa`, CNAEXT `SetLogicalSizeProviderEXT`). CHANGED.
- `Game::Run()` on Emscripten no longer unwinds the caller: a stack-allocated `Game` is legal. `Game.cpp:1162-1176` (`RunLoop` awaits `requestAnimationFrame` via Asyncify on the same stack); `docs/emscripten-mainloop-game-lifetime.md:1-20` ("No page-lifetime leak or Emscripten-specific heap allocation is required"); commit `dccfb88f8` (2026-08-22, after BASE). Requires Asyncify: application executables opt in automatically; an external final link must use `CNA::EmscriptenAsyncify`. CHANGED (alpha.1 site says the opposite in ~25 places).
- `Game` constructor now calls `CNA::Internal::Xnb::RegisterAllBuiltInXnbReaders()`: `Game.cpp:338` (commit `fcc9320f5`, 2026-08-23). A stand-alone `ContentManager` still starts with an empty registry. CHANGED (sheet 04 V5).
- `Game` initialises `CultureInfo::DefaultThreadCurrentCulture/UICulture` from the platform's preferred-locale list when the application has not set them: `Game.cpp:112-160`, called at `:323` (commit `0b41d8a6f`). NEW.
- `Game::UnloadContent()` default body is **empty** (`Game.cpp:796-798`; same at BASE `Game.cpp:638-640`); it is invoked from the graphics device's `DeviceDisposing` event (`Game.cpp:812-821`) during `Dispose(bool)` (`:912-940`, `Content_.Dispose()` at `:929` runs first). `OnExiting` is raised at the end of `RunLoop` (`:1193`), i.e. **before** `UnloadContent`. PRE-EXISTING ERROR on several pages.
- `GameComponentCollection` gained `Add/Insert(std::shared_ptr<IGameComponent>)` (CNAEXT) that keeps the component alive (`43748c883`); loading-screen threads may add components (component lists are mutex-guarded, `Game.hpp`). NEW.
- New CNAEXT: `GameWindow::FileDropEXT/TextDropEXT` (drag-and-drop), `CNA::SetProjectGraphicsProfileEXT` (project profile, default Reach), `XmlSerializationEXT.hpp` (opt-in `XmlSerializer` support for the math value types; pulls `SharpRuntime::Xml.Serialization`). NEW.
- Math: `Matrix operator*(float, Matrix)` added (`Matrix.hpp:968`); `Color()` default = transparent black (`Color.hpp:376`, `890eaf5d3`); Vector2/Vector3 compound `+= -= *= /=` are CNAEXT (`Vector2.hpp:625-640`); `Equals(std::any)` (XNA's `Equals(object)`) on the math value types (XNA-MISSING-002); `Matrix::ToString` now XNA's exact format (`871e89ae1`). `Vector3::Length/Distance/DistanceSquared`, matrix products and `BoundingSphere::CreateFromPoints` reproduce XNA's 32-bit x87 accumulation (wider-than-float, narrow once) and XNA's tie-break for the widest axis (last axis wins): `Vector3.cpp:444-448,508-510`, `Matrix.cpp:999,1107`, `BoundingSphere.cpp:212`. CHANGED (numerical results can differ in the last bits from alpha.1).
- `BoundingFrustum::Intersects(Ray)` **SAME**: ray origin outside the frustum returns "no hit", inside returns 0, and only a boundary origin throws `NotImplementedException` (`BoundingFrustum.cpp:244-264`; identical at BASE). The site's "throws" is imprecise; real XNA has the same limitation.
- `math` is a compiled module (`modules/math/src/*.cpp`, `CMakeLists.txt:1-2`), not header-only as `docs/math-types.html:48` says (PRE-EXISTING ERROR).
