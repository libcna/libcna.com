## 1. Method

**Reading CNA.** CNA was read only through Git objects (`git -C …/cna show|log|diff|grep|ls-tree` at B and T) and the read-only extracted tree `~/.cache/libcna-com/cna-target`, whose `.extracted-from` stamp is exactly T. No CNA code or script was executed; where an entry rests on a script's result (the `setenv` scan of CNA-BUG-275, the devices filter count of CNA-BUG-035, the `ObjectDisposedException` count of CNA-BUG-273), its pattern was re-implemented over the tree.

**Mechanical pass over all 310 published entries.** Each entry's `sources` paths and `{{src:}}`/`{{tree:}}` tokens were compared with T (a directory counts as present when a file of T lies under it):
- 58 entries name a path absent at T;
- 235 name a path changed in B..T, directly or under a named directory;
- 17 name nothing that changed.

Every published field was scanned with `check_retired_renderers.line_hits` and `semantic_findings` over the retired set derived from CNA (55 entries hit by spelling, 13 by list semantics), for the retired modern GPU layer (2 entries: CNA-BUG-094 and CNA-BUG-246), and for stale snapshot wording (the old pin, renderer and identity counts, ABI 0.46.0, the C API coverage figures, `GraphicsBackend*`, alpha.1 presented as current). For every entry with a changed or absent path, `git log B..T -- <paths>` listed the commits to read.

**Verification pass.** Every entry was decided against the code and tests at T, with `CNA_DEMOS_REPAIR_MATRIX.json` and `handoff.md` treated as CNA's view, never as proof. The bar:
- A commit title is never proof.
- PROVEN FIXED needs the fixing commit, the code path at T and, where one exists, the test that pins it.
- OBSOLETE needs the removing commit and the code (or document) gone at T.
- An entry that named several renderers, of which only some were retired, was edited or narrowed to the survivors, never retired for the retirement alone.
- Nothing unverified was published. Confidence values were left as they were, except for the new entry (`recorded-by-cna`) and CNA-BUG-278, which now rests on CNA's handoff record of a reproduced defect.
- The nine CNA-DEMOS issues whose fixes are committed but not closed (005, 006, 007, 008, 022, 023, 031, 066, 067) were never used as proof that an entry is fixed. Where their commits changed code an entry describes (CNA-GAP-007 ← ISSUE-008, CNA-GAP-035 ← ISSUE-023, CNA-GAP-042 ← ISSUE-031, CNA-PLAT-016 ← ISSUE-006), the entry stays published, describes the code at T, and says that CNA has not closed the fix.

The 17 entries whose paths did not change were re-read at T as well; the 131 carried entries were each re-checked against the named code at T (the notes of section 4 record the statement that was checked). A global scan of the published text after editing found no reference to a retired entry id and no source path or token absent at T.

**Coordinator notes folded in.** The tombstoned pages: CNA-BUG-114, CNA-BUG-229 and CNA-VGAP-022 linked them and now link current pages (presentation and back-buffer readback, EasyGL state, the GameTime page); every other tombstone link was in an entry retired here. CNA-VGAP-025's title was rewritten (CI now configures both renderers). CNA-BUG-012 was re-verified and still holds at T (STUB still takes the all-true default arm of `ExpectedCapabilities()`, and the `SDL_GPU` arm keeps custom effects true off Apple, Windows and the browser). CNA-BUG-113 is already narrowed to `SDL_GPU`. CNA-BUG-133 still holds. Immediate `SpriteBatch`: WEBGPU's per-Draw `FlushPendingSpritesEXT` (WebGPURenderer.cpp, the `immediateMode_` branch of `WebGPUSpriteBatchRenderer::Draw`) flushes only the compiled-effect sprite batch and is compiled only with `CNA_WEBGPU_COMPILED_EFFECTS`; stock sprites are appended to `spriteCommands_` and drawn later, so CNA-BUG-278 keeps naming both renderers, as handoff.md section 5.1 does.

**How the edits were applied.** Every change goes through `patches-adversarial.json`, so stable ids never move:
- **Original entries:** `entries[key].set` (a field replaced in full drops any older `append` of that field).
- **Reclassified entries:** keyed by their id before reclassification (for example CNA-BUG-127 → GAP-066, CNA-BUG-100 → GAP-064).
- **Audit-added entries:** edited inside their `added[]` element (NEW-AUDIT-*, NEW-PIN-*, NEW-PIN2-*).
- **Fold survivors:** CNA-VGAP-025 and CNA-VGAP-026 got evidence without the folded paragraph, which the fold re-appends; the folded duplicates' summaries were corrected so that the re-appended text is current (CNA-VGAP-048 into 025, CNA-VGAP-043 into 026).
- **Retirements:** original entries under `retired`; audit-added entries under `retired_added` (keyed by temp id); none of the reclassified entries was retired.
- **Reclassification:** CNA-GAP-010 → bug (severity low) as a `late` reclassification (section 5), which allocates CNA-BUG-278 after the added bugs.
- **New entry:** appended to `added` as NEW-PIN3-01.

A check script compared every intended field value with the merged `issues-source.json` after applying the repin to the intended value. The only differences are the expected ones: the fold paragraphs re-appended to CNA-VGAP-025 and 026, and the comparison's own emulation of `plain_text` for `public_contract`.

## 5. `scripts/known_issues.py` changes

**New `"late": true` on a reclassification.** Reclassifications are allocated before `added`, so reclassifying an entry into a class that already holds audit-added entries would take an id before them and renumber every one (here CNA-BUG-251..277). A reclassification marked `late` is allocated after every `added` entry instead and takes the next id of its class; no existing id moves.
- Late reclassifications are taken out of the entry set right after `retired`, so `added` and the id resolution cannot see them, and are allocated after `added`, in key order.
- `retired_reclassified` retires a late one the same way as an ordinary one.
- The format comment above `apply_adversarial` documents it, including that `late` must never be flipped on an existing reclassification.
- It is used once: CNA-GAP-010 → CNA-BUG-278.
- Regression check: `scripts/test_validators.py` `late_reclassification_problems()` runs `apply_adversarial` on an in-memory three-entry patch (one ordinary and one late reclassification into the bug class, one added bug) and requires the ids BUG-011 (ordinary), BUG-012 (added), BUG-013 (late). Nothing is read from or written to disk.

**Other changes:** `TODAY` is 2026-10-25 (the `generated` field of `data/known-issues.json`). The new repin step c1c316b9 → c6dec91f is data, not code (the list form already existed).
