# Fact sheet 01 - Renderers and graphics selection (CNA TARGET `009d40f5`)

Scope: the exact public renderer surface, selection mechanics, capability model and renderer feature/test
evidence at CNA TARGET `009d40f5dd085c4e674d3479675fac84b12b3e0a` (branch `next`, "merge(OpenGL4ModernGraphics)").
BASE = CNA `v0.1.0-alpha.1` (`1bb2145d99ed572dd4eb15009c34e2e5f410fcf0`), the revision the deployed site was last synchronized to.

Conventions

- Paths without prefix are relative to the TARGET worktree root (`/rv/tmp/libcna-v2/cna-target`). `BASE:` paths are relative to `/rv/tmp/libcna-v2/cna-base`.
- Evidence order used: implementation, then CMake/headers, then test registration, then generated reports; CNA's own Markdown is only cited where marked "(CNA prose)" and never as the sole basis of a fact.
- Confidence: **Verified** = read in implementation/build configuration and, where a second independent source exists, cross-checked; **Strong** = one authoritative code source, or code plus CNA prose; **Probable** = derived by reading code paths, or relies on comments/prose, not exercised.
- Retired renderer identities are deliberately NOT named in this file. Their names, C ABI values, module directories, dependencies and scrub patterns are in the private, non-published scratchpad file `retired-renderers.txt`. This file only counts them.

Headline numbers (all Verified): **25 public identities over 21 implementation families** at TARGET (BASE code: 50 identities over 46 families); **26** identities retired in CNA's registry (25 of them were BASE identities, one was added and retired after BASE); **19** `GraphicsCapability` members (BASE 14); **32** `RendererFeature` ids and **22** `RendererLimit` ids in a new capability-profile API; C ABI `0.29.0` (BASE `0.7.0`).

### C. Selecting a renderer at build time

- **V17. Default renderer per host** (cache default of `CNA_GRAPHICS_RENDERER`, overridable): **Emscripten -> `WEBGL2`**; **Linux -> `OPENGLES3`**; **everything else -> `SDL_RENDERER`** (Windows, macOS, iOS, Android, other Unix). Android's `CMAKE_SYSTEM_NAME` is `Android`, so it takes the last branch. The rule is unchanged since BASE and lives in one file used by both renderer selection and the SDL gate. - `cmake/RendererIdentityDefault.cmake:26-31`; `cmake/RendererSelection.cmake:6,13`; BASE `cmake/RendererSelection.cmake:8-15` (identical rule). Windows and macOS therefore default to the 2D-only `SDL_RENDERER`; a 3D renderer must be chosen explicitly there. - **Verified**. (Android build viability itself is not verified by CNA: `docs/android-graphics-limitations.md` (CNA prose, dated) reports the NDK cross-build failing in a sibling repo - Probable, may be stale.)
- **V18. Presets** (not defaults): `dev`, `unit`, `release-modules` use `STUB`; `web` `WEBGL2`; `macos`, `ios`, `ios-simulator` `SDL_RENDERER`; `tests`, `cnaext`, `devices-asan/tsan/ubsan` `OPENGLES3`; `multi-renderer` `HEADLESS` with `CNA_GRAPHICS_RENDERERS="HEADLESS;SOFTWARE;STUB"`. - `CMakePresets.json:19-26,46-53,83-90,110-116,125-160,167-202,209-241`. - **Verified**.
- **V19. Selection options.** `CNA_GRAPHICS_RENDERER` is a cache STRING whose STRINGS property is the public list; there are 25 per-identity switches `CNA_RENDERER_<X>` (OFF by default) and **exactly one** may be ON (else `FATAL_ERROR`), which then becomes `CNA_GRAPHICS_RENDERER`. If a `CNA_RENDERER_<X>` is ON it overrides the cache value of `CNA_GRAPHICS_RENDERER` for that configure (`RendererSelection.cmake:88`); `CNA_GRAPHICS_RENDERERS` (semicolon list, default empty = single-renderer mode) opts into a multi-renderer build. - `cmake/RendererSelection.cmake:12-15,17-73,75-89`; `cmake/RendererDefaultSelection.cmake:33-37`. - **Verified**.
- **V20. Multi-renderer builds.** With `CNA_GRAPHICS_RENDERERS` set, `CNA_GRAPHICS_RENDERER` names the **default** and **must be a member** of the list - otherwise `FATAL_ERROR` (no silent substitution); duplicates are removed and the default is moved first. Only the default's `CNA_RENDERER_<X>` macro is defined project-wide (each family's own macro is private to its target); `CNA_MULTI_RENDERER` is defined when more than one is compiled in; tests get `CNA_RENDERER_PRESENT_<IDENTITY>` per compiled-in renderer; a generated `CnaRendererRegistry.generated.cpp` lists the linked families (default first). Configure-time output line: `CNA: renderer set -- <list> (default: <X>)`. - `cmake/RendererDefaultSelection.cmake:35-59`; `cmake/RendererSelection.cmake:110-118,559-580`; `cmake/UnitTests.cmake:758-772`; `cmake/RendererRegistry.cmake:97-156`; CTests `CnaRendererDefaultSelection_*` (`cmake/Tests/ModuleProbes.cmake:607-615`). - **Verified**.
- **V21. Combination rules at TARGET (configure-time `FATAL_ERROR` with a reason):** (1) `PORTABLEGL` cannot be co-linked with any real-GL renderer (`OPENGLES2/3`, `OPENGL33`, `WEBGL1/2`, `OPENGL4`) - it defines the global `gl*` symbols; (2) `GDI` + `SOFTWARE` (ODR: same TUs, different defines); (3) two identities from different platform partitions (Windows-only, Emscripten-only, macOS-only) - "one toolchain cannot target both". ### D. Selecting a renderer at runtime

- **V26. The runtime selection API is functionally unchanged since BASE** - only a comment path differs between BASE and TARGET in `GraphicsRendererSelection.hpp`, `GraphicsRendererSelection.cpp` and `GraphicsRendererSelectionEmscripten.cpp` (file diff), and the C selection surface has the same 26 `cna_graphics_renderer_*` declarations in both `core_ext.h`. - **Verified**.
- **V27. Public API** `CNA::GraphicsRendererSelection` (`modules/core/include/CNA/GraphicsRendererSelection.hpp:36-166`): `SetPreferred(GraphicsRendererType)`, `SetPreferred(std::string_view)`, `GetSelected()`, `GetActive()`, `IsLatched()`, `GetAvailable()`, `IsAvailable()`, `SetFallbackChain(span)`, `EnableAutomaticFallback(bool)`, `IsFallbackEnabled()`, `GetFallbackHistory()`; `GraphicsDevice::GetGraphicsRendererType()/GetGraphicsRendererName()` report the device's real renderer (`GraphicsDevice.hpp:1524,1534`); `getCurrentGraphicsRendererType()/Name()` are compile-time and describe only the build default (`GraphicsRendererType.hpp:108-165,266-269`). - **Verified**.
- **V28. Resolution order (highest first):** explicit `SetPreferred()`; the `CNA_GRAPHICS_RENDERER` **environment variable**; the build's compile-time default. In an Emscripten build the page property `Module.cnaPreferredRenderer` is consulted at the environment variable's precedence (an actual env var wins over it); `Module._cna_set_preferred_renderer(name)` is an exported alternative that behaves like `SetPreferred`. - `modules/core/src/GraphicsRendererSelection.cpp:118-151,218-229`; `modules/core/src/GraphicsRendererSelectionEmscripten.cpp:47-59,83-140`. The environment is read **once** (first `GetSelected()`); a bad value throws once, after which the default silently applies (the "consulted" flag is set before parsing, `:121-123`) - **Probable** (code reading).
- **V29. Not-compiled-in / unknown choices are errors, not substitutions:** `SetPreferred(X)` for a renderer not in `GetAvailable()` throws `System::InvalidOperationException` "the X renderer is not compiled into this build. Available: ... Rebuild with -DCNA_GRAPHICS_RENDERER=X, or configure a fallback chain" - unless a fallback chain/automatic fallback is enabled, in which case the rejection is recorded. - `GraphicsRendererSelection.cpp:96-112,195-203`; tests `GraphicsRendererSelectionTests.cpp:130-160,229-260`. - **Verified**.
- **V30. Latching.** Selection is process-wide. `IsLatched()` becomes true when a renderer has been **successfully created** by the first `GraphicsDevice` (`GraphicsRendererSelectionAccessEXT::Latch`, `modules/graphics/src/Xna/GraphicsDevice.cpp:4325-4341`); a failed resolution does **not** latch (test `GraphicsRendererFallbackTests.cpp:148-160`), so a game may catch the error and retry with another configuration. After the latch `SetPreferred`, `SetFallbackChain` and `EnableAutomaticFallback` throw `InvalidOperationException` ("must be selected before the first GraphicsDevice is constructed") (`GraphicsRendererSelection.cpp:64-76,195-203,258-279`); `GetActive()` throws before any renderer exists; `GetSelected()` never latches (test `:94-100`); re-creating the same renderer on a live device (`Reset`, MSAA change) and a second `GraphicsDevice` keep the selection (`:203-227`). The header comment (`GraphicsRendererSelection.hpp:75-79`, "when the first GraphicsDevice begins construction") is stale relative to the code. - **Verified**.
- **V31. Fallback is OFF by default** (a renderer that is unavailable or fails to initialize is an error). `SetFallbackChain(chain)` enables it with an explicit order (chain entries not compiled in are skipped and recorded); `EnableAutomaticFallback(true)` orders every compiled-in renderer by declared maturity, with `Software`-category renderers ranked 10 places later and `STUB` always last (`GraphicsRendererSelection.cpp:172-192`). ## Selection & build mechanics

Single-renderer build (default, recommended): `cmake -S . -B build -DCNA_GRAPHICS_RENDERER=VULKAN` or, equivalently, exactly one `-DCNA_RENDERER_VULKAN=ON`. Omit both to get the per-host default (V17). Names are exact-case in CMake. A retired or unknown name stops the configure (V7).

Multi-renderer build: `-DCNA_GRAPHICS_RENDERER=<default> -DCNA_GRAPHICS_RENDERERS="A;B;C"` (default must be in the list; combination rules V21; each family's dependencies are pulled in). Then, before the first `GraphicsDevice`, in C++:

```cpp
CNA::GraphicsRendererSelection::SetPreferred(CNA::GraphicsRendererType::Vulkan);   // or SetPreferred("VULKAN")
CNA::GraphicsRendererSelection::SetFallbackChain({CNA::GraphicsRendererType::OpenGLES3,
                                                  CNA::GraphicsRendererType::Software});  // opt-in
```

or set the environment variable `CNA_GRAPHICS_RENDERER=VULKAN` (native) / `var Module = { cnaPreferredRenderer: "CANVAS" };` (Emscripten page). Precedence: explicit call > environment/`Module` property > build default. Unknown or not-compiled-in names throw; fallback is off unless enabled; the selection latches on the first successful device creation; `GetSelected()` = what CNA will try, `GetActive()` = what actually started, `GetFallbackHistory()` = what was skipped and why (V27-V31). `UseNullDevice`/`UseReferenceDevice` on `GraphicsAdapter` map to `HEADLESS`/`SOFTWARE` (V33).

Build-axis notes: `CNA_PLATFORM` (`SDL3` default, `SDL2`, `X11`, `WAYLAND`, `HEADLESS`, `TERMINAL`, `WIN32`) is independent of the renderer and decides which renderers can find a window/GL/Vulkan service (V14-V16); four renderers force SDL3 (V15). Sibling repositories `../sharp-runtime`, `../easy-gl` (+`../meta-gl`), `../free-direct` must exist for the renderers that need them (V22). Multi-renderer CI exists for `HEADLESS;SOFTWARE;STUB`, `OPENGL33;VULKAN;SOFTWARE;HEADLESS` and, for Emscripten, `WEBGL2;CANVAS;HTML_DOM;SVG_DOM` (workflow files `multi-renderer-ci.yml`, `platform-ci.yml:596-597`, `emscripten-multi-renderer-ci.yml:115-116`; the Emscripten job builds and asserts symbols, it does not run the four renderers).

## Open questions

1. **Does `-DCNA_BUILD_C_API=ON` build at TARGET?** CHANGELOG says it builds again at ABI 0.29.0 and the 25-row map is `static_assert`ed; not built here (no compiler use allowed). Treat "builds" as Strong, not Verified.
2. **Metal.** Declared *Supported*, but CNA's own page says the adapted `.mm` has no fresh macOS compile/run evidence. The website should not present Metal as validated beyond the CI build + `Metal*` test lane.
3. **Automatic-fallback ordering quirk** (V31): `HEADLESS` ranks before `SOFTWARE`/`PORTABLEGL`. Derived from the ranking code, not exercised by a test I found.
4. **Environment variable read-once behaviour** (V28): a bad `CNA_GRAPHICS_RENDERER` throws once, then silently yields the default on later `GetSelected()` calls. Code reading only.
5. **Stale wording inside CNA** (do not copy): `GraphicsRendererSelection.hpp:75-79` (latch "begins construction"); `GraphicsCapability.hpp:179` (D3D "can express" compute); `Direct2DCapabilityContract` test named "AllThirteen"; comments in `GraphicsRendererSelection.cpp:114-115`, `GraphicsRendererDescriptor.hpp:13`, `GraphicsRendererSelectionEmscripten.cpp:31-40`, root `handoff_*.md`, `integration/lanes/*.md` and some test docstrings still name retired renderers. CNA docs at `docs/*.md` are stale in both directions (e.g. `graphics-renderer-feature-matrix.md` still talks about "45 of 46" style history).
6. **SDL_GPU device-level vs renderer-level capabilities** (note 1): public answer is the device's; a caller holding the renderer interface directly sees different values.
7. **Which renderer CI selects for CNAEXT engine tests** is not recorded in the tree (`graphics-ext/examples/CMakeLists.txt:118-150`); engine tests skip on Windows and Emscripten builds and when the selected renderer lacks ThreeD/CustomEffects/shadow query. Do not state "shadows/IBL verified on renderer X" beyond the table above.
8. **Windows renderers under real Windows.** Test evidence is mostly cross-compiled + Wine (DXVK/vkd3d-proton); `d3d-windows-ci.yml`/`gdi-windows-ci.yml` are manual dispatch. No pass/fail result was available.
9. **Android.** Default is `SDL_RENDERER`; CNA's dated status page reports the NDK build failing in a sibling repo; current state unknown.
10. **Test counts.** No universal per-renderer test count is stated here on purpose: registrations are loops/options/labels dependent (parity fixtures alone are 32 per registering renderer).
11. **Emscripten availability of non-web renderers** (e.g. `SDL_RENDERER`, `SOFTWARE`, `HEADLESS`, `STUB`, `PORTABLEGL`, `WEBGPU` under wasm): CMake does not refuse them, but only `WEBGL2`, `CANVAS`, `HTML_DOM`, `SVG_DOM` have CI/build evidence there. The site should list only those four as browser-supported plus `WEBGL1`/`WEBGPU` as CMake-permitted.
