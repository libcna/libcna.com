## Executive summary (15 lines)
1. Between O and T the whole GamerServices/Net/Avatar stack was rebuilt (GS-001…GS-011, GSP, GSX, GSH, GS-AUDIT P1–P4, GS-009g/h); **every libcna.com page on these topics except `features.html` is pinned to O and now materially wrong.**
2. Default (no endpoint) = **local offline profiles**: no gamer exists until Guide sign-in or `CNA_GAMER_SERVICES_AUTO_SIGN_IN`; the four "Stub Gamer" identities are gone (GamerServicesDispatcher.cpp:39-50).
3. Service-backed mode is enabled **outside game code**: env `CNA_GAMER_SERVICES_ENDPOINT`+`CNA_GAME_ID` (+CA bundle/version), a `cna-title.json` manifest, user settings, or `CNA::GamerServices::setConfigurationOverride` (Configuration.hpp:8-34; ServiceConfiguration.cpp:80-95).
4. HTTPS only (TLS ≥1.2, hostname-verified); plain HTTP only for numeric loopback with explicit opt-in; no credentials in config; refresh tokens in Linux keyring / 0600 files / DPAPI (gamer-services-server.md:11-17,173-196).
5. Guide is a CNA-drawn console-style system UI: every standard `Guide.Show*` opens a real page; Home/pad Guide button opens it; it owns input while visible; GS-009h restores title render states after it draws.
6. Achievements: offline local store (+ optional `GamerServices/Achievements.json` catalog) or provisioned service catalogs; leaderboards: offline local store or provisioned service boards written only during network gameplay and committed at host `EndGame`.
7. Social (friends, presence, messages, reviews, parties, pictures) is service-only; local profiles get `GamerPrivilegeException`/`GamerServicesNotAvailableException`.
8. Net: Local/LocalWithLeaderboards in-process; **SystemLink = direct ENet/UDP LAN (works offline)**; **PlayerMatch/Ranked = CNA service directory + authenticated WSS relay only** (no P2P/NAT traversal), with invitations, host migration, AddLocalGamer, Opus voice.
9. Avatars: standard `AvatarDescription/AvatarAnimation/AvatarRenderer`, 71 bones, 31 presets, original CNA catalogs v1–v3 (repo licence, generated by `tools/avatar_builder`), Guide avatar editor; GS-009g aligned to XNA −Z space; CBIND-143 lets avatars load in single-thread browser builds.
10. Browser builds: avatars, Guide and local profiles work; service, relay, SystemLink discovery, voice, event channel are refused/absent (owner-scoped out).
11. Server: MIT C++23 (OpenSSL, Boost.Beast, SQLite WAL, nlohmann/json), one process/one SQLite writer, operator-provisioned accounts/titles; **no public instance is evidenced**; public-Internet deployment explicitly unqualified.
12. Qualification (GS-AUDIT-P4, 2026-10-02, Linux only): GamerServices 649/0/0, Net 524/0/0, server 33 pass / 0 fail / 7 skip (NAT gates skipped: no slirp4netns); Windows/macOS, real WAN/NAT, physical voice, GPU avatar pixels on DX/Metal not qualified.
13. Accepted HIGH limitation: achievements/scores are authenticated **client claims** (no anti-cheat); Ranked = majority agreement, no TrueSkill.
14. Known-issues data (verified against O): of 37 relevant entries, 16 are fixed/obsolete at T, 4 narrowed, 17 still accurate — 9 of those 17 are the unchanged WP7 push-notification module (table §8).

## 2. Sign-in, profiles, credentials

**Offline (default)** [SRC/DOC]
- No endpoint ⇒ gamers are **local offline profiles** "as on an Xbox 360 without Xbox LIVE": `Guide.ShowSignIn(paneCount,false)` asks each pane for a profile name; names 1–15 ASCII letters/digits/single spaces, start with a letter, unique ignoring case; `IsSignedInToLive=false`; no online-session or purchase privilege; own random avatar stored with the profile; plays Local and SystemLink; local achievements/leaderboards; service Guide panes and PlayerMatch/Ranked refuse (`docs/gamer-services-server.md:19-26`).
- Store: `CNA_GAMER_SERVICES_PROFILES_DIR/profiles.json` else `$XDG_DATA_HOME/cna/gamer-services/profiles.json`/`~/.local/share/...` (`%LOCALAPPDATA%\CNA\gamer-services` Windows) (`src/Internal/LocalProfiles.cpp:205-208`); atomic serialized writes; unreadable store never overwritten; `"autoSignIn": true` or `CNA_GAMER_SERVICES_AUTO_SIGN_IN=a,b` (≤4) sign in at start; per-profile `gameDefaults` (:27-48). Local profiles are never sent to a service (:34).
- `Guide::ShowSignIn(int paneCount, bool onlineOnly)` (`Guide.hpp:607`): paneCount must be 1, 2 or 4 (`Guide.cpp:1021-1033`); throws `GuideAlreadyVisibleException` if visible, `GamerServicesNotAvailableException` if not initialized or `onlineOnly` without a service. UI strings: "New profile" / "Sign in with a CNA account", "Account name", "Password for <name>" (`src/Internal/Guide/GuideSignIn.cpp:27-29,157-174`).
- Gamer access: `Gamer::getSignedInGamersProperty()` → `SignedInGamerCollection*` (`Gamer.hpp:89`); `operator[](PlayerIndex)` → that player's `SignedInGamer*` or nullptr (`SignedInGamerCollection.hpp:35`; GS-004m `771d4ff59`). `SignedInGamer::SignedIn/SignedOut` static events (`SignedInGamer.hpp:188,196`); **SignedIn replays already-signed-in gamers to a late subscriber** (`SignedInGamer.cpp:29-31`). Presence: mutable CNAEXT `GamerPresence& getPresenceProperty()` (`SignedInGamer.hpp:90`), published for accounts at next `Dispatcher.Update`.
- Guests: only with a service, `ShowSignIn(panes, true)` + typing `Guest` ⇒ "Alice (1)" `IsGuest`, no service call, no achievements, refused in PlayerMatch/Ranked; full matrix `docs/gamer-services-server.md:120-128`, known-limitations #16.

**Service-backed authentication** [SRC/DOC/RT]
- GS-003a `92dcdc061` (config), GS-003b/004a `0ab6cc3fe` (identities + Guide sign-in through XNA API), GS-004b/c `f1bb88e36`,`d57a41f54` (private refresh authority), GSH-07 `835810e5a` (keyring/DPAPI).
- Server side (S:`protocol/v1.md` `auth.login`): scrypt N=32768,r=8,p=1 verifiers; random 256-bit access token, stored hashed, 1-hour; rotating 30-day refresh families, replay revokes family (S:`README.md:25`); 32 live sign-ins/account (oldest signed out); 10 logins/min/address.
- Client storage of **refresh credential only** (never password/access token), bound to endpoint+title+slot; process lease per endpoint/title (`docs/gamer-services-server.md:173-196`):
  | Host | Store |
  |---|---|
  | Linux + desktop keyring | freedesktop Secret Service via `libsecret-1.so.0` loaded at runtime; 2-s timeout ⇒ files [RT Linux] |
  | Linux headless / macOS / other POSIX | `$XDG_STATE_HOME|~/.local/state/cna/gamer-services/credentials`, 0700 dir, 0600 atomic files — **plaintext, not encrypted at rest**; macOS Keychain not used [PLAT] |
  | Windows | `%LOCALAPPDATA%\cna\gamer-services\credentials`, DPAPI-sealed — **tested under Wine only** [PLAT] |
  | Browser | nothing kept |
  `CNA_GAMER_SERVICES_CREDENTIALS_DIR=<dir>` forces files; `=0` disables persistence; `CNA_GAMER_SERVICES_KEYRING=0`.
- Dispatcher restores ≤4 identities, refreshes before expiry, 30-s heartbeat; transport loss keeps last identity with backoff; confirmed revocation signs out at Update; a lost refresh response may force fresh Guide sign-in (:190-196). GS-AUDIT-P4 added `policy-refresh` (privileges + full ≤1024 block list on heartbeat/renewal) (`audit/gamer-services/gamer-services-handoff-phase4.md:35-38`).
- Accounts are **operator-provisioned**; no self-registration, password change or reset over the wire (known-limitations #21; S:`README.md:43-46,77`).
