Roadmap

Development Roadmap

CNA is a long-term project developed incrementally. This page describes the honest current state and the path forward - no overpromising, no fake ETAs.

⚠

Honest timeline note: CNA is a long-term open-source project maintained in spare time. There are no fixed release dates. Milestones are goals, not commitments, and items marked "Open" below are gaps that have been identified, not work that has been scheduled. Progress is incremental and driven by API coverage, renderer stability, and real-world testing against ported games.

Current State

Where CNA actually is

0.1.0-alpha.1 is CNA's first tagged pre-release. It resolves to commit 1bb2145d99ed572dd4eb15009c34e2e5f410fcf0 (20 August 2026) and follows Semantic Versioning. This page tracks the development snapshot 009d40f5 (24 September 2026, branch next), which is 2,877 commits later; its product version string is still 0.1.0-alpha.1 and no newer tag exists (see Releases & Versioning). At this snapshot CNA represents every one of the 331 documented XNA 4.0 runtime types and 3,627 documented members — representation, not behaviour — exposes 25 renderer identities across 21 implementation families (alpha.1: 50 across 46), and has 904 C++ test sources with 12,610 statically discoverable GoogleTest-family definitions. These are source facts, not a universal pass count; APIs may still change before 1.0.

Read that as: breadth is largely done, depth is not. The sections below separate what has shipped since alpha.1 from what is genuinely partial and what remains open.

Shipped

What is done and verified

Everything in this list exists in the source tree of snapshot 009d40f5 and was confirmed by audit rather than by changelog. Items labelled "New" arrived after the alpha.1 tag.

Complete

25 renderer identities, single or multi-renderer builds Shipped

A normal build selects one identity with CNA_GRAPHICS_RENDERER. An opt-in CNA_GRAPHICS_RENDERERS list links several compatible families and selects one before the first device through GraphicsRendererSelection; fallback is explicit and the choice latches once the first renderer has been created successfully. Platform gates and dependency costs still apply. Since alpha.1 the set has been deliberately curated from 50 identities over 46 implementation families to 25 over 21: a name outside the 25 is a configure-time error, never a silent fallback, and no surviving identity was renumbered in the C ABI. See Graphics Renderers.

Production-ready

EasyGL renderer — the most mature path Shipped

EasyGL implements CNA's five GL-profile identities and is the Linux default through OPENGLES3. It covers the stock effect families, lighting and GL context-loss recovery, and on the ES3-generation profiles instancing, occlusion queries, anisotropy, multiple render targets and 3D textures; the ES2-generation profiles (OPENGLES2, WEBGL1) have no MSAA, MRT, occlusion queries, 3D textures or instancing. Use the renderer capability report for the exact profile and feature boundary.

Complete — was listed here as "planned, not started"

Direct3D 9 renderer — functional, and the pixel-exact XNA oracle target Shipped

This page previously described DIRECTX9 as a possible future renderer. That is out of date: it is a Windows-only implementation with SM2/SM3 shaders, device-lost recovery and MRT bounded by the graphics profile. It is also the renderer used for CNA's 39-scene pixel-exact XNA oracle comparison at --tolerance 0: the references come from the genuine XNA 4.0 runtime under Wine and DXVK on Linux, the result is recorded as 39 of 39 (the last consolidated dated report covers 31 scenes; later per-scene notes record the rest), and the check is manual and not run in CI. Compiled XNA effects are an opt-in build feature.

Complete

Vulkan renderer Shipped

A functional SPIR-V renderer with MRT handling, device-queried depth formats, stencil state, MSAA resolve and mip blit cascades. Its modern-graphics campaign added compute and storage buffers, indirect and base-instance draws, GPU timers, float and half-float render targets, and shadow-map and image-based-lighting sampling. Compiled XNA effects are an independent opt-in build feature.

New

SDL_GPU renderer Shipped

A deferred/retained renderer with SPIR-V shaders, the stock effect families, stencil and MSAA resolve. It is no longer Vulkan-only: with CNA_SDL_GPU_SHADERCROSS (on by default on Windows and Apple) SDL's Direct3D 12 and Metal devices are reached by translating the SPIR-V through SDL_shadercross. The modern-graphics campaign added compute, indirect draw, float targets and shadow and IBL sampling; the renderer reports no occlusion queries. Compiled XNA effects are an independent opt-in feature.

New

FreeDirect renderer — the best 2D fidelity in the project Shipped

A 2D-only DirectDraw-shaped renderer fronting the sibling free-direct project: a CPU compositor with bilinear filtering, distinct blend formulas and Wrap/Mirror addressing. It is cross-platform despite the name (it is not Windows-gated), though CNA's own maturity table declares it Experimental.

New

ASCII effect Migrated

The former ASCII renderer was deliberately removed and its logic promoted to a CNAEXT post-process effect, CNA::Graphics::AsciiPostProcessEffect, with a companion AsciiPass for the engine layer's post-process chain. Because it now works through the public Texture2D::GetData() and SpriteBatch API, it applies on any renderer and to 3D-rendered sources — which the old renderer could not do. Requires -DCNA_CNAEXT=ON.

Shipped, narrow

Canvas renderer (Emscripten) Configuration-specific

The Canvas renderer is a browser-only 2D identity with 17 statically discoverable GoogleTest-family definitions in its module. That source count is useful inventory, not proof of pixel behavior in every browser; execute the Emscripten configuration you intend to ship.

Complete

The .xnb content pipeline Shipped

A real XNB loader is wired into ContentManager: 61 built-in readers (60 without native 128-bit integers), covering primitives, math, textures, fonts, audio, video, stock and compiled effects, and models on top of LZX decompression and shared-resource resolution. Typed external references and explicit custom-reader registration are present, ReflectiveTypeReaderBuilder registers custom types from a declared field list, and a Game registers the built-in readers itself. Since alpha.1 CNA also writes content: the build-time cna-content tool turns source assets into .cnb (the default) or .xnb, including LZX compression, and ContentManager resolves .xnb, then .cnb, then loose files. CNA reports that its XNB output loads in a genuine XNA 4.0 runtime under Wine; that has not been re-run for this page. See XNB Content Pipeline.

New

Build-time Content Pipeline and the CNB format Shipped

The XNA-shaped Microsoft::Xna::Framework::Content::Pipeline API is represented (128 of 128 types, 705 of 705 members, 10 importers, 12 processors) and driven by cna-content, which imports images, audio, video, fonts, glTF, .fbx, .x and existing .xnb and compiles .fx sources through an external legacy fxc (that route's verification against a genuine Microsoft fxc is not established). CNB is CNA's own deterministic container: a 64-byte header, CRC-32C per structure and chunk, and schemas for textures, models, animation clips, sounds and more. The pipeline has no C ABI export. See Content Pipeline, CNB Format and Command-Line Tools.

Complete

PBR effects and skeletal animation Shipped

Beyond the five XNA stock effects and SpriteEffect (all implemented natively in C++, not translated from bytecode), CNA ships non-XNA PbrEffect and SkinnedPbrEffect, plus RenderPipelineSettings, PbrMaterial, TonemappingMode and ShadowQuality, now inside a much larger engine layer (below). Skeletal animation is real: SkinnedModelEXT with AnimationPlayer, AnimationClipEXT, BoneTrackEXT and KeyframeEXT, plus MorphTargetEXT blend shapes. All of it sits behind the CNAEXT boundary, so it is visible at compile time as non-XNA surface. PBR draws are implemented on the GL family, Vulkan, OpenGL4, SDL_GPU, WebGPU and Direct3D 9/11/12 (Metal factor-only, Software as a reduced CPU cross-check); FNA3D and PortableGL refuse them.

Complete

Pixel-exact verification against the real XNA runtime Shipped

39 scenes under tools/xna-oracle/, rendered by the genuine Microsoft XNA 4.0 runtime under Wine and DXVK on Linux and diffed byte-for-byte against CNA's DIRECTX9 output at --tolerance 0 — recorded in the repository as matching all 39, run manually rather than in CI, and not yet repeated on native Windows. Alongside it: differential testing against a real running FNA build (tools/fna-reference/, also manual), and a compile-time CNAEXT purity check: defining CNA_STRICT_XNA_API turns CNAEXT declarations into [[deprecated]] warnings that -Werror promotes to errors, though the repository's own harness for it covers only Microsoft::Devices and its sensors.

Complete

A real Input, Audio, Net and Storage core Shipped

Input has zero stubs and a SDL3 GamePad bridge (the native X11 and Wayland platforms read gamepads through evdev). XACT is a real parser and player, not a facade — a real binary parser for the XGS/XWB/XSB formats with FACT's actual volume formula. Net is real ENet over genuine UDP with real LAN discovery and best-effort host migration; PlayerMatch, Ranked and JoinInvited are refused with GamerServicesNotAvailableException rather than pretending. Storage is real std::filesystem IO with correct player namespacing and path-containment checks. See XNA Compatibility for the per-namespace breakdown.

New

XNA API representation closed: 331 of 331 types, 3,627 of 3,627 members Shipped

Every documented type and member of the ten XNA 4.0 runtime assemblies now has a matching C++ declaration (the first census found 3,463), measured by tools/audit_xna_runtime_surface.py against Microsoft's own XML documentation and DLL metadata. That includes the previously missing Microsoft.Xna.Framework.Design namespace: thirteen type converters in the opt-in CNA::Design module (see Framework.Design). This is representation, not behaviour: behaviour is verified only for the subsets on the Verification page, and the census is a manual script, not a CI gate.

New

Native platforms: X11, Wayland and Win32 Shipped

CNA_PLATFORM gained three native implementations that use no SDL — X11 (Xlib, XKB, XInput2, XRandR, GLX), Wayland (xdg-shell, xkbcommon, EGL, Vulkan, wl_shm) and Win32 (user32, gdi32, WGL) — next to SDL3 (the default), SDL2, HEADLESS and TERMINAL, and CNA_ENABLE_SDL=OFF builds without SDL at all. X11 runs in CI (Xvfb) and a Win32 platform harness runs under Wine; Wayland is validated only locally, and Win32 has no gamepad, IME or drag-and-drop support. See Native Platforms.

New

ALSA audio and optional FFmpeg Shipped

CNA_AUDIO_PLATFORM=ALSA plays and records through ALSA (libasound is loaded at run time) with CNA's own mixer and vendored WAV, Ogg Vorbis, MP3 and FLAC decoders, so SDL-free Linux builds have XNA audio. FFmpeg video is now optional (CNA_ENABLE_VIDEO=AUTO|ON|OFF): the Video types link everywhere and throw NotSupportedException when no backend was built.

New

Compiled XNA effects on 14 renderer identities Shipped

Effect(GraphicsDevice&, bytes) and the XNB EffectReader load XNA Effect Framework bytecode on FNA3D (always) and, behind default-OFF build options, on the EasyGL family, Vulkan, WebGPU, Software, Direct3D 9, 11 and 12, SDL_GPU and OpenGL4. A default configure reports the capability on FNA3D only. Runtime HLSL .fx compilation, DXBC and MGFX remain unsupported.

New

Modern-graphics campaigns: OpenGL4, SDL_GPU, WebGPU and Vulkan Shipped

Compute and storage buffers, indirect and base-instance draws, GPU timers, float and half-float render targets, and shadow-map and image-based-lighting sampling landed on the renderers whose code and tests support them. GraphicsCapability grew from 14 to 19 members and the new RendererCapabilityProfile API reports 32 features, 22 limits and per-format usage. 32 cross-renderer parity fixtures run on EasyGL, WebGPU, SDL_GPU and OpenGL4 against the fixtures' own assertions — not against real XNA.

New, opt-in

CNAEXT engine layer Opt-in, not in CI

The CNA::Graphics engine layer grew from 12 to 98 public headers: an HDR render pipeline, more than twenty post-process passes, four shadow-map types, clustered lighting, image-based lighting, sky and fog, compute and storage resources, particles and multi-language shader packages. It needs -DCNA_CNAEXT=ON (default OFF), runs only on renderers with custom-shader support and is at engine-layer revision 18, which its own header calls "not an ABI guarantee". No workflow builds it. See CNAEXT Engine Layer.

New, opt-in

Diagnostics and Inspector Opt-in, not in CI

CNA_DIAGNOSTICS=OFF|STATS|FULL (default OFF) adds counters, gauges, per-frame counters, CPU profiler zones, bounded recording and Chrome-trace export, with built-in instrumentation for frames, draw calls and audio voices. CNA_BUILD_INSPECTOR adds an in-process agent (authenticated TCP) and the cna-inspector bridge that serves an offline browser UI; it is view-only and desktop-only, and no renderer supplies a resource-preview provider yet. No workflow configures either. See Diagnostics and Inspector.

In Progress

Partial, and known to be partial

These exist and work in part. The gaps below are specific and audited, not vague.

Partial

DIRECTX12 — no longer missing scissor, viewport, stencil and blend factor Partial

In alpha.1 the core had PSO and root-signature caches plus a barrier tracker but no scissor, viewport, stencil or blend factor, and MRT cleared without drawing. Those draw-route gaps have since been closed in the source, and the renderer's capability report now states stencil, MRT, occlusion queries, instancing and 3D textures. Its verification surface is still especially narrow: Windows-only, exercised mostly under Wine and in a manually dispatched Windows lane, with no compute or indirect draw, and the multi-target draw path is not independently exercised by this audit.

Partial

WebGPU — formerly no render targets at all Partial

In alpha.1 this was a backbuffer-only forward renderer: no render targets, MSAA, cube or 3D textures, queries or instancing, with a non-functional stencil path. It now reports real MRT (two to four targets), occlusion queries, wireframe, multi-stream input, instancing, probed MSAA, probed float render targets and compute, and it gained a browser route through the Emscripten emdawnwebgpu port and opt-in compiled effects. CNA still declares it Experimental, half-float linear filtering is false, and no workflow builds it.

Partial

Metal — a narrow 3D contract and no compiled effects Partial

Metal is the most conservative 3D renderer: no MSAA, MRT, occlusion queries, instancing, multi-stream input, custom effects, compute or float targets, only SurfaceFormat::Color, factor-only PBR, and no compiled-effect support. CNA declares it Supported, but its own Metal page records no fresh macOS compile-and-run result for the adapted native source; the only automatic macOS lane builds it and runs the Metal* tests. macOS-only, and refused on iOS.

Thin

Continuous integration Partial

The snapshot contains 20 workflow files (28 jobs, 17 of them triggered automatically) covering Linux, Apple, Emscripten, the native X11 platform and a Wine-executed Win32 harness, multi-renderer selection and five build-free C API gates. The alpha.1 defect in which the general job and two Input rows selected a removed renderer value and failed at configure time is fixed. Still absent: any workflow for Wayland, Android, building the C API library or running the oracle corpus; Windows Direct3D and GDI lanes remain manual; and nothing builds the CNAEXT engine layer, Diagnostics or the Inspector. By static reading, several lanes check out sharp-runtime at pinned commits that predate components CNA now requires, and the runs recorded for the snapshot commit did not all conclude successfully (the causes were not investigated for this page). The working lanes provide useful scoped evidence, but not exhaustive coverage across 25 identities, graphics drivers, physical iOS devices or the complete GPU pixel/oracle matrix.

Open

Truthful capability reporting Partial

Six GraphicsCapability answers — compiled effects, float and half-float render targets, half-float linear filtering, compute and indirect draw — are now derived from dedicated renderer hooks that default to false, and multiple render targets are capped by the GraphicsProfile. The remaining entries still fall through to the renderer's own switch, whose shared default is permissive. DIRECTX11, DIRECTX12 and SDL_GPU now override SupportsCapability(), but DIRECTX9 still never does — so it advertises MSAA, occlusion queries, custom effects and instancing without necessarily querying the device. The new RendererCapabilityProfile adds device-probed answers, but a true from the older capability API still means "not contradicted", not "verified".

Experimental

Experimental C API — release gate "Not ready" Partial

The C ABI is at 0.29.0 (alpha.1: 0.7.0) with 61 headers, 4,055 routes and 221 recorded struct layouts. Its committed release report records one unmet criterion: 468 public C++ symbols are still unmapped (9,355 inventoried: 8,363 implemented, 15 partial, 468 planned, 509 not applicable); re-running the gate against this snapshot measures two unmet criteria (coverage and limitations, because its scope model leaves modules/design, modules/diagnostics and modules/inspector unclassified) and its --check fails. The alpha.1 compile blocker — a renderer-map count mismatch — no longer exists in the source, but no CI job builds the library and it was not built for this page. ABI 0.x is experimental: 0.28.0 and 0.29.0 were incompatible steps. The language bindings are separate, pre-alpha projects pinned to ABI 0.21.x, so none is qualified against 0.29.0. See Experimental Native C API.

Remaining boundaries

Work that remains before 1.0

Highest impact

Compiled effects beyond qualified builds Partial

XNA/FNA D3D9 Effect Framework binaries now load through Effect and XNB EffectReader on 14 of the 25 identities: FNA3D always, and thirteen more behind default-OFF build options. What remains open is Metal (no compiled-effect implementation; it needs a macOS build to develop), the 2D-only and no-pixel renderers, and the default configure, which reports the capability on FNA3D only. HLSL .fx source, DXBC and MGFX remain unsupported at run time; .fx sources compile only at build time through an external legacy fxc.

Planned

Consistent surface-format coverage Renderer-dependent

Public Texture2D format admission is renderer-qualified: eight renderer families (SDL_GPU, Vulkan, WebGPU, Direct3D 11 and 12, EasyGL, Software and OpenGL4) classify formats themselves, while the others defer to the framework's Color-only public rule even when an internal renderer layer knows additional native formats. The default Reach profile additionally refuses the eleven HiDef-only formats. The remaining task is a truthful, tested per-renderer contract for every format a game intends to use.

Partly done

ReflectiveReader for custom XNB types Partial

The XNB loader has 61 built-in readers. Video, typed external references and compiled effects are represented, and custom readers can be registered explicitly, either as a ContentTypeReader<T> or, since alpha.1, through ReflectiveTypeReaderBuilder and EnumTypeReader from a declared field list. What remains absent is runtime reflection-based discovery, which C++ does not offer: user and closed-generic types still require deliberate registration.

Planned

A GamerServices service renderer Not started

The GamerServices types are present with complete member signatures. There is no online service behind them — no Steam, no Xbox Live, no HTTP — but CNA does not stop at FNA's no-op shim: achievements and leaderboard entries are genuinely persisted as JSON under a GamerServices directory in the StorageDevice root and reload in a later process, and LeaderboardWriter/LeaderboardReader implement real sorting, ranking and paging. Guide's message-box and keyboard-input paths are real implementations with overlay rendering. What genuinely does nothing is fourteen Guide::Show* overlay entry points plus DelayNotifications, and the XNA-faithful AvatarRenderer::Draw() — the working avatar path is the CNAEXT DrawRealEXT().

Planned

Media portability and codec coverage Platform-dependent

The Media catalogue layer, playback, and FFmpeg-backed video paths are implemented. Remaining boundaries are platform and codec specific: the Video types exist in every build, but file-backed decoding needs the optional FFmpeg backend, which is built only on Linux and macOS (the optional split was not run on macOS by its author), so elsewhere it throws NotSupportedException. SDL_mixer does not provide AAC decoding for .m4a/.aac; CNA's own ALSA mixer decodes WAV, Ogg Vorbis, MP3 and FLAC, and Opus, WMA and XMA are not decoded. Expand only with explicit build and runtime evidence.

Planned

Deeper tests for Media, Storage and Canvas Open

Coverage is uneven rather than absent: Storage has 14 GoogleTest-family definitions (path safety, not read/write round trips), Media 304, and the Canvas renderer 17. Those source counts still leave many runtime paths and platform combinations without execution evidence.

Open

Wayland, Android and oracle checks in CI Open

Native Wayland has registered suites (an in-process test compositor, Weston, Mutter) that are run locally, and Android has code, an SDL entry point and a demo Gradle project, but no workflow selects CNA_PLATFORM=WAYLAND or builds for Android. The 39-scene XNA oracle diff is a CTest only in a DIRECTX9 plus Wine cross-build tree and is in no workflow; the last consolidated dated DIRECTX9 report covers 31 scenes (later per-scene notes record the rest) and a native-Windows re-run is open; EasyGL and Software have a CTest on two line scenes only (the EasyGL test fails on any pixel difference; the Software test only if a scene does not render). Software has been measured at 18 of 39 scenes byte-exact.

Open

Save persistence on the web Open

CNA mounts no persistent file system for Emscripten builds, so anything StorageDevice or GamerServices writes is lost when the page reloads; persist through your own browser storage. This is a documented gap, not a scheduled item.

Long term

Public stable release (v1.0) Long term

The project is versioned, but this snapshot is deliberately pre-1.0: its version string is still 0.1.0-alpha.1 and nothing newer has been tagged. Reaching 1.0 requires an explicit compatibility policy, stable public APIs (the C ABI is 0.x and has taken incompatible steps recently; the engine layer says it is still moving), clearer renderer capability contracts, reproducible configuration-scoped verification and production evidence on the platforms CNA intends to support.

🚀

Contributing: high-value work includes closing named renderer gaps, improving capability accuracy, expanding configuration-specific runtime evidence, and testing this snapshot's new platform, content-pipeline, compiled-effect and C API boundaries. See the GitHub repository (the documented snapshot is on its next branch) and the detailed roadmap.
