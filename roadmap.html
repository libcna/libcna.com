Roadmap

Development Roadmap

CNA is a long-term project developed incrementally. This page describes the honest current state and the path forward - no overpromising, no fake ETAs.

⚠

Honest timeline note: CNA is a long-term open-source project maintained in spare time. There are no fixed release dates. Milestones are goals, not commitments. Progress is incremental and driven by API coverage, backend stability, and real-world testing against ported games.

Current State

Where CNA actually is

236,708 lines of C++23 across 908 source files, and 2,738 commits — 2,183 of them in July 2026 alone. Essentially every public XNA 4.0 type is present, so type presence is about 99%; functional coverage is about 75%, weighted. Verification stands at 4,845 GoogleTest cases across 419 suites, 648 backend pixel and integration tests, and a 39-scene pixel-exact comparison against the real XNA 4.0 runtime.

Read that as: breadth is largely done, depth is not. The sections below separate what has shipped from what is genuinely partial and what nobody has started.

Shipped

What is done and verified

Everything in this list exists in the source tree today and was confirmed by audit rather than by changelog.

Complete

14 rendering backends, selectable at build time Shipped

SDL_RENDERER, EASYGL, BGFX, VULKAN, WEBGPU, HEADLESS, SOFTWARE, D3D11, D3D12, CANVAS, ASCII, DX3, D3D9 and SDL_GPU, chosen with -DCNA_GRAPHICS_BACKEND. Exactly one per binary; there is no runtime dispatch and no fallback. The shared interface, IGraphicsBackend, has 132 virtuals of which 59 are pure. Maturity tracks age: EasyGL, Vulkan, bgfx and SDL_Renderer date from April 2026, and the other nine were created within roughly the last two weeks.

Production-ready

EasyGL backend — the most mature path Shipped

5,305 LOC and 239 CTests. 13 GLSL programs, all 9 effect families, per-vertex and per-pixel lighting, instancing, occlusion queries, anisotropy, fog, and GL context-loss recovery. Only 4 virtuals go unoverridden. This is the Linux default and the backend everything else is measured against.

Complete — was listed here as "planned, not started"

Direct3D 9 backend — functional, and the pixel-exact XNA oracle target Shipped

This page previously described D3D9 as a possible future backend that had not been authorized. That is out of date: D3D9 is 6,902 LOC with 19 CTests, Windows-only, with 43 of its 45 overrides real, 72 verified SM2/SM3 shader blobs, full device-lost and D3DPOOL_DEFAULT recovery, and caps-validated MRT. It is the one backend held to pixel-exact XNA 4.0 authenticity rather than a "looks right" bar, and it is the backend the 39-scene oracle corpus is diffed against at --tolerance 0.

Complete

Vulkan backend Shipped

10,506 LOC and 138 CTests: 35 SPIR-V entry points, 8 effect paths, an MRT proxy, device-queried depth formats, a real stencil PSO, MSAA resolve and mip blit cascades. Functional, close to production.

New

SDL_GPU backend Shipped

6,683 LOC and 21 CTests. A deferred/retained design with 23 SPIR-V blobs, 9 effect families, stencil and MSAA resolve. Its device layer is Vulkan-only today.

New

Dx3 backend — the best 2D fidelity in the project Shipped

1,178 LOC and 9 CTests, 2D only. DirectDraw-shaped, fronting the sibling free-direct project: a real CPU compositor, bilinear filtering, 4 distinct blend formulas, and real Wrap/Mirror addressing — a genuine win over SDL_Renderer. Cross-platform despite the name.

New

Ascii backend Shipped

753 LOC and 6 CTests, 2D only. A thin decorator over SDL_Renderer that quantizes the frame to a glyph and colour grid, with two runtime modes via CNA_ASCII_MODE=BLACKWHITE|COLOR. It is SDL-windowed, not a TTY backend.

New — but untested

Canvas backend (Emscripten) Shipped, untested

1,177 LOC: 11 EM_JS functions with careful un-premultiply and clip handling, mature in design and narrow in scope. The caveat is stated rather than buried: it has zero CTests, and no automated test has ever rendered a single Canvas pixel.

Complete

The .xnb content pipeline Shipped

A real XNB reader, roughly 4,000 LOC, wired into ContentManager: 49 registered type readers covering primitives, math types, textures, SpriteFont, SoundEffect, Song, the stock effects and the model family, on top of a real 31 KB LZX decompressor, the full FNA ContentReader surface, and two-pass shared-resource resolution, fuzz-hardened against malformed files. 24 test files and 134 test cases run against binary MonoGame fixtures. ContentManager prefers a .xnb when one exists and falls back to loose files otherwise. Note that you must call RegisterAllBuiltInXnbReaders() once at startup — a deliberate design decision, but it means the registry is empty by default.

Complete

PBR effects and skeletal animation Shipped

Beyond the six XNA stock effects (all implemented natively in C++, not translated from bytecode), CNA ships non-XNA PbrEffect and SkinnedPbrEffect, plus RenderPipelineSettings, PbrMaterial, TonemappingMode and ShadowQuality. Skeletal animation is real: SkinnedModelEXT with AnimationPlayer, AnimationClipEXT, BoneTrackEXT and KeyframeEXT, plus MorphTargetEXT blend shapes. All of it sits behind the NOXNA boundary, so it is visible at compile time as non-XNA surface.

Complete

Pixel-exact verification against the real XNA runtime Shipped

39 scenes under tools/xna-oracle/, rendered by a real C#/XNA reference renderer and diffed byte-for-byte against CNA's D3D9 output at --tolerance 0. Alongside it: differential testing against a real running FNA build (tools/fna-reference/), and a compile-time NOXNA purity check that turns all 1,289 non-XNA declarations into [[deprecated]] warnings under -Werror.

Complete

A real Input, Audio, Net and Storage core Shipped

Input has zero stubs and a 2,071-line SDL3 GamePad bridge. XACT is a real parser and player, not a facade — a 1,115-line parser for the XGS/XWB/XSB binary formats with FACT's actual volume formula. Net is real ENet over genuine UDP with real LAN discovery. Storage is real std::filesystem IO with correct player namespacing. See XNA Compatibility for the per-namespace breakdown.

In Progress

Partial, and known to be partial

These exist and work in part. The gaps below are specific and audited, not vague.

Partial

D3D12 — missing scissor, viewport, stencil and blend factor Partial

6,819 LOC with a strong core: PSO and root-signature caches and a barrier tracker. But there is no scissor, no viewport, no stencil and no blend factor, and MRT clears without ever drawing. One CTest covers the entire backend.

Partial

WebGPU — no render targets at all Partial

7,110 LOC and 14 CTests, and today a backbuffer-only forward renderer: no render targets, no MSAA, no cube or 3D textures, no queries, no instancing, and a non-functional stencil path. Render-target support is the gating item.

Partial

bgfx — no D3D or Metal shader blobs Partial

4,367 LOC and 114 CTests, with 108 shader blobs built for GL, GLES, Vulkan and WebGPU only. The consequence is worth stating plainly: on bgfx's default Windows and macOS renderers, 3D silently draws nothing. Separately, CreateIndexBuffer32 is never overridden, so DrawUserIndexedPrimitives uploads 32-bit indices into a 16-bit buffer and corrupts geometry.

Thin

Continuous integration Partial

Three workflows exist and only one, input-ci.yml, is auto-triggered — ubuntu-24.04, gcc-14, a 5-way backend matrix, running only the input-labelled tests. devices-tests.yml is path-filtered; d3d-windows-ci.yml is manual dispatch only. There is no macOS, Android or Emscripten CI, and the full CnaTests suite cannot build on any Windows toolchain because roughly 10 files use POSIX ::setenv(). Because backend choice is compile-time, full coverage would need 14 separate configure, build and test runs.

Open

Truthful capability reporting Partial

SupportsCapability() returns true from the base for everything, and 7 of the 14 backends never override it. WebGPU claims 5 capabilities it does not have, Software claims 6, and Ascii reports the inverse of the backend it wraps. Draw offsets (startIndex/baseVertex) are also ignored on D3D11.

Not Started

Real gaps nobody has begun

Highest impact

Compiled .fx shader bytecode Not started

Effect(GraphicsDevice&, byte[]) throws NotImplementedException unconditionally, and there is no MojoShader equivalent anywhere in the tree. Games with custom HLSL effects cannot run; custom shaders are reachable only by hand-writing GLSL or SPIR-V for the NOXNA ShaderEffect, per backend. This is the single biggest real porting gap in the project.

Planned

Surface formats beyond SurfaceFormat::Color Not started

Texture::ValidateFormat throws for all 25 other formats, and it is called from both Texture2D constructors and from Texture3D and TextureCube. DXT and DDS files therefore load only by CPU-decompressing to RGBA, and float, half and HDR render targets are unavailable despite the enum listing them.

Planned

ReflectiveReader for custom XNB types Not started

The XNB pipeline covers the stock types well and cannot load a single user-defined one. C++ has no reflection, so this needs a design decision before any code. Missing alongside it: EnumReader, ExternalReferenceReader, VideoReader and a real EffectReader, which is currently an always-throwing placeholder.

Planned

A GamerServices service backend Not started

All 51 types are present with complete member signatures and there is no backend of any kind behind them — no Steam, no HTTP, no sqlite, not even filesystem persistence. Leaderboard I/O throws, all three Guide::ShowMessageBox entry points throw, 16 of 17 Guide::Show* methods are empty, and GamerServicesDispatcher::Initialize() fabricates four gamers named "Stub Gamer". It is a faithful port of FNA's no-op shim: your code compiles and runs, and nothing persists.

Planned

The Media catalogue layer Not started

14 types — MediaLibrary, MediaSource, Album, Artist, Genre, Playlist, Picture, PictureAlbum and their 6 collections — throw on every member, and MediaLibrary::SavePicture(string, Stream*) is declared with no definition anywhere, which makes it a link error rather than a throw. Playback itself is real: MediaPlayer through SDL3_mixer and VideoPlayer through FFmpeg, though FFmpeg is unavailable on Emscripten, Android and every Windows target.

Planned

Tests for Media, Storage and Canvas Not started

Media and Storage have zero unit tests, and the Canvas backend has zero CTests. Storage in particular is believed complete and correct, which is exactly the situation where an absent suite is worth flagging.

Long term

Public stable release (v1.0) Long term

A versioned release other projects can safely depend on. Reaching it plausibly requires .fx support (or an explicit decision never to have it), surface formats beyond Color, coverage for the untested namespaces, CI that gates the full unit suite on at least one platform, and an API stability guarantee — which is not something to offer while 2,183 commits land in a single month.

🚀

Contributing: CNA is open source (Ms-PL). The highest-value contributions right now are the unglamorous ones — writing the missing Media and Storage tests and the first Canvas pixel test, closing the named backend gaps, making SupportsCapability() truthful, and removing the POSIX ::setenv() dependency so the test suite can build on Windows. See the GitHub repository for open issues and the TODO list, and the detailed roadmap for the full breakdown.
