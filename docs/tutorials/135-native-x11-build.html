Tutorial 135: Running on X11 through SDL3

CNA Tutorials  ·  CNA snapshot c6dec91f

ℹ

What you’ll learn: how CNA reaches X11 through SDL3’s x11 video driver, which packages the vendored SDL3 needs to get that driver, how to select it, how to confirm which window system a running game is on, and what CNA’s own tests prove about it.

ℹ

Before you start — Tutorial 02: Setting Up Your Dev Environment for the workspace layout (CNA, sharp-runtime, easy-gl and meta-gl) and Tutorial 03: Your First CNA Window for the small game used in step 5. You need a Linux machine with an X server: Xorg, or Xwayland on a Wayland desktop. Without a display you can follow along with xvfb-run.

On an Xorg session — or on a Wayland desktop through Xwayland — a CNA game opens its window through SDL3’s x11 video driver. SDL3 is CNA’s one windowing implementation, so there is nothing X11-specific to select in CNA itself: you make sure the vendored SDL3 is built with its X11 driver, pick that driver when more than one is available, and let the renderer take the Display* and window it needs from the SDL3 window.

What you are building

CNA’s own 3D house demo and 2D demo, built once with the default SDL3 platform and run on SDL’s x11 driver, then a few lines in your own game that report which window system it is on.

1. Install the packages before the first configure

The vendored SDL3 is configured by CNA’s own build and gets exactly the video drivers whose development files it finds at that moment. Install them first (the Debian and Ubuntu names CNA’s own platform workflow installs; Building has the full list for both Linux drivers and the GL/Vulkan/audio packages):

sudo apt install libx11-dev libxext-dev libxrandr-dev libxi-dev libxcursor-dev \
                 libxfixes-dev libxss-dev libxtst-dev libxkbcommon-dev

Installing them later does not add the driver to an SDL that was already configured: start a fresh build directory.

2. Configure and build

cmake -S cna -B cna/build -G Ninja -DCNA_GRAPHICS_RENDERER=OPENGL33 \
      -DCMAKE_C_COMPILER_LAUNCHER=ccache -DCMAKE_CXX_COMPILER_LAUNCHER=ccache
cmake --build cna/build --parallel

CNA_PLATFORM is left at its default, SDL3. Any renderer that runs in an SDL3 window works here; OPENGL33 and SDL_GPU (on SDL’s Vulkan driver) are good 3D choices on a Linux desktop, and the default OPENGLES3 needs nothing extra. The 3D house demo below is built only when the renderer is a GL profile, WEBGPU or FNA3D; with SDL_GPU run the 2D demo.

3. Run on the x11 driver

SDL_VIDEODRIVER=x11 ./cna/build/cna_house3d_demo
SDL_VIDEODRIVER=x11 ./cna/build/cna_demo_2d

SDL picks a driver by itself when SDL_VIDEODRIVER is unset; setting it makes the choice explicit, and SDL reports an error if the driver is not in this build. SDL_VIDEODRIVER=wayland runs the same binary on the other Linux window system when its driver is present.

4. Your own game needs no change

A game written against the XNA API does not name the window system. The same executable runs on X11 and Wayland (and the same source on Windows and macOS) because the window comes from SDL3 and the renderer asks the platform for what it needs: EasyGL for a GL context, SDL_GPU and FNA3D for the SDL window itself, WEBGPU for the native handle.

5. Ask which window system you are on

GameWindow::GetNativeWindowHandleEXT() (a CNAEXT extension, so hidden in a CNA_STRICT_XNA_API build) returns the NativeWindowHandle the renderer received. Add this to LoadContent() of the game from Tutorial 03:

#include <iostream>

#include "CNA/Platform/NativeWindowHandle.hpp"
#include "CNA/Platform/NativeWindowSystem.hpp"

void MyGame::LoadContent()
{
    const CNA::Platform::NativeWindowHandle handle =
        getWindowProperty().GetNativeWindowHandleEXT();
    std::cout << "window system: " << CNA::Platform::ToString(handle.system) << '\n';

    CNA::Platform::X11NativeWindow x11{};
    if (CNA::Platform::TryGetX11(handle, x11)) {
        std::cout << "Display* " << x11.display << ", window XID " << x11.window << '\n';
    }
}

The TryGet… functions return true only when the window really is that system, so code written for one window system refuses another by name instead of misreading its pointers.

Troubleshooting

  • x11 not available from SDL. The vendored SDL3 was configured before the X11 packages were installed. Install them and reconfigure SDL from scratch (remove the build directory’s SDL cache, or start a new build directory).
  • No display. Run under xvfb-run -a, or point DISPLAY at a running X server.
  • A GPU renderer refuses to start. Check the renderer’s own requirement (a Vulkan driver for SDL_GPU on Linux, the easy-gl and meta-gl siblings for the GL renderers); the window system is rarely the cause.

What CNA’s tests cover — and what they do not

CnaPlatformSdl3X11Tests runs the SDL3 window suite and the window conformance suite on a private Xvfb (tools/platform/x11_test_server.sh) with SDL_VIDEODRIVER=x11, and Sdl3WindowTest.NativeHandleMatchesTheVideoDriver asserts the handle a renderer receives. The platform workflow runs it on every push to CNA’s integration branches, and fails the step if it skips. CNA’s recorded local validation (2026-10-06) passed 38 of its tests with none skipped, and ran several renderers’ 3D house and 2D demos on the x11 driver. Neither is a run on a real desktop session with a physical GPU; treat those as your own test.
