CNA backend architecture

CNA's rendering pipeline is split into a frontend (the XNA-compatible API in Microsoft::Xna::Framework::Graphics) and a backend (the actual GPU calls). The backend interface is IGraphicsBackend. The frontend delegates all draw calls to the active backend through this interface. You can add a new backend without modifying any frontend code.

IGraphicsBackend interface overview

The interface lives in include/CNA/Internal/Backends/Common/IGraphicsBackend.hpp, in namespace CNA::Internal::Backends. That one header declares the whole backend contract: IGraphicsBackend itself plus the resource interfaces it hands back.

The design is not one flat interface of opaque integer handles. IGraphicsBackend is a factory: it owns the window and the frame, and it returns std::unique_ptrs to per-resource backend objects, each with its own small interface.

  • Frame and surface: Clear(float r, float g, float b, float a), Present(), GetViewportSize(int&, int&), SetVirtualResolution(int, int), SetPresentationMode(int).
  • Resource factories: CreateTexture(const ImageData&), CreateSpriteBatch(), CreateOcclusionQuery(), CreateTexture3D(…), CreateTextureCube(…) — returning ITextureBackend, ISpriteBatchBackend, IOcclusionQueryBackend, and friends.
  • Resource interfaces declared alongside it: IVertexBufferBackend, IIndexBufferBackend, IEffectBackend, IRenderTargetBackend, IRenderTargetCubeBackend.
  • SDL escape hatches, still marked TODO: abstract later in the header: GetWindowInternal(), GetRendererInternal().
ℹ

The interface carries 59 pure virtual methods. Many more are virtual-with-a-default, deliberately: ReadBackbuffer throws unless overridden, SetSwapInterval is a no-op, CreateOcclusionQuery returns nullptr, and the coordinate-transform pair returns false to mean “window space equals logical space”. A partial backend is a supported thing to build — you override what your API can do and inherit a documented fallback for the rest.

Skeleton custom backend class

A backend is constructed ready to draw — there is no separate Init/Shutdown pair, the constructor and destructor do that work. Below is the shape of a minimal backend; the real ones under src/CNA/Internal/Backends/ are the authoritative reference for the remaining overrides.

// MyCustomGraphicsBackend.hpp
#pragma once
#include "CNA/Internal/Backends/Common/IGraphicsBackend.hpp"

namespace CNA::Internal::Backends::MyCustom
{
    class MyCustomGraphicsBackend final : public IGraphicsBackend
    {
    public:
        explicit MyCustomGraphicsBackend(const GraphicsBackendCreateArgs& args);
        ~MyCustomGraphicsBackend() override;

        // --- Frame ---
        void Clear(float r, float g, float b, float a) override;
        void Present() override;
        void GetViewportSize(int& width, int& height) override;
        void SetVirtualResolution(int width, int height) override;
        void SetPresentationMode(int mode) override;

        // --- SDL escape hatches (still required by the interface) ---
        SDL_Window*   GetWindowInternal()   const override { return window_; }
        SDL_Renderer* GetRendererInternal() const override { return nullptr; }

        // --- Resource factories ---
        std::unique_ptr<ITextureBackend>     CreateTexture(const ImageData& data) override;
        std::unique_ptr<ISpriteBatchBackend> CreateSpriteBatch() override;

        // Optional: the base class already returns nullptr, meaning
        // "this backend has no hardware occlusion queries".
        std::unique_ptr<IOcclusionQueryBackend> CreateOcclusionQuery() override
        {
            return nullptr;
        }

    private:
        SDL_Window* window_        = nullptr;
        int         virtualWidth_  = 0;
        int         virtualHeight_ = 0;
    };
}

Each factory returns an object implementing its own small interface. ITextureBackend, for instance, requires only GetWidth(), GetHeight() and GetNativeTexture(); UpdatePixels, UpdatePixelsLevel, BindGL and GetData all have no-op defaults you override when your API supports them.

Selecting a backend

⚠

There is no runtime backend registry in CNA — no Register("NAME", factory) call, and nothing to do inside main(). The backend is a compile-time choice: exactly one backend translation unit is compiled into the library, chosen by the CNA_GRAPHICS_BACKEND CMake option.

The whole contract between CNA and a backend implementation is one free function, in namespace CNA::Internal::Backends, defined by whichever backend .cpp got compiled. GraphicsDevice calls it — unqualified, resolved at link time — and never knows which backend it got:

// MyCustomGraphicsBackend.cpp
namespace CNA::Internal::Backends
{
    std::unique_ptr<IGraphicsBackend> CreateGraphicsBackend(
        const GraphicsBackendCreateArgs& args)
    {
        return std::make_unique<MyCustom::MyCustomGraphicsBackend>(args);
    }
}

GraphicsBackendCreateArgs is what the frontend hands you at construction: the SDL_Window*, the requested virtualWidth/virtualHeight, a CnaPresentationMode, multiSampleCount, the swap interval, and the contextRecoveryEnabled flag. Add your source directory and a CNA_BACKEND_MYCUSTOM compile definition to the backend branch in CMakeLists.txt, then configure with -DCNA_GRAPHICS_BACKEND=MYCUSTOM.

Texture upload path

Texture2D asks the backend for one object per texture rather than juggling handles: it calls backend->CreateTexture(imageData) and keeps the returned std::unique_ptr<ITextureBackend> for the texture's lifetime. Later writes go through that object — UpdatePixels(rgba, stride) for a full level-0 replacement, UpdatePixelsLevel(level, rgba, w, h) for an individual mip. Readback runs the other way through GetData(…), and Texture2D only reaches for it when it has no CPU-side shadow copy of its own — in practice, for render targets.

If your backend can lose its GPU context (WebGL, or an Android app going to background), implement ShareCpuPixels: Texture2D passes a shared_ptr to the pixel buffer it already owns, so you can restore from it after a context loss without keeping a second copy.

Shader compilation

Shaders are the responsibility of IEffectBackend, not of IGraphicsBackend directly. How the source reaches the GPU is entirely the backend's business, and CNA's own backends deliberately disagree: EasyGL and Vulkan consume GLSL (Vulkan compiling to SPIR-V), the WebGPU backend uses WGSL via wgpu-native, and the D3D11/D3D12 backends ship all stock shader variants as hand-written HLSL rather than transpiling anything. Pick whichever of those is closest to your target API and read that backend first.

Real reference implementations

This tutorial teaches the interface shape using a hypothetical MYCUSTOM backend, but CNA now ships several real, non-hypothetical backends worth reading as reference implementations of the same IGraphicsBackend contract: native Direct3D D3D11/D3D12 (Windows-only, hand-written HLSL), an experimental native WEBGPU backend (WGSL shaders via wgpu-native), and two CI/testing-oriented backends, HEADLESS (implements the full interface without a GPU or window at all) and SOFTWARE (a real CPU rasterizer, useful as a template if your custom backend also needs to produce genuine pixels without a GPU). Source lives under src/CNA/Internal/Backends/{D3D11,D3D12,WebGPU,Headless,Software}/ in the CNA repository.

Testing strategy

Configure with -DCNA_GRAPHICS_BACKEND=MYCUSTOM and run CNA's 4,845-test suite. The math tests never touch the GPU, so they pass the moment your backend constructs without crashing — that alone validates the frontend against your build. The 648 backend pixel and integration tests are the real exercise: they open a window, render, and compare output.

The HEADLESS backend is the model to copy for bring-up. It implements the full interface with no GPU and no window, but it still validates its arguments and tracks resource lifetimes rather than stubbing everything out — which means it catches frontend misuse instead of silently swallowing it.
