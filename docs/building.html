Building CNA

CMake-based build system  ·  C++23 required

Step 1 - Clone and initialise submodules

git clone https://github.com/openeggbert/cna.git
cd cna
git submodule update --init --recursive

This populates third_party/SDL, third_party/SDL_image, and third_party/SDL_mixer. After this step, SDL is built from source by the CMake build - no system SDL packages are required.

Step 2 - Select a backend and build

CNA requires exactly one rendering backend to be selected at configuration time via -DCNA_GRAPHICS_BACKEND=<BACKEND>. Nine backends are available today: SDL_RENDERER, EASYGL, BGFX, and VULKAN are CNA's four established, cross-platform, pixel-test-verified backends; WEBGPU is an experimental native desktop backend; HEADLESS and SOFTWARE are CI/testing-only backends that need no GPU or display server; and D3D11/D3D12 are native, Windows-only backends (Wine-verified from Linux, not yet verified on real Windows hardware).

Linux - EasyGL (OpenGL) backend

cmake -S . -B build -DCNA_GRAPHICS_BACKEND=EASYGL
cmake --build build --target CNA CnaTests

Requires ../easy-gl to be present alongside the CNA repository.

Linux - SDL_Renderer backend

cmake -S . -B build-sdlrenderer -DCNA_GRAPHICS_BACKEND=SDL_RENDERER
cmake --build build-sdlrenderer --target CNA CnaTests

Windows - SDL_Renderer backend (MSVC)

On Windows with MSVC 2022 opened from a Developer Command Prompt:

git submodule update --init --recursive
cmake -S . -B build-win -DCNA_GRAPHICS_BACKEND=SDL_RENDERER
cmake --build build-win --target CNA CnaTests

Linux → Windows cross-compilation (MinGW-w64)

# Install the cross toolchain (Debian/Ubuntu)
sudo apt install mingw-w64

git submodule update --init --recursive
cmake -S . -B build-windows \
      -DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/mingw-w64.cmake \
      -DCNA_GRAPHICS_BACKEND=SDL_RENDERER
cmake --build build-windows --target CNA CnaTests

bgfx backend

cmake -S . -B build-bgfx -DCNA_GRAPHICS_BACKEND=BGFX
cmake --build build-bgfx --target CNA

bgfx is fetched via CMake FetchContent - no separate clone needed. Implementation is ongoing; not all features are complete.

Vulkan backend

cmake -S . -B build-vulkan -DCNA_GRAPHICS_BACKEND=VULKAN
cmake --build build-vulkan --target CNA

The Vulkan backend is CNA's second-most mature backend: full 2D and 3D pipeline, all five stock effects (pixel-tested), instancing, MRT, MSAA 4×, FillMode::WireFrame, and Texture3D/TextureCube. Open gaps: BlendState Requires a Vulkan-capable GPU and driver. Vulkan SDK headers must be present (usually via your distribution's vulkan-headers / libvulkan-dev package).

WebGPU backend (experimental)

cmake -S . -B build-webgpu -DCNA_GRAPHICS_BACKEND=WEBGPU
cmake --build build-webgpu --target CNA

An experimental fifth backend using native wgpu-native (pinned v29.0.1.1). By default CMake downloads the official prebuilt package automatically; for an offline/reproducible build, extract the package yourself and pass -DCNA_WEBGPU_ROOT=/absolute/path/to/wgpu-native -DCNA_WEBGPU_AUTO_DOWNLOAD=OFF. The native 2D baseline (SpriteBatch, Texture2D, resize/present, backbuffer readback) is verified, including against an independent real game; most stock 3D effects, render targets, and full state-object mapping are still open. Browser/Emscripten WebGPU is not implemented — this is the native desktop backend only.

Headless backend (CI/testing-only)

cmake -S . -B build-headless -DCNA_GRAPHICS_BACKEND=HEADLESS -DCNA_BUILD_TESTS=ON
cmake --build build-headless -j

Renders nothing by design — no window, no GPU context, no OpenGL/Vulkan library is even linked. Every draw/resource call does real bookkeeping instead (argument validation, resource-lifecycle tracking, draw-call/state-change counters), controlled by a runtime strictness dial (CNA_HEADLESS_MODE=Fast|Validation|Trace). Built for fast CI runs of game logic with no display server needed at all — not for verifying pixel output.

Software backend (CPU rasterizer, CI/testing-only)

cmake -S . -B build-software -DCNA_GRAPHICS_BACKEND=SOFTWARE -DCNA_BUILD_TESTS=ON
cmake --build build-software -j

Unlike Headless, this backend actually rasterizes real triangles into a CPU-owned RGBA8 framebuffer (a real edge-function rasterizer, perspective-correct interpolation, real per-pixel depth test) — no GPU, window, or display server involved at any point. Useful for deterministic pixel tests on GPU-less CI machines. Verified against EasyGL on a canonical test scene with a max per-channel pixel difference of 1. Not a real-time backend: no SIMD, no multithreading, and Present() is a no-op.

Direct3D 11 backend (native Windows, Wine-verified)

# Install the cross toolchain (Debian/Ubuntu)
sudo apt install mingw-w64

cmake -S . -B build-d3d11 \
      -DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/mingw-w64.cmake \
      -DCNA_GRAPHICS_BACKEND=D3D11 \
      -DCNA_BUILD_TESTS=ON
cmake --build build-d3d11 -j

D3D11 is hard-gated to CMAKE_SYSTEM_NAME=Windows at configure time — it cannot be selected on a native Linux/macOS configure. A real ID3D11Device/ID3D11DeviceContext backs this: all 10 stock HLSL shader variants, textures/render targets (MRT/MSAA/occlusion queries), all four state-object classes, a real SpriteBatch, and a runtime-D3DCompile() custom ShaderEffect path, all pixel-verified (6 CTest binaries, 96+ checks). Verified by cross-compiling with MinGW-w64 and running the result through Wine + DXVK on a real GPU — this proves the backend's logic, not real-Windows-hardware parity (MSVC build, real DXGI present/tearing, device-lost recovery, and WARP fallback are still open). To reproduce the Wine dev-loop:

sudo apt-get install -y dxvk-wine64
WINEPREFIX=~/.wine-cna-d3d11 wineboot --init
WINEPREFIX=~/.wine-cna-d3d11 dxvk-setup install
scripts/run-wine-dxvk.sh build-d3d11/examples/d3d11_smoke_test.exe

Direct3D 12 backend (native Windows, Wine-verified, off-screen only)

cmake -S . -B build-d3d12 \
      -DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/mingw-w64.cmake \
      -DCNA_GRAPHICS_BACKEND=D3D12 \
      -DCNA_BUILD_TESTS=ON
cmake --build build-d3d12 --target CNA

Same Windows-only CMake gate as D3D11. Built directly on D3D11's own HLSL/DXBC bytecode and format/state tables. Real command queues, descriptor heaps, command lists, fences, a per-resource barrier tracker, PSOs, root signatures, all 10 stock HLSL shader variants, a real SpriteBatch, and functionally-proven device-removed recovery are all pixel-verified off-screen (the D3D12_Smoke CTest: 80/80 checks). Verified via Wine + vkd3d-proton (a separate translation layer and Wine prefix from D3D11's own DXVK setup) — swap-chain presentation genuinely crashes under this dev loop (a real Wine/vkd3d-proton dxgi.dll architecture mismatch, not a CNA bug), so every proof stays off-screen; real-Windows-hardware verification is also still open. Runtime-settable blend/depth-stencil/rasterizer state, per-slot SamplerState, a public render-target backend, Texture3D, and occlusion queries are not yet implemented for this backend. Test binaries run through scripts/run-wine-vkd3d.sh, which needs vkd3d-proton's d3d12.dll/d3d12core.dll (obtainable from a Steam "Proton - Experimental" install or vkd3d-proton's prebuilt GitHub releases) registered as native DLL overrides in a dedicated Wine prefix.

Emscripten / WebAssembly (EasyGL + WebGL 2)

# 1. Install and activate the Emscripten SDK
git clone https://github.com/emscripten-core/emsdk.git
cd emsdk
./emsdk install latest
./emsdk activate latest
source ./emsdk_env.sh
cd ..

# 2. Configure and build
cmake -S cna -B build-wasm \
      -DCMAKE_TOOLCHAIN_FILE=$EMSDK/upstream/emscripten/cmake/Modules/Platform/Emscripten.cmake \
      -DCNA_GRAPHICS_BACKEND=EASYGL
cmake --build build-wasm --target CNA

Output files are .html, .js, and .wasm. Serve them from a local web server — browsers block direct file:// access due to CORS. FFmpeg video (VideoPlayer) is excluded on this target. Assets must be preloaded via Emscripten's --preload-file linker flag.

Android (SDL_Renderer backend, Android NDK)

cmake -S . -B build-android \
      -DCMAKE_TOOLCHAIN_FILE=$ANDROID_NDK/build/cmake/android.toolchain.cmake \
      -DANDROID_ABI=arm64-v8a \
      -DANDROID_PLATFORM=android-21 \
      -DCNA_GRAPHICS_BACKEND=SDL_RENDERER
cmake --build build-android --target CNA

SDL3's native Android JNI/Activity layer is used. Set ANDROID_NDK to your NDK path. The build has been validated on Android hardware with the SDL_RENDERER backend. Sensor (Accelerometer) and touch input need runtime validation on an Android device.

Optional: use system-installed SDL

By default CNA builds SDL3 from the vendored submodules. If you prefer to link against system SDL3 packages, pass -DCNA_USE_SYSTEM_SDL=ON:

cmake -S . -B build -DCNA_USE_SYSTEM_SDL=ON -DCNA_GRAPHICS_BACKEND=SDL_RENDERER
cmake --build build --target CNA CnaTests

This calls find_package for SDL3, SDL3_image, and SDL3_mixer. The packages must be installed (e.g. via your distribution's package manager).

Running the tests

ctest --test-dir build --output-on-failure

Running the demos

# Hello-triangle verification target (EasyGL / SDL_RENDERER)
cmake --build build --target hello-triangle-sdl

# House 3D demo (EasyGL backend)
cmake --build build --target cna_house3d_demo
./build/cna_house3d_demo

# 2D demo
cmake --build build --target cna_demo_2d
./build/cna_demo_2d

Troubleshooting

sharp-runtime not found

CNA requires sharp-runtime to be present as a sibling directory:

parent/
├── cna/
└── sharp-runtime/

Clone sharp-runtime next to CNA and re-run CMake configuration.

easy-gl not found (EASYGL backend)

The EASYGL backend requires easy-gl as a sibling directory. Clone it alongside CNA or switch to SDL_RENDERER if you do not need OpenGL.

Submodule directories empty

Run git submodule update --init --recursive from the repository root. If this fails, check your network and that the submodule URLs in .gitmodules are accessible.

Vulkan: no Vulkan device found

The Vulkan backend requires a Vulkan-capable GPU and driver. On Linux, install libvulkan-dev and ensure your GPU driver provides a Vulkan ICD (check with vulkaninfo). On virtual machines without GPU passthrough, Vulkan is generally not available.

EASYGL: OpenGL context creation failed

The EasyGL backend requires OpenGL ES 3.0 (or OpenGL 3.0+ desktop with ES emulation). On Linux, ensure your GPU driver is installed and your display server is running. On headless CI servers, use a software renderer such as LIBGL_ALWAYS_SOFTWARE=1 or Mesa's llvmpipe.

bgfx: FetchContent download fails

The BGFX backend fetches bgfx.cmake via CMake's FetchContent during configuration. This requires an internet connection. If you are behind a proxy, set the https_proxy environment variable before running CMake.

WebGPU: wgpu-native package not found

By default the WEBGPU backend downloads the pinned wgpu-native v29.0.1.1 package automatically at configure time, which requires an internet connection. For an offline or reproducible build, extract the official package yourself (it must contain include/webgpu.h and a libwgpu_native library under lib/) and pass -DCNA_WEBGPU_ROOT=/absolute/path -DCNA_WEBGPU_AUTO_DOWNLOAD=OFF.

D3D11 / D3D12: "requires CMAKE_SYSTEM_NAME=Windows"

Both Direct3D backends are hard-gated to a Windows target and fail fast with a FATAL_ERROR on a native Linux/macOS configure. Cross-compile from Linux using -DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/mingw-w64.cmake (the same MinGW-w64 toolchain SDL_RENDERER's own Windows cross-build already uses), then run the resulting binaries through scripts/run-wine-dxvk.sh (D3D11, needs Wine + DXVK) or scripts/run-wine-vkd3d.sh (D3D12, needs Wine + vkd3d-proton, a separate Wine prefix from D3D11's). Both wrappers fail loudly if the run silently fell back to a software path instead of the expected translation layer.

CNA

A modern C++ reimplementation of the XNA 4.0 API. 227 of 245 XNA 4.0 public types implemented, verified by 4,373 unit tests and 490 GPU pixel tests across its four established rendering backends.
