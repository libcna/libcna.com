Building CNA

CMake-based build system  ·  C++23 required  ·  CMake >= 3.20  ·  14 selectable backends

Step 1 - Clone and initialise submodules

git clone https://github.com/openeggbert/cna.git
cd cna
git submodule update --init --recursive

This populates third_party/SDL, third_party/SDL_image, and third_party/SDL_mixer. After this step, SDL is built from source by the CMake build - no system SDL packages are required.

Step 2 - Check the sibling repositories

CNA does not vendor everything. Some dependencies must exist as sibling directories next to the CNA checkout, because CMake pulls them in with add_subdirectory(../<repo>).

Sibling repoRequired whenWhat it is
../sharp-runtime Always A C++23 reimplementation of a .NET BCL subset (135,204 lines). CNA is built on it - System::* collections, IO, text, threading, numerics and so on all come from here. Without it, CNA does not configure at all.
../easy-gl Only for -DCNA_GRAPHICS_BACKEND=EASYGL A toolkit-independent OOP wrapper over OpenGL / OpenGL ES. It in turn pulls in meta-gl.
../free-direct Only for -DCNA_GRAPHICS_BACKEND=DX3 A DirectX 3 / DirectDraw 2D subset implemented over SDL3, which the Dx3 backend fronts.

Everything else is vendored or fetched. SDL3, SDL_image and SDL_mixer are git submodules, built once and cached - no system SDL packages are needed. googletest is a submodule too. enet, cgltf, stb and wgpu-native (pinned to v29.0.1.1) are in-tree. FFmpeg is found through pkg-config, is optional, and is only available on desktop Linux.

⚠

bgfx.cmake is the project's only unpinned dependency. It is fetched via FetchContent at GIT_TAG master, so a BGFX build is not reproducible over time and needs network access at configure time.

Step 3 - Select a backend and build

CNA requires exactly one rendering backend to be selected at configuration time via -DCNA_GRAPHICS_BACKEND=<BACKEND>. 14 backends are available today. The default is EASYGL on Linux and Emscripten, and SDL_RENDERER everywhere else.

The three Direct3D backends are hard-gated to CMAKE_SYSTEM_NAME=Windows and fail fast on a native Linux or macOS configure. CANVAS is equally gated to an Emscripten target. Maturity varies enormously between these 14 - see Rendering Backends before committing to one.

Linux - EasyGL backend (the default, and the most mature)

cmake -S . -B build -DCNA_GRAPHICS_BACKEND=EASYGL
cmake --build build --target CNA CnaTests

Requires ../easy-gl alongside the CNA repository. This is the best-verified backend, with 239 registered CTest entries.

Linux - SDL_Renderer backend (2D only)

cmake -S . -B build-sdlrenderer -DCNA_GRAPHICS_BACKEND=SDL_RENDERER
cmake --build build-sdlrenderer --target CNA CnaTests

68 CTest entries. 2D only - 3D entry points throw by design rather than silently doing nothing.

Vulkan backend

cmake -S . -B build-vulkan -DCNA_GRAPHICS_BACKEND=VULKAN
cmake --build build-vulkan --target CNA

The largest backend in the tree and the second-best verified (138 CTest entries). Requires a Vulkan-capable GPU and driver; Vulkan SDK headers must be present, usually via your distribution's vulkan-headers or libvulkan-dev package.

SDL_GPU backend

cmake -S . -B build-sdlgpu -DCNA_GRAPHICS_BACKEND=SDL_GPU
cmake --build build-sdlgpu --target CNA

SDL3's GPU API, with a deferred/retained design and 23 SPIR-V blobs covering 9 effect families. Vulkan is the only device backing it today. 21 CTest entries.

bgfx backend

cmake -S . -B build-bgfx -DCNA_GRAPHICS_BACKEND=BGFX
cmake --build build-bgfx --target CNA

bgfx is fetched via CMake FetchContent - no separate clone needed, but network access is required at configure time and the tag is unpinned. Its 108 shader blobs cover OpenGL, OpenGL ES, Vulkan and WebGPU only; there are no D3D or Metal variants.

WebGPU backend (experimental)

cmake -S . -B build-webgpu -DCNA_GRAPHICS_BACKEND=WEBGPU
cmake --build build-webgpu --target CNA

Uses native wgpu-native, pinned to v29.0.1.1. By default CMake downloads the prebuilt package automatically; for an offline or reproducible build, extract the package yourself and pass -DCNA_WEBGPU_ROOT=/absolute/path -DCNA_WEBGPU_AUTO_DOWNLOAD=OFF. It is a backbuffer-only forward renderer with no render targets, no MSAA and no instancing.

Software backend (CPU rasterizer)

cmake -S . -B build-software -DCNA_GRAPHICS_BACKEND=SOFTWARE -DCNA_BUILD_TESTS=ON
cmake --build build-software -j

A genuine CPU rasterizer - edge functions, a real Z-buffer, perspective-correct 1/w interpolation - with no GPU, window or display server involved. TriangleList is the only supported primitive type.

Headless backend

cmake -S . -B build-headless -DCNA_GRAPHICS_BACKEND=HEADLESS -DCNA_BUILD_TESTS=ON
cmake --build build-headless -j

Renders nothing by design. ReadBackbuffer returns the last clear colour and discards the requested coordinates. Built for fast CI runs of game logic, not for verifying pixel output.

Dx3 backend (2D only)

cmake -S . -B build-dx3 -DCNA_GRAPHICS_BACKEND=DX3
cmake --build build-dx3 --target CNA

Requires ../free-direct alongside the CNA repository. Despite the DirectDraw-shaped API it is genuinely cross-platform and is not Windows-gated. It has the best 2D fidelity of any backend, including real Wrap and Mirror texture addressing.

Ascii backend (2D only)

cmake -S . -B build-ascii -DCNA_GRAPHICS_BACKEND=ASCII
cmake --build build-ascii --target CNA

# Two runtime modes, selected by environment variable:
CNA_ASCII_MODE=BLACKWHITE ./build-ascii/cna_demo_2d
CNA_ASCII_MODE=COLOR      ./build-ascii/cna_demo_2d

A thin decorator over SDL_Renderer that quantizes the frame into a glyph and colour grid. It is SDL-windowed, not a TTY backend.

Direct3D 9 backend (Windows-only)

# Install the cross toolchain (Debian/Ubuntu)
sudo apt install mingw-w64

cmake -S . -B build-d3d9 \
      -DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/mingw-w64.cmake \
      -DCNA_GRAPHICS_BACKEND=D3D9 \
      -DCNA_BUILD_TESTS=ON
cmake --build build-d3d9 -j

The XNA-authenticity backend: 43 of its 45 overrides are real, it carries 72 verified SM2/SM3 shader blobs, and it implements full device-lost and D3DPOOL_DEFAULT recovery. It is the backend the 39-scene XNA oracle corpus under tools/xna-oracle/ is diffed against pixel-exactly at --tolerance 0. Verified from Linux through Wine + DXVK on a real GPU.

Direct3D 11 backend (Windows-only)

cmake -S . -B build-d3d11 \
      -DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/mingw-w64.cmake \
      -DCNA_GRAPHICS_BACKEND=D3D11 \
      -DCNA_BUILD_TESTS=ON
cmake --build build-d3d11 -j

Five state-object caches, MRT with deferred resolve, instancing, and runtime shader compilation via D3DCompile. Verified from Linux through Wine + DXVK on a real GPU, and on real Windows via the manual MSVC CI workflow. Note that only 7 CTest entries cover its 4,521 lines, and that draw offsets (startIndex / baseVertex) are ignored on this backend.

Direct3D 12 backend (Windows-only, partial)

cmake -S . -B build-d3d12 \
      -DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/mingw-w64.cmake \
      -DCNA_GRAPHICS_BACKEND=D3D12 \
      -DCNA_BUILD_TESTS=ON
cmake --build build-d3d12 --target CNA

Same Windows-only gate, and it shares the D3DCommon DXBC shader bytecode with D3D9 and D3D11. The core is strong - PSO and root-signature caches, a real barrier tracker - but this backend is rated partial: there is no scissor, no viewport, no stencil and no blend factor, and MRT clears but never draws. Exactly one CTest entry covers its 6,819 lines. Verified from Linux through Wine + vkd3d-proton, and on real Windows via the manual MSVC CI workflow.

Emscripten / WebAssembly

# 1. Install and activate the Emscripten SDK
git clone https://github.com/emscripten-core/emsdk.git
cd emsdk
./emsdk install latest
./emsdk activate latest
source ./emsdk_env.sh
cd ..

# 2. Configure via the bundled 'web' preset (EasyGL is the default here)
cmake -S cna --preset web
cmake --build cna/build-web --target CNA

# Or select the Emscripten-only Canvas backend explicitly
emcmake cmake -S cna -B build-canvas -DCNA_GRAPHICS_BACKEND=CANVAS
cmake --build build-canvas --target CNA

Web is a real build path, not an aspiration: there is a web CMake preset, a prebuilt Emscripten SDL tree, and -sASYNCIFY / -sEXIT_RUNTIME test wiring. Output files are .html, .js and .wasm; serve them from a local web server, since browsers block direct file:// access. FFmpeg is unavailable on Emscripten, so VideoPlayer is excluded. There is no Emscripten CI job, and the CANVAS backend has zero automated pixel tests.

Android (Android NDK)

cmake -S . -B build-android \
      -DCMAKE_TOOLCHAIN_FILE=$ANDROID_NDK/build/cmake/android.toolchain.cmake \
      -DANDROID_ABI=arm64-v8a \
      -DANDROID_PLATFORM=android-21 \
      -DCNA_GRAPHICS_BACKEND=SDL_RENDERER
cmake --build build-android --target CNA

Android is genuinely wired through CMake - the NDK toolchain is handled and the sensor code links against android. Set ANDROID_NDK to your NDK path. There is no CMake preset and no CI job for Android, so this path is built and checked by hand. FFmpeg is unavailable here, so video playback is out.

Optional: use system-installed SDL

By default CNA builds SDL3 from the vendored submodules. If you prefer to link against system SDL3 packages, pass -DCNA_USE_SYSTEM_SDL=ON:

cmake -S . -B build -DCNA_USE_SYSTEM_SDL=ON -DCNA_GRAPHICS_BACKEND=SDL_RENDERER
cmake --build build --target CNA CnaTests

This calls find_package for SDL3, SDL3_image, and SDL3_mixer. The packages must be installed (e.g. via your distribution's package manager).

Running the tests

ctest --test-dir build --output-on-failure

The CnaTests binary holds 4,845 GoogleTest cases across 419 suites. On top of that, 648 backend integration and pixel tests are registered as CTest entries - but they are split unevenly across the 14 backends, and because backend choice is a compile-time decision, full coverage requires 14 separate configure + build + test runs.

⚠

The full CnaTests suite cannot be built on any Windows toolchain. Roughly 10 test files use the POSIX ::setenv(), which has no MSVC or MinGW equivalent in use here. Windows verification therefore runs the backend-level tests, not the whole unit suite.

Running the demos

# House 3D demo (EasyGL backend)
cmake --build build --target cna_house3d_demo
./build/cna_house3d_demo

# 2D demo
cmake --build build --target cna_demo_2d
./build/cna_demo_2d

There are 28 real demo programs under examples/ - the roughly 559 other .cpp files in that directory are pixel tests, not demos.

Be aware how thin the automated side of this is: only one of the project's three CI workflows triggers automatically.

The full unit suite and the GPU pixel suites are run locally, by hand - they are not gated by CI. See Platforms for the wider CI picture.

Requirements

  • C++23 (CMAKE_CXX_STANDARD 23) - this is a hard requirement, not a preference
  • CMake 3.20 or newer
  • ../sharp-runtime as a sibling directory, always
  • Backend-specific siblings and SDKs as listed in the backend table above

Troubleshooting

sharp-runtime not found

CNA requires sharp-runtime to be present as a sibling directory:

parent/
├── cna/
└── sharp-runtime/

Clone sharp-runtime next to CNA and re-run CMake configuration.

easy-gl not found (EASYGL backend)

The EASYGL backend requires easy-gl as a sibling directory (it in turn pulls in meta-gl). Clone it alongside CNA, or switch to another backend if you do not need OpenGL.

free-direct not found (DX3 backend)

The DX3 backend requires free-direct as a sibling directory - it is the DirectDraw subset the backend fronts. Clone it alongside CNA, or switch to SDL_RENDERER if you only need plain 2D.

Submodule directories empty

Run git submodule update --init --recursive from the repository root. If this fails, check your network and that the submodule URLs in .gitmodules are accessible.

Vulkan: no Vulkan device found

The Vulkan backend requires a Vulkan-capable GPU and driver. On Linux, install libvulkan-dev and ensure your GPU driver provides a Vulkan ICD (check with vulkaninfo). On virtual machines without GPU passthrough, Vulkan is generally not available.

EASYGL: OpenGL context creation failed

The EasyGL backend requires OpenGL ES 3.0 (or OpenGL 3.0+ desktop with ES emulation). On Linux, ensure your GPU driver is installed and your display server is running. On headless CI servers, use a software renderer such as LIBGL_ALWAYS_SOFTWARE=1 or Mesa's llvmpipe.

bgfx: FetchContent download fails

The BGFX backend fetches bgfx.cmake via CMake's FetchContent during configuration. This requires an internet connection. If you are behind a proxy, set the https_proxy environment variable before running CMake.

WebGPU: wgpu-native package not found

By default the WEBGPU backend downloads the pinned wgpu-native v29.0.1.1 package automatically at configure time, which requires an internet connection. For an offline or reproducible build, extract the official package yourself (it must contain include/webgpu.h and a libwgpu_native library under lib/) and pass -DCNA_WEBGPU_ROOT=/absolute/path -DCNA_WEBGPU_AUTO_DOWNLOAD=OFF.

D3D9 / D3D11 / D3D12: "requires CMAKE_SYSTEM_NAME=Windows"

All three Direct3D backends are hard-gated to a Windows target and fail fast on a native Linux or macOS configure. Cross-compile from Linux using -DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/mingw-w64.cmake, then run the resulting binaries through the Wine runners under scripts/ - Wine + DXVK for D3D9/D3D11, Wine + vkd3d-proton for D3D12. Alternatively build natively on Windows with MSVC, which is what the manual-dispatch d3d-windows-ci.yml workflow does for D3D11 and D3D12.

CANVAS: refuses to configure

The CANVAS backend is Emscripten-only. Configure it through emcmake cmake (or the web preset with an explicit backend override); it cannot be selected on any native target. Note also that it has zero automated pixel tests, so verify its output yourself.

CnaTests fails to build on Windows

Expected. Roughly 10 test files use the POSIX ::setenv(), so the full CnaTests suite does not build on any Windows toolchain. Build the library and the backend-level tests there instead, and run the full unit suite on Linux.

CNA
