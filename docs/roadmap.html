Detailed Roadmap

What has shipped, what is genuinely incomplete, and what nobody has started

On this page

  • Current state
  • Shipped
  • Remaining work
  • Toward a public stable release
  • Contributing to the roadmap
⚠

CNA is a long-term open-source project. There are no fixed release dates. Progress is incremental. This roadmap describes goals and current priorities, not commitments.

Current state

CNA is 236,708 lines of C++23 across 908 source files, with 2,738 commits — 2,183 of them in July 2026 alone. Essentially every public XNA 4.0 type is present (type presence ≈ 99%), but functional coverage is about 75%, weighted. Verification stands at 4,845 GoogleTest cases across 419 suites, 648 backend pixel/integration tests, and a 39-scene pixel-exact comparison against the real XNA 4.0 runtime.

Remaining work is therefore depth, not breadth. The list below is drawn from an audit of the source tree, not from a wish list.

Shipped

Rendering backends — 14 selectable

Selected at build time with -DCNA_GRAPHICS_BACKEND=<NAME>, one per binary, no runtime dispatch. Default is EASYGL on Linux and Emscripten, SDL_RENDERER elsewhere. Maturity tracks age closely: EasyGL, Vulkan, bgfx and SDL_Renderer date from April 2026; the other nine were created within roughly the last two weeks.

BackendStateNotes
EasyGLProduction-ready5,305 LOC, 239 CTests. 13 GLSL programs, all 9 effect families, per-vertex and per-pixel lighting, instancing, occlusion queries, anisotropy, fog, GL context-loss recovery. Only 4 unoverridden virtuals.
VulkanFunctional10,506 LOC, 138 CTests. 35 SPIR-V entry points, 8 effect paths, MRT proxy, device-queried depth formats, real stencil PSO, MSAA resolve, mip blit cascades.
D3D9Functional6,902 LOC, 19 CTests. Windows-only; 43 of 45 overrides real, 72 verified SM2/SM3 blobs, full device-lost and D3DPOOL_DEFAULT recovery, caps-validated MRT. Uniquely targets pixel-exact XNA 4.0 authenticity, and is the backend the oracle corpus is diffed against.
SDL_GPUFunctional6,683 LOC, 21 CTests. Deferred/retained design, 23 SPIR-V blobs, 9 effect families, stencil and MSAA resolve. Vulkan-only device today.
D3D11Functional4,521 LOC, 7 CTests. Windows-only; 5 state-object caches, MRT with deferred resolve, instancing, runtime D3DCompile.
SoftwareFunctional1,739 LOC, 6 CTests. A genuine CPU rasterizer: edge functions, a real Z-buffer, perspective-correct 1/w interpolation. TriangleList only, no GPU needed.
Dx3Functional1,178 LOC, 9 CTests. 2D only, DirectDraw-shaped, fronting the sibling free-direct project. Best 2D fidelity of any backend: a real CPU compositor, bilinear filtering, 4 distinct blend formulas, and real Wrap/Mirror addressing.
AsciiFunctional753 LOC, 6 CTests. 2D only; a thin decorator over SDL_Renderer that quantizes the frame to a glyph and colour grid. Two runtime modes via CNA_ASCII_MODE. SDL-windowed, not a TTY backend.
SDL_RendererProduction-ready within its 2D scope1,008 LOC, 68 CTests. The only backend whose capability reporting is fully truthful, with no silent no-ops; 3D calls throw by design.
CanvasMature but unverified1,177 LOC, 0 CTests. Emscripten-only, 11 EM_JS functions, careful un-premultiply and clip handling — and no automated test ever renders a Canvas pixel.
bgfxPartial4,367 LOC, 114 CTests. 108 shader blobs, but GL/GLES/Vulkan/WebGPU only.
D3D12Partial6,819 LOC, 1 CTest. Strong core (PSO and root-signature caches, barrier tracker) with real gaps listed below.
WebGPUExperimental7,110 LOC, 14 CTests. Backbuffer-only forward renderer.
HeadlessTest harness1,545 LOC, 7 CTests. Deliberately renders nothing; ReadBackbuffer returns the last clear colour. For fast CI of game logic.

Content and rendering features

  • The .xnb content pipeline. A real XNB reader, roughly 4,000 LOC, wired into ContentManager, with 49 registered type readers, a real 31 KB LZX decompressor, the full FNA ContentReader surface, two-pass shared-resource resolution, and fuzz-hardening — covered by 24 test files and 134 test cases against binary MonoGame fixtures. Earlier versions of this site said CNA could not read .xnb at all; that is no longer true.
  • Six XNA stock effects — BasicEffect, AlphaTestEffect, DualTextureEffect, EnvironmentMapEffect, SkinnedEffect, SpriteEffect — implemented natively in C++ rather than translated from bytecode.
  • PBR effects (NOXNA): PbrEffect and SkinnedPbrEffect, plus RenderPipelineSettings, PbrMaterial, TonemappingMode and ShadowQuality.
  • Skeletal animation (NOXNA): SkinnedModelEXT with AnimationPlayer, AnimationClipEXT, BoneTrackEXT and KeyframeEXT, plus MorphTargetEXT blend shapes.
  • cna_tool_gltf_to_cnj, an offline glTF 2.0 → .cnj Model/AnimationClip converter, built unconditionally. This is CNA's actual content path for models.

Verification infrastructure

  • The XNA 4.0 oracle corpus — 39 scenes under tools/xna-oracle/, rendered by a real C#/XNA reference renderer and diffed at --tolerance 0 against CNA's D3D9 output.
  • FNA differential testing against a real running FNA build, via tools/fna-reference/ and scripts/compare-fna-reference.py.
  • The NOXNA purity check — 1,289 tagged declarations, turned into [[deprecated]] warnings under -Werror so the XNA-only surface is proven to stand alone.

Remaining work

Every item below is a real, audited gap, ordered roughly by how much it costs a porting project.

ItemStateWhat it would take
Compiled .fx shader bytecode Not started The Effect(GraphicsDevice&, byte[]) constructor throws unconditionally, and there is no MojoShader equivalent. This is the single biggest barrier to porting an existing XNA game, and nothing else on this list comes close.
Surface formats other than Color Not started Texture::ValidateFormat throws for the other 25 formats, from both Texture2D constructors and from Texture3D and TextureCube. Until this changes there are no float, half or HDR render targets through the XNA API.
ReflectiveReader for custom XNB types Not started The 49 registered readers cover the stock types; no user-defined type can be loaded from an .xnb. C++ has no reflection, so this needs a design, not just an implementation. EnumReader, ExternalReferenceReader, VideoReader and a real EffectReader are missing alongside it, and the Array/List/Dictionary/Nullable readers exist but are unregistered.
D3D12: scissor, viewport, stencil, blend factor In progress The core is strong — PSO and root-signature caches, a barrier tracker — but these four state paths are absent and MRT clears without ever drawing. One CTest covers the whole backend.
WebGPU render targets In progress Today it is a backbuffer-only forward renderer: no render targets at all, no MSAA, no cube or 3D textures, no queries, no instancing, non-functional stencil.
bgfx D3D and Metal shader coverage In progress 108 shader blobs exist for GL, GLES, Vulkan and WebGPU only. On bgfx's default Windows and macOS renderers, 3D silently draws nothing. Also open on bgfx: CreateIndexBuffer32 is never overridden, so DrawUserIndexedPrimitives uploads 32-bit indices into a 16-bit buffer and corrupts geometry.
A GamerServices service backend Not started All 51 types are present with complete signatures and no backend of any kind — no Steam, no HTTP, no sqlite, not even filesystem persistence. Leaderboard I/O throws, Guide::ShowMessageBox throws, and GamerServicesDispatcher::Initialize() fabricates four gamers named "Stub Gamer".
The Media catalogue layer Not started 14 types — MediaLibrary, MediaSource, Album, Artist, Genre, Playlist, Picture, PictureAlbum and their 6 collections — throw on every member. MediaLibrary::SavePicture(string, Stream*) has no definition at all, making it a link error. Playback itself is real.
Tests for Media and Storage Not started Both namespaces have zero unit tests. Storage in particular is believed complete and correct, and nothing asserts on it. The Canvas backend is in the same position, with zero CTests.
Broader CI In progress Of three workflows, only input-ci.yml is auto-triggered, and it runs only the input-labelled tests. d3d-windows-ci.yml is manual dispatch only. There is no macOS, Android or Emscripten CI. The full CnaTests suite cannot build on any Windows toolchain, because roughly 10 files use POSIX ::setenv() — fixing that is a prerequisite for real Windows CI.
Truthful SupportsCapability() In progress The base returns true for everything and 8 of 14 backends never override it. WebGPU claims 5 capabilities it lacks, Software claims 6, and Ascii reports the inverse of the backend it wraps. Draw offsets (startIndex/baseVertex) are also ignored on D3D11.

Toward a public stable release

A versioned release that other projects can safely depend on is the long-term goal. Reaching it plausibly requires, at minimum:

  • Compiled .fx support, or an explicit and documented decision never to have it.
  • Surface formats beyond Color.
  • Test coverage for Media, Storage and the Canvas backend.
  • CI that gates the full unit suite on at least one platform.
  • An API stability guarantee, which is not something to offer while 2,183 commits land in a single month.

Contributing to the roadmap

The highest-value contributions right now are the unglamorous ones:

  • Writing the missing Media and Storage tests, and the first Canvas pixel test.
  • Closing the named backend gaps — D3D12 state paths, WebGPU render targets, bgfx D3D/Metal shaders and the 32-bit index buffer bug.
  • Making SupportsCapability() truthful, backend by backend.
  • Removing the POSIX ::setenv() dependency so the test suite can build on Windows.
  • Porting games to CNA to expose API gaps that an audit cannot find.

Open issues and TODO markers in the source are the best starting points. See the GitHub repository.

CNA

A modern C++ reimplementation of the XNA 4.0 API. Near-complete XNA 4.0 type coverage, verified by 4,845 unit tests and 648 backend pixel/integration tests across 14 selectable rendering backends.
