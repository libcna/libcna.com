CNA Demos

Runnable demonstrations of CNA capabilities across web, Android, and desktop platforms. CNA is a work in progress - demos reflect current state and will expand over time. Hosted browser builds are prebuilt binaries: the CNA revision each was compiled from is not recorded, so they demonstrate what CNA can do, not the behavior of the documented snapshot.

🚀

Fourteen web builds available now: CNA compiles to WebAssembly via Emscripten, and its WebGL 2 renderer (an EasyGL profile) is the Emscripten default. The demos below run directly in the browser from demos.libcna.com, and forty of the ported XNA samples are playable at samples.libcna.com. Android APKs and prebuilt Windows binaries are not published yet.

📚 cna-samples (GitHub)

C++ ports of the official XNA Game Studio 4.0 sample library — a concrete measure of how much real XNA code has been migrated. The repository’s own plan (cna-samples revision 4da98a0, 20 September 2026) inventories 153 upstream sample directories, of which 87 are marked complete — a native OpenGL ES 3 run plus a real-browser WebGL 2 run with no workaround — 49 await owner decisions (Windows Phone/Silverlight and WinForms apps, Avatar packs, XNA 2.0 archive samples, Visual Basic duplicates and similar), 14 are documented non-ports, and Racing Game is tracked separately. The counts belong to that pinned revision and to CNA next at that date; they are not a result for CNA snapshot 009d40f5 and not a universal runtime result across renderers.

ⓘ

Shader-driven samples are no longer blocked by .fx. An earlier revision of this page said that 23 samples could not build because CNA lacked compiled-shader support. That is no longer true: BloomSample, NormalMapping, PerPixelLighting, ShadowMapping, DistortionSample, ShatterEffect, NonPhotoRealistic, ColorReplacement, SkinningSample, CPUSkinning, CustomModelAnimation, CustomModelEffect, ShipGame and Spacewar are all marked complete, because the official Effect binaries produced by XNA’s own content build load through CNA’s compiled-effect path. What CNA still does not do is compile HLSL .fx source at run time; see Effects System. The remaining samples wait on owner decisions or are documented non-ports, not on a missing shader compiler.

🌐 Web Builds (Emscripten / WebGL 2)

CNA compiles to WebAssembly via Emscripten; the WEBGL2 renderer (an EasyGL profile, and the Emscripten default) runs on WebGL 2, and CNA also has Canvas, HTML DOM, SVG DOM and WebGPU renderers for the browser. Full 2D and 3D rendering work in the browser today. These are prebuilt binaries hosted at demos.libcna.com; each loads and responds to input when checked, but none is tied to a recorded CNA revision.

🖥 Desktop Builds

Desktop builds are the primary current delivery target. Linux binaries and Windows executables can be built from source following the build guide. Prebuilt binaries may be published with future releases. Clone CNA’s next branch, as the build guide explains.

Procedural 3D house scene with walls, roof, windows, door, and floor. Player movement with WASD + gravity. Uses EasyGL (OpenGL ES 3.0) renderer. Tests: 3D rendering, BasicEffect, keyboard input. Build with cmake --build build --target cna_house3d_demo.

GitHub Releases

🏃 Speedy Blupi - Port / Demo

Speedy Blupi, in its 2013 Windows Phone edition, has been decompiled, translated from C# to C++ and moved onto CNA by the OpenEggbert project (repository openeggbert/mobile-eggbert, MIT-licensed). It is a showcase of the framework's capability to support real game code, a practical test of CNA's API coverage and a demonstration of the XNA-style game loop in action. It is an independent consumer of CNA, not part of CNA or its test suite: every result below belongs to the CNA revision it was built with, not to snapshot 009d40f5.

Speedy Blupi - Desktop

Builds and runs on Linux (SDL_Renderer) from source, and Windows builds are documented (native, MinGW cross-build, and Direct3D 11/12 through Wine or Proton). No prebuilt binaries are published, and the repository lists open issues; follow the project on GitHub for updates.

Source on GitHub

Speedy Blupi - Web

Playable in the browser at speedyblupi.com, hosted by the OpenEggbert project as a WebAssembly build made with Emscripten. 🎮 cna-examples (GitHub)

A single browsable catalogue application that demonstrates CNA's own APIs area by area — rather than porting existing XNA samples, this is purpose-built teaching material. One executable (cna_examples) presents a Home → Area → Category → Demo menu you navigate at runtime, so you can step through the API surface without rebuilding. At revision ea33c9a29 (13 September 2026) 249 demo screens are registered across 13 areas and 79 categories, every one calling a real API rather than a mock. It builds against the OPENGLES3 renderer by default, though the renderer is overridable, and a hosted WebAssembly build is available above.

📝

Broad, with a catalogue checker. An earlier revision of this page described only two populated areas and no tests. Today every area has demos, tools/check_catalog.py keeps the table, plan and registrations in agreement, and the README reports all 249 screens rendering on both OPENGLES3 and SDL_RENDERER via a headless sweep. The count moves with the repository; run ./build/cna_examples --list-demos for the authoritative list.

Input — 52 screens

Keyboard, Mouse, Gamepad, Touch and a catch-all Other group (joysticks, host sensors, haptics, device enumeration and a cross-subsystem summary).

Audio — 12 screens

SoundEffect, SoundEffectInstance, 3D audio (AudioListener/AudioEmitter with Apply3D()), DynamicSoundEffectInstance, Microphone and XACT.

Graphics — 83 screens

40 in 2D Graphics and 43 in 3D Graphics, including self-checking screens that compute their own pass/fail for volume and cube textures.

Framework, Math, Content, Media, Devices, Net and more

Game loop and components, vectors and matrices, ContentManager with the XNB and CNJ formats, Song/Video/MediaLibrary, sensors and power, network sessions and leaderboards, storage, diagnostics and avatars — the remaining areas.
