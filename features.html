Features

What CNA offers

CNA provides a structured, incremental C++ implementation of the XNA 4.0 programming model. Below is a detailed overview of current and planned capabilities.

⚠

Measured against FNA, essentially every public XNA 4.0 type is now present in CNA — the only outright absences are five reflection-only ContentSerializer attributes that have no meaning in C++. Presence is not the same as behaviour, though, and CNA is honest about the split: Graphics, Input, Audio, Net, Storage and the math namespace are production-real, while Media's catalogue types and all of GamerServices are deliberate API-shaped no-ops that let XNA code compile. A real .xnb content pipeline now exists (49 type readers, genuine LZX decompression); you register the built-in readers once at startup. The biggest remaining gap is compiled .fx shader bytecode, which still throws — custom shaders must be hand-written GLSL/SPIR-V through ShaderEffect. A second real limit: only SurfaceFormat::Color textures can be constructed, so float/half/HDR render targets are unavailable despite the enum listing them. Verification is real: 4,845 unit tests and 648 backend pixel/integration tests across 14 selectable backends, plus differential testing against a running FNA build and a 39-scene oracle corpus diffed pixel-exactly against the real XNA 4.0 runtime. 63 of the 86 official XNA samples build on it. APIs are still evolving — good for research, demos and porting experiments, not yet for shipping a commercial game.

Core API

XNA 4.0 API Implementation

CNA mirrors the Microsoft::Xna::Framework namespace hierarchy, translating XNA's C# API into idiomatic C++23.

⚙
Implemented

Game Loop

The Game base class provides the full Initialize(), LoadContent(), Update(), Draw(), UnloadContent() lifecycle. GameTime, GameComponent, DrawableGameComponent, GameComponentCollection, GameWindow, and FrameworkDispatcher are all implemented.

🎨
Implemented

SpriteBatch

Full 2D rendering abstraction. Supports all SpriteSortMode values, transform matrix, custom Effect, blend and sampler states. DrawString with SpriteFont included. Backend-agnostic across all supported backends.

📷
Implemented

Texture2D

Full texture lifecycle: load from disk, GetData/SetData for all mip levels, SaveAsPng/SaveAsJpeg, pixel cache. RenderTarget2D is a proper subclass with FBO + depth renderbuffer (EasyGL) or off-screen Vulkan images.

Known gap: only SurfaceFormat::Color textures can be constructed. Texture::ValidateFormat throws for all 25 other formats, and it is called from both Texture2D constructors as well as Texture3D and TextureCube. DXT/DDS files load only by CPU-decompressing to RGBA, and float/half/HDR render targets are therefore unavailable despite the enum listing them.

💥
Implemented

GraphicsDevice

Full render state API: BlendState, DepthStencilState, RasterizerState, SamplerState, scissor rect, viewport, render targets. DrawPrimitives, DrawIndexedPrimitives, DrawUserIndexedPrimitives, DrawInstancedPrimitives (hardware-accelerated on the backends that support instancing), GetBackBufferData<Color> all implemented. GraphicsDevice exposes all 6 XNA events and all 5 Draw* families.

Cross-backend caveat: SupportsCapability() is not trustworthy — the base implementation returns true for everything and 7 of the 14 backends never override it. Draw offsets (startIndex/baseVertex) are ignored on D3D11, and on bgfx outside the wireframe path.

🏹
Implemented

Math Types

Complete math library: Vector2/3/4, Matrix, Quaternion, Color, Rectangle, Point, BoundingBox, BoundingSphere, BoundingFrustum, Plane, Ray, MathHelper, Curve, CurveKey. All operators, static factories, and interpolation methods. Matrix has all 30 statics including Decompose, billboards, shadow and reflection; Curve::Evaluate handles all 5 loop types; Color carries all 141 named constants. The one known gap in the core Framework namespace is BoundingFrustum::Intersects(Ray), which throws.

📊
Implemented

PackedVector Types

All 17 XNA 4.0 PackedVector types implemented in the Microsoft::Xna::Framework::Graphics::PackedVector namespace: Byte4, HalfSingle, HalfVector2/4, NormalizedByte2/4, NormalizedShort2/4, Rg32, Rgba1010102, Rgba64, Short2/4, Vector2/4. A correct IEEE 754 half-float codec is implemented from scratch, handling subnormals, infinities and NaN in both directions. Known gap: ToString() and GetHashCode() are missing on all 17.

🎮
Implemented

Input

The Input namespace has zero stubs. Keyboard exposes all ~145 Keys members; Mouse covers position, buttons and wheel; GamePad is a real SDL3 bridge (a 2,071-line implementation) with rumble, trigger rumble, LED control, hot-plug and per-device capability probing. TouchPanel genuinely detects all 10 XNA gesture types via a 474-line state machine with exponentially-smoothed flick velocity.

Known bug: TouchCollection reports IsReadOnly == true, but its mutators mutate instead of throwing.

🔋
Implemented (~85–90%)

Devices & Sensors

The Microsoft::Devices namespace talks to real hardware. Accelerometer and Gyroscope use the real SDL3 sensor API on Android, iOS and desktop with correct m/s²→g conversion and serious concurrency hardening. VibrateController really vibrates, via SDL_InitHapticRumble and a real SDL_HAPTIC_LEFTRIGHT effect, deliberately excluding gamepads. Compass and Motion are Android-only (an NDK fusion of 5 sensors) and honestly report NotSupported elsewhere. Covered by 356 unit tests.

Note: the CNA_DEVICES CMake option defaults to OFF, so this layer is not exercised by any current build or CI job.

🎵
Implemented (~92%)

Audio

Implemented (SDL3_mixer): SoundEffect, SoundEffectInstance (volume, pitch, pan, looping), DynamicSoundEffectInstance, MediaPlayer/Song.
XACT is a real parser and player, not a facade: a 1,115-line parser for the XGS/XWB/XSB binary formats behind AudioEngine, SoundBank, WaveBank and Cue, using FACT's actual volume formula and real RPC curves, with output through SDL3_mixer. 3D audio uses FAudio's exact Doppler and F3DAudio attenuation. 493 unit tests cover the namespace.

Known gaps: only the first PlayWave per track is honoured, XMA and WMA throw, and reverb is a no-op.

💾
Partial (~80%)

Content System & .xnb Pipeline

Extensible ContentManager with the ContentTypeReader<T> pattern, loading loose files directly: Texture2D (PNG/BMP/etc.), SpriteFont (.font.json), Model (.model.json), SoundEffect, Song, Video.

A real .xnb pipeline now exists (~4,000 LOC, 24 test files and 134 test cases against binary MonoGame fixtures). 49 XNB type readers are registered, covering all primitives, all math types, Texture2D/Texture3D/TextureCube, SpriteFont, SoundEffect, Song, the 5 stock effects and the model family. It ships a real 31 KB LZX decompressor, the full FNA ContentReader surface, two-pass shared-resource resolution, and fuzz hardening against malformed files. ContentManager prefers a .xnb when one exists, else falls back to loose files.

You must call CNA::Internal::Xnb::RegisterAllBuiltInXnbReaders() once at startup — a deliberate, documented design decision, but it does mean the registry is empty by default.

Known gaps: there is no ReflectiveReader, so custom user-defined types cannot be loaded from XNB at all; EnumReader, ExternalReferenceReader, VideoReader and a real EffectReader are missing (the last is registered as an always-throwing placeholder). The Array/List/Dictionary/Nullable readers are implemented but not registered, since without reflection each closed generic needs hand-registration. ResourceContentManager is a pure stub, and ContentManager::Unload() clears its maps without disposing assets.

🌐
Implemented (~87%)

Networking

The Net namespace (23 types) is real: genuine ENet over UDP, real LAN discovery via broadcast on port 61190 with measured RTT for QoS, and a two-process loopback test. Real transport is gated to SystemLink; PlayerMatch and Ranked correctly no-op because they require Xbox Live, and voice chat is a no-op by design. 174 unit tests.

🎮
Shape only — no backend

GamerServices & Avatar

All 51 GamerServices types are present with complete member signatures, but there is no backend of any kind — no Steam, no HTTP, no database, no filesystem persistence. It is a faithful port of FNA's no-op shim, so XNA code compiles and runs but nothing is ever persisted. Roughly 40% of the shape is meaningful; the service behind it is effectively 0%.

Concretely: 16 of the 17 Guide::Show* methods are empty bodies and all 3 ShowMessageBox entry points throw; ShowKeyboardInput displays nothing and EndShowKeyboardInput returns ""; GamerServicesDispatcher::Initialize() fabricates four gamers named "Stub Gamer"; every leaderboard I/O path throws; IsFriend() always returns false and GetFriends() returns empty. AvatarRenderer::Draw() validates 71 bones and then does nothing — the working renderer sits behind the NOXNA DrawRealEXT().

What is genuinely complete: all 16 enums, 6 exceptions, 3 EventArgs and the 4 collection types are real data structures with correct .NET exception semantics, covered by 311 unit tests.

3D Graphics

3D Rendering Pipeline

Eight of the 14 backends cover 2D and 3D. EasyGL is the most mature 3D path; Vulkan, D3D9, D3D11, SDL_GPU and the CPU Software rasterizer are functional, while bgfx, D3D12 and WebGPU have named 3D gaps.

🏠
Implemented (EasyGL)

3D Rendering

Four shader variants by vertex stride, depth test/write, blend, cull mode, matrix upload. Tested with the House 3D demo — procedural walls, roof, windows, door, floor with player movement and gravity. Also runs via WebGL 2 in the browser.

✨
Implemented

Effects System

All six XNA stock effects — BasicEffect, AlphaTestEffect, DualTextureEffect, EnvironmentMapEffect, SkinnedEffect, SpriteEffect — implemented natively in C++ rather than translated from bytecode. All IEffectMatrices, IEffectFog and IEffectLights interfaces, and EffectParameter with all Get/Set overloads.

The biggest porting gap in CNA: compiled .fx bytecode is not supported at all. Effect(GraphicsDevice&, byte[]) throws NotImplementedException unconditionally — there is no MojoShader equivalent — so games with custom HLSL effects cannot run. Custom shaders are reachable only through the NOXNA ShaderEffect, using hand-written GLSL or SPIR-V source.

✨
Implemented (NOXNA)

PBR & Skeletal Animation

Beyond the XNA stock set, CNA ships non-XNA effects and types: PbrEffect and SkinnedPbrEffect for physically based rendering, and a full skeletal-animation stack in SkinnedModelEXT with AnimationPlayer, AnimationClipEXT, BoneTrackEXT and KeyframeEXT. MorphTargetEXT adds blend shapes, alongside tangent and skinned vertex types and sRGB/BC7 surface formats. Render-pipeline settings (PbrMaterial, TonemappingMode, ShadowQuality) live in the CNA:: namespace.

Note: the CNA_NOXNA CMake option defaults to OFF, so this layer is not exercised by any current build or CI job.

📈
Implemented

Vertex & Index Buffers

VertexBuffer, DynamicVertexBuffer, IndexBuffer (16/32-bit), DynamicIndexBuffer. All four VertexPosition* types: VertexPositionColor, VertexPositionTexture, VertexPositionColorTexture, VertexPositionNormalTexture.

🌹
Implemented

Model System

Model::Draw with bone transforms, IEffectMatrices binding, and a full mesh/part rendering pipeline. Models load from .model.json descriptors or from .xnb via ContentManager. CNA's actual model content path is gltf_to_cnj, an offline glTF 2.0 → .cnj Model/AnimationClip converter that is built unconditionally.

🎦
Implemented

SpriteFont

Full glyph data model, MeasureString, and SpriteBatch::DrawString with three overloads. Fonts loaded from .font.json atlas descriptors.

🎬
Partial

Media & Video Playback

Real: MediaPlayer genuinely plays songs through SDL3_mixer, and VideoPlayer genuinely decodes video through FFmpeg (real libavcodec/libavformat/libswresample with PTS-driven pacing).

Known gaps: FFmpeg is unavailable on Emscripten, Android and every Windows target, so video playback is effectively native-Linux-only today. Separately, 14 Media types throw on every member — MediaLibrary, MediaSource, Album, Artist, Genre, Playlist, Picture, PictureAlbum and all 6 collections. That is the Zune/Windows-Phone media-catalogue API, not something a game normally touches, but it is a shim. Overall Media is around 33% functional, and there are zero test files for it.

💾
Implemented (100%)

Storage

All 3 Storage types are fully functional: real std::filesystem IO, a hand-written glob matcher, and correct <root>/<displayName>/Player{N} namespacing. The async Begin*/End* pairs are implemented synchronously, which is the correct choice for desktop. Caveat: zero unit tests cover this namespace.

🔀
Backend-dependent

Multisample Anti-Aliasing

Enabled via GraphicsDeviceManager: set PreferMultiSampling = true and MultiSampleCount on PresentationParameters before device creation. Real MSAA resolve is implemented on the Vulkan and SDL_GPU backends. The WebGPU and Software backends have no MSAA at all, and the 2D-only backends do not apply.

🔍
Implemented (EasyGL only)

OcclusionQuery

Hardware occlusion queries are implemented on EasyGL, which is the backend to use for GPU-driven visibility culling. They are not available on WebGPU, and the 2D-only backends (SDL_Renderer, Dx3, Ascii, Canvas) have no GPU query API at all.

⚡
Implemented (EasyGL, D3D9)

Context-Loss Recovery

GraphicsDevice exposes DeviceLost and DeviceReset events following the XNA pattern. EasyGL implements real GL context-loss recovery (relevant on Android and some desktop compositors), and D3D9 implements full device-lost and D3DPOOL_DEFAULT recovery. Other backends do not.

Platform

SDL3 Foundation

SDL3 is the cross-platform foundation for windowing, input, audio, and surface lifecycle. CNA vendors SDL3 as a Git submodule - no system SDL packages are required.

🖥
Implemented

Windowing & Events

SDL3 manages window creation, resizing, and the OS event loop. CNA wraps this through GameWindow and the Game run loop.

🎵
Implemented

SDL3_mixer Audio

SDL3_mixer, vendored as a submodule, is the audio output path for SoundEffect, MediaPlayer/Song and the XACT player. Microphone is wired to real SDL3 audio capture streams.

📷
Implemented

SDL3_image Loading

SDL3_image is used for loading PNG, JPG, and other texture formats into Texture2D. Vendored alongside SDL3.

Rendering

Pluggable Rendering Backends

CNA separates the game-facing API from the rendering implementation. A single CMake flag — -DCNA_GRAPHICS_BACKEND=<NAME> — selects the backend at build time; all game code remains unchanged. There are 14 selectable backends, and exactly one is compiled into a given build: there is no runtime dispatch and no runtime registry. The default is EASYGL on Linux and Emscripten, SDL_RENDERER elsewhere. The shared interface, IGraphicsBackend, has 132 virtual methods of which 59 are pure virtual.

⚠

Maturity varies enormously, and tracks age closely. EasyGL, Vulkan, bgfx and SDL_Renderer date from April 2026. The other ten backends were all created within roughly the last two weeks — treat them accordingly. Two further cross-backend caveats are worth knowing before you pick one: SupportsCapability() is unreliable (the base returns true for everything, 7 of 14 backends never override it, WebGPU claims 5 capabilities it lacks, Software claims 6, and Ascii reports the inverse of the backend it wraps); and because the backend choice is compile-time, full test coverage requires 14 separate configure/build/test runs.

💥
Production-ready (2D scope)

SDL_Renderer Backend

The most portable 2D backend, built on SDL3's own hardware-accelerated renderer. Notably, it is the only backend whose capability reporting is fully truthful — there are no silent no-ops, and 3D calls throw by design rather than quietly drawing nothing. 68 CTest entries. Selected with -DCNA_GRAPHICS_BACKEND=SDL_RENDERER.

🔸
Production-ready — most mature

EasyGL (OpenGL) Backend

CNA's most mature backend and the default on Linux and Emscripten. Shader-driven rendering through the easy-gl library: 13 GLSL programs covering all 9 effect families, per-vertex and per-pixel lighting, instancing, occlusion queries, anisotropic filtering, fog, and real GL context-loss recovery. Only 4 virtuals are left unoverridden, and it carries 239 CTest entries — more than any other backend. Selected with -DCNA_GRAPHICS_BACKEND=EASYGL.

🔷
Partial

bgfx Backend

Integration with the bgfx cross-platform graphics library, pulled in through CMake FetchContent. 4,367 LOC, 108 shader blobs and 114 CTest entries. Selected with -DCNA_GRAPHICS_BACKEND=BGFX.

Known gaps: shaders are built for GL/GLES/Vulkan/WebGPU only — no D3D or Metal, so 3D silently draws nothing on bgfx's default Windows and macOS renderers. DrawUserIndexedPrimitives corrupts geometry: the backend never overrides CreateIndexBuffer32, so 32-bit indices are uploaded into a 16-bit buffer (every other 3D backend implements this). Draw offsets are also ignored outside the wireframe path. Note too that bgfx.cmake is fetched at GIT_TAG master — the only unpinned dependency in the project.

🔸
Functional — near production

Vulkan Backend

The second-most mature backend after EasyGL, and the largest at 10,506 LOC with 138 CTest entries. 35 SPIR-V entry points across 8 effect paths, an MRT proxy, device-queried depth formats, a real stencil PSO, MSAA resolve, and mip blit cascades. Custom SPIR-V ShaderEffect and GetBackBufferData pixel readback both work. Selected with -DCNA_GRAPHICS_BACKEND=VULKAN.

Known gaps: see the Roadmap.

🖥
Functional — Windows-only

Direct3D 11 Backend

4,521 LOC, Windows-only (hard-gated at CMake configure time). 5 state-object caches, MRT with deferred resolve, instancing, and a runtime D3DCompile path for custom shaders. Verified both from Linux through Wine + DXVK on a real GPU and on real Windows via the manual native-MSVC CI workflow, which also checks 20 HLSL shaders against a genuine D3DCOMPILER_47.dll. Selected with -DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/mingw-w64.cmake -DCNA_GRAPHICS_BACKEND=D3D11.

Known gaps: draw offsets (startIndex/baseVertex) are ignored, SupportsCapability() is never overridden, and only 7 CTest entries cover it.

🖥
Partial — Windows-only

Direct3D 12 Backend

6,819 LOC with a strong core: PSO and root-signature caches, a barrier-transition tracker, and the same DXBC shader blobs shared with D3D9/D3D11. Verified from Linux through Wine + vkd3d-proton and on real Windows via the manual native-MSVC workflow. Selected with -DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/mingw-w64.cmake -DCNA_GRAPHICS_BACKEND=D3D12.

Known gaps: no scissor, no viewport, no stencil and no blend factor; MRT clears but never draws. SupportsCapability() is never overridden. Only 1 CTest entry covers this backend — the thinnest coverage of any backend that renders.

🌐
Experimental

WebGPU Backend

An experimental backend using native wgpu-native (pinned at v29.0.1.1). 7,110 LOC with a working 2D baseline and an early 3D draw path; 14 CTest entries. Selected with -DCNA_GRAPHICS_BACKEND=WEBGPU.

Known gaps: it is a backbuffer-only forward renderer — no render targets at all, no MSAA, no cube or 3D textures, no queries, no instancing, and non-functional stencil. It also claims 5 capabilities through SupportsCapability() that it does not actually have.

🧪
Test harness, not a renderer

Headless Backend

Renders nothing by design — no window, no GPU, no graphics API calls at all. 1,545 LOC of bookkeeping instead: argument validation, resource-lifecycle tracking and draw-call counters, for fast CI runs of game logic with no display server or GPU driver. Selected with -DCNA_GRAPHICS_BACKEND=HEADLESS.

Be aware: ReadBackbuffer simply returns the last clear colour and discards the x/y coordinates. It is not a pixel oracle.

🖥
Functional (narrow)

Software Backend

A genuine CPU rasterizer in 1,739 LOC: real edge functions, a real Z-buffer, and perspective-correct 1/w interpolation, all into a CPU-owned framebuffer — no GPU, window or display server involved. Useful for deterministic pixel tests on GPU-less machines. Selected with -DCNA_GRAPHICS_BACKEND=SOFTWARE.

Known gaps: TriangleList primitives only, no MSAA, and it claims 6 capabilities through SupportsCapability() that it does not have. Not a real-time backend by design.

🖥
Functional (upper) — Windows-only

Direct3D 9 Backend

6,902 LOC, Windows-only, and the backend that uniquely targets pixel-exact XNA 4.0 authenticity — it is the one diffed against the 39-scene XNA oracle corpus at zero tolerance. 43 of its 45 overrides are real, with 72 verified SM2/SM3 shader blobs, full device-lost and D3DPOOL_DEFAULT recovery, and caps-validated MRT. 19 CTest entries. Selected with -DCNA_GRAPHICS_BACKEND=D3D9.

Note: created 2026-07-14 — one of the newest backends. SupportsCapability() is not overridden.

💥
Functional

SDL_GPU Backend

6,683 LOC built on SDL3's GPU API, with a deferred/retained design: 23 SPIR-V blobs covering 9 effect families, real stencil support and MSAA resolve. 21 CTest entries. Selected with -DCNA_GRAPHICS_BACKEND=SDL_GPU.

Known gaps: it drives a Vulkan device only today, despite SDL_GPU's broader potential. SupportsCapability() is not overridden. Created 2026-07-15.

🔸
Functional — best 2D fidelity

Dx3 (DirectDraw) Backend

A DirectDraw-shaped 2D backend in 1,178 LOC, fronting the sibling free-direct library. Despite the name it is genuinely cross-platform. It has a real CPU compositor with bilinear filtering, 4 distinct blend formulas, and real Wrap/Mirror addressing — the last of which is a genuine win over SDL_Renderer. 9 CTest entries. Selected with -DCNA_GRAPHICS_BACKEND=DX3.

Scope: 2D only. Created 2026-07-15.

🖲
Functional

ASCII Backend

A thin 753-LOC decorator over SDL_Renderer that quantizes the finished frame to a glyph and colour grid, with two runtime modes selected by CNA_ASCII_MODE=BLACKWHITE|COLOR. 6 CTest entries. Selected with -DCNA_GRAPHICS_BACKEND=ASCII.

Note: this is an SDL-windowed backend, not a terminal/TTY renderer. Its SupportsCapability() reports the inverse of the backend it wraps. 2D only; created 2026-07-15.

🌐
Mature but narrow — unverified

Canvas Backend

An Emscripten-only 2D backend in 1,177 LOC, driving the browser's HTML canvas through 11 EM_JS functions with careful un-premultiply and clip handling. Selected with -DCNA_GRAPHICS_BACKEND=CANVAS.

Important caveat: it has zero CTest entries — no automated test ever renders a Canvas pixel. The code reads as careful, but nothing verifies it. Created 2026-07-15.

Platform Support

Cross-Platform Architecture

CNA's SDL3 foundation makes it possible to target multiple operating systems and hardware platforms from a single codebase.

🔗
Supported

Linux (x86_64)

The primary development platform, with EASYGL as the default backend, and the only platform with automatic CI. It is also the only target where FFmpeg video decoding is available.

🖥
Supported

Windows (x86_64)

Reached through a MinGW-w64 cross-toolchain as well as native MSVC. The D3D9, D3D11 and D3D12 backends are Windows-gated; they are verified from Linux through Wine + DXVK / vkd3d-proton on a real GPU, and D3D11/D3D12 are additionally verified on real Windows through a manual native-MSVC workflow.

Known gap: the full CnaTests suite cannot build on any Windows toolchain — roughly 10 files use POSIX ::setenv().

📱
Supported

Android

Genuinely wired through CMake and the Android NDK — sensors link against android, and Compass/Motion use a real NDK fusion of 5 sensors. Caveats: there is no Android CI and no CMake preset, and FFmpeg video is unavailable on this target.

🌐
Supported

Emscripten / Web

A real path, not an aspiration: a dedicated web CMake preset, an Emscripten SDL prebuilt tree, -sASYNCIFY/-sEXIT_RUNTIME test wiring, and the Emscripten-only CANVAS backend alongside EasyGL/WebGL 2. The House 3D Demo and CNA Demo are playable in the browser today. Caveats: no Emscripten CI, and FFmpeg video is excluded on this target.

🖥
Not supported

macOS / iOS

Stated plainly: macOS gets minimal handling only, and there are zero iOS references in the codebase. Neither is a supported target today, and neither has CI.

Technology

Modern C++23 Codebase

⚡

C++23 Standard

CNA targets C++23 throughout. Requires GCC 12+, Clang 15+, or MSVC 2022 v17.8+.

📦

CMake Build System

CMake 3.20+ with vendored SDL3/SDL3_image/SDL3_mixer as Git submodules. Backend selected with a single CMake flag.

🧪

Test Suite

GoogleTest unit suite (CnaTests): 4,845 test cases across 419 suites, in 287 test .cpp files. By area: Graphics 1,627, CNA internals 553, Audio 493, Devices/Sensors 356, GamerServices 311, Input 232, Net 174, Content 158, plus roughly 700 for the core math types. Separately, 648 backend integration and pixel tests run under ctest, and roughly 436 of 559 example programs (78%) perform real GPU→CPU readback with exact-match assertions at zero tolerance, plus 17 golden PNGs. A live EasyGL build tree registers 5,089 CTest entries in total. A compile-time NOXNA purity check turns every non-XNA-tagged declaration into a [[deprecated]] warning under -Werror. See Verification & Known Issues.

Real gaps: Media and Storage have zero unit tests, and the CANVAS backend has zero CTest entries.

⚙

Continuous Integration

Be aware that CI is thin. Of the three GitHub workflows, only input-ci.yml is auto-triggered: ubuntu-24.04 with gcc-14, a 5-way matrix (EasyGL, EasyGL with ASan/UBSan, SDL_Renderer, Vulkan, bgfx), running only the input-labelled tests. A devices workflow is path-filtered to Microsoft/Devices/**, and the Windows D3D11/D3D12 workflow is manual dispatch only. There is no macOS, Android or Emscripten CI, and the full unit suite and GPU pixel suites are run locally by hand rather than gated by CI.

🔧

sharp-runtime

A required sibling repo and a substantial project in its own right: a C++23 reimplementation of a .NET BCL subset at 135,204 LOC with roughly 12,375 test cases across 376 test files. It implements System::* broadly — primitives, Collections (Generic, Immutable, Concurrent, Frozen, Specialized, ObjectModel), IO (plus Compression, Hashing, IsolatedStorage), Text (including a full System.Text.Json and Regex), Net (Sockets, Http, WebSockets), Threading (plus Tasks and Channels), Xml (plus Linq and XPath), Globalization (10 calendars), Numerics (including BigInteger), Diagnostics and Buffers. Only 5 non-trivial files reference NotImplementedException. Security.Cryptography covers hashing only — no asymmetric crypto, TLS or X.509, by design.

CNA

A modern C++ reimplementation of the XNA 4.0 API. Near-complete XNA 4.0 type coverage, verified by 4,845 unit tests and 648 backend pixel/integration tests across 14 selectable rendering backends.
