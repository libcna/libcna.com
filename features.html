Features

What CNA offers

CNA provides a structured, incremental C++ implementation of the XNA 4.0 programming model. Below is a detailed overview of current and planned capabilities.

⚠

CNA implements 357 public types across the Microsoft.Xna.Framework namespaces. Every XNA 4.0 namespace is covered except Framework.Design, a Windows Forms designer namespace with no C++ equivalent. Presence is not the same as behaviour, so rather than publishing a blended coverage percentage CNA pins its public surface with compile-time signature-freeze tests and a CNA_STRICT_XNA_API purity mode that turns any use of a CNA extension into a compile error. Graphics, Input, Audio, Net, Storage, Media and the math namespace are real implementations; GamerServices is a real local implementation with genuine on-disk persistence but no online service. A read-side .xnb loader handles 50 built-in type readers with a hand-written LZX decompressor; you register them once at startup. glTF 2.0 models load at runtime straight through Content.Load<Model>(). The biggest remaining gap is compiled .fx shader bytecode, which still throws — custom shaders must be hand-written GLSL, SPIR-V or HLSL through ShaderEffect. A second real limit: Texture2D construction is restricted to SurfaceFormat::Color on every renderer except SKIA, so float/half/HDR textures are unavailable there despite the enum listing them. Verification is real: 6,818 GoogleTest cases across 433 test files, 1,621 registered renderer pixel/smoke tests, and a 39-scene oracle corpus captured from the real XNA 4.0 runtime, which DIRECTX9 matches pixel-exactly at zero tolerance. 63 of the 86 in-scope XNA samples are ported and building. APIs are still evolving — good for research, demos and porting experiments, not yet for shipping a commercial game.

Core API

XNA 4.0 API Implementation

CNA mirrors the Microsoft::Xna::Framework namespace hierarchy, translating XNA's C# API into idiomatic C++23.

⚙
Implemented

Game Loop

The Game base class provides the full Initialize(), LoadContent(), Update(), Draw(), UnloadContent() lifecycle. GameTime, GameComponent, DrawableGameComponent, GameComponentCollection, GameWindow, and FrameworkDispatcher are all implemented.

🎨
Implemented

SpriteBatch

Full 2D rendering abstraction. Supports all SpriteSortMode values, transform matrix, custom Effect, blend and sampler states. DrawString with SpriteFont included. Renderer-agnostic across every renderer that supports 2D.

📷
Implemented

Texture2D

Full texture lifecycle: load from disk, GetData/SetData for all mip levels, SaveAsPng/SaveAsJpeg, pixel cache. RenderTarget2D is a proper subclass with FBO + depth renderbuffer (EasyGL) or off-screen Vulkan images.

Known gap: on every renderer except SKIA, only SurfaceFormat::Color textures can be constructed — Texture::ValidateFormat throws for the other formats, and it guards both Texture2D constructors as well as Texture3D and TextureCube. DXT/DDS files load only by CPU-decompressing to RGBA, so float/half/HDR textures are unavailable there despite the enum listing them. SKIA has passed a promotion gate for the packed, float, normalized and DXT/BC7 formats.

💥
Implemented

GraphicsDevice

Full render state API: BlendState, DepthStencilState, RasterizerState, SamplerState, scissor rect, viewport, render targets. DrawPrimitives, DrawIndexedPrimitives, DrawUserIndexedPrimitives, DrawInstancedPrimitives (hardware-accelerated on the renderers that support instancing), GetBackBufferData<Color> all implemented. GraphicsDevice exposes all 6 XNA events and all 5 Draw* families.

Cross-renderer caveat: SupportsCapability() fails open — the base implementation returns true for every capability except multi-stream vertex input, and DIRECTX9, DIRECTX11, DIRECTX12 and SDL_GPU never override it at all. Treat a true as "not contradicted", not as evidence. Test the feature you actually depend on.

🏹
Implemented

Math Types

Complete math library: Vector2/3/4, Matrix, Quaternion, Color, Rectangle, Point, BoundingBox, BoundingSphere, BoundingFrustum, Plane, Ray, MathHelper, Curve, CurveKey. All operators, static factories, and interpolation methods. Matrix has all 30 statics including Decompose, billboards, shadow and reflection; Curve::Evaluate handles all 5 loop types; Color carries all 141 named constants. The one known gap in the core Framework namespace is BoundingFrustum::Intersects(Ray), which throws.

📊
Implemented

PackedVector Types

All 17 XNA 4.0 PackedVector types implemented in the Microsoft::Xna::Framework::Graphics::PackedVector namespace: Byte4, HalfSingle, HalfVector2/4, NormalizedByte2/4, NormalizedShort2/4, Rg32, Rgba1010102, Rgba64, Short2/4, Vector2/4. A correct IEEE 754 half-float codec is implemented from scratch, handling subnormals, infinities and NaN in both directions. Known gap: ToString() and GetHashCode() are missing on all 17.

🎮
Implemented

Input

The Input namespace has zero stubs. Keyboard exposes all ~145 Keys members; Mouse covers position, buttons and wheel; GamePad is a real SDL3 bridge with rumble, trigger rumble, LED control, hot-plug and per-device capability probing. TouchPanel genuinely detects all 10 XNA gesture types via a 474-line state machine with exponentially-smoothed flick velocity.

Known bug: TouchCollection reports IsReadOnly == true, but its mutators mutate instead of throwing.

🔋
Implemented (~85–90%)

Devices & Sensors

The Microsoft::Devices namespace talks to real hardware. Accelerometer and Gyroscope use the real SDL3 sensor API on Android, iOS and desktop with correct m/s²→g conversion and serious concurrency hardening. VibrateController really vibrates, via SDL_InitHapticRumble and a real SDL_HAPTIC_LEFTRIGHT effect, deliberately excluding gamepads. Compass and Motion are Android-only (an NDK fusion of 5 sensors) and honestly report NotSupported elsewhere. Covered by 356 unit tests.

Note: the CNA_DEVICES CMake option defaults to OFF, so this layer is not exercised by any current build or CI job.

🎵
Implemented (~92%)

Audio

Implemented (SDL3_mixer): SoundEffect, SoundEffectInstance (volume, pitch, pan, looping), DynamicSoundEffectInstance, MediaPlayer/Song.
XACT is a real parser and player, not a facade: a real binary parser for the XGS/XWB/XSB formats behind AudioEngine, SoundBank, WaveBank and Cue, using FACT's actual volume formula and real RPC curves, with output through SDL3_mixer. 3D audio uses FAudio's exact Doppler and F3DAudio attenuation. 493 unit tests cover the namespace.

Known gaps: only the first PlayWave per track is honoured; XMA and WMA wave-bank entries are not decoded — they log a diagnostic and yield a null sound rather than throwing, so the effect is silently missing; and reverb is a deliberate no-op because SDL3_mixer has no aux-send bus. .m4a/.aac are unplayable for the same reason.

💾
Partial (~80%)

Content System & .xnb Pipeline

Extensible ContentManager with the ContentTypeReader<T> pattern, loading loose files directly: Texture2D (PNG/BMP/etc.), SoundEffect (WAV), Song, Video, plus SpriteFont, Model and Effect from CNA's single .cnj JSON descriptor format.

A real .xnb pipeline now exists (~4,000 LOC, 24 test files and 134 test cases against binary MonoGame fixtures). 50 XNB type readers are registered, covering all primitives, all math types, Texture2D/Texture3D/TextureCube, SpriteFont, SoundEffect, Song, the 5 stock effects and the model family. It ships a real 31 KB LZX decompressor, the full FNA ContentReader surface, two-pass shared-resource resolution, and fuzz hardening against malformed files. ContentManager prefers a .xnb when one exists, else falls back to loose files.

You must call CNA::Internal::Xnb::RegisterAllBuiltInXnbReaders() once at startup — a deliberate, documented design decision, but it does mean the registry is empty by default.

Known gaps: there is no ReflectiveReader, so custom user-defined types cannot be loaded from XNB at all; EnumReader, ExternalReferenceReader, VideoReader and a real EffectReader are missing (the last is registered as an always-throwing placeholder). The Array/List/Dictionary/Nullable readers are implemented but not registered, since without reflection each closed generic needs hand-registration. ResourceContentManager is a pure stub, and ContentManager::Unload() clears its maps without disposing assets.

🌐
Implemented (~87%)

Networking

The Net namespace (23 types) is real: genuine ENet over UDP, real LAN discovery via broadcast on port 61190 with measured RTT for QoS, and a two-process loopback test. Real transport is gated to SystemLink; PlayerMatch and Ranked correctly no-op because they require Xbox Live, and voice chat is a no-op by design. 174 unit tests.

🎮
Real local implementation — no online service

GamerServices & Avatar

All 52 GamerServices types are present with complete member signatures. There is no online service behind them — no Steam, no Xbox Live, no HTTP — but, unlike FNA's no-op shim, CNA backs them with a real local implementation that genuinely persists to disk. Achievements and leaderboard entries are written as JSON under SDL_GetPrefPath() using an atomic temp-file-and-rename, and they reload correctly in a later process.

Concretely: LeaderboardWriter and LeaderboardReader are real, with rating-descending sort, 1-based ranks, pivot centring and paging. Guide::BeginShowMessageBox/EndShowMessageBox and BeginShowKeyboardInput/EndShowKeyboardInput are complete CNA-original implementations, including SpriteBatch overlay rendering, password masking and real mouse hit-testing. What genuinely does nothing: fifteen Guide::Show* entry points (gamer card, marketplace, party, players, sign-in, messages and friends UI) are documented no-ops, and AvatarRenderer::Draw() validates its bones and then deliberately does nothing — faithful to the XNA reference assembly. The working avatar renderer sits behind the CNAEXT DrawRealEXT(), which does real GPU skinning of a 19-bone rig and is covered by pixel-readback tests.

What is genuinely complete: all 16 enums, 6 exceptions, 3 EventArgs and the 4 collection types are real data structures with correct .NET exception semantics, covered by 311 unit tests.

3D Graphics

3D Rendering Pipeline

Most of the 46 renderers implement the full 2D + 3D pipeline; eleven are deliberately 2D-only and refuse 3D calls deterministically rather than silently doing nothing. The GL family, Vulkan, the Direct3D renderers, SDL_GPU and the CPU Software rasterizer are the best-exercised 3D paths.

🏠
Implemented (EasyGL)

3D Rendering

Four shader variants by vertex stride, depth test/write, blend, cull mode, matrix upload. Tested with the House 3D demo — procedural walls, roof, windows, door, floor with player movement and gravity. Also runs via WebGL 2 in the browser.

✨
Implemented

Effects System

All six XNA stock effects — BasicEffect, AlphaTestEffect, DualTextureEffect, EnvironmentMapEffect, SkinnedEffect, SpriteEffect — implemented natively in C++ rather than translated from bytecode. All IEffectMatrices, IEffectFog and IEffectLights interfaces, and EffectParameter with all Get/Set overloads.

The biggest porting gap in CNA: compiled .fx bytecode is not supported at all. Effect(GraphicsDevice&, byte[]) throws NotImplementedException unconditionally — there is no MojoShader equivalent — so games with custom HLSL effects cannot run. Custom shaders are reachable only through the CNAEXT ShaderEffect, using hand-written GLSL or SPIR-V source.

✨
Implemented (CNAEXT)

PBR & Skeletal Animation

Beyond the XNA stock set, CNA ships non-XNA effects and types: PbrEffect and SkinnedPbrEffect for physically based rendering, and a full skeletal-animation stack in SkinnedModelEXT with AnimationPlayer, AnimationClipEXT, BoneTrackEXT and KeyframeEXT. MorphTargetEXT adds blend shapes, alongside tangent and skinned vertex types and sRGB/BC7 surface formats. Render-pipeline settings (PbrMaterial, TonemappingMode, ShadowQuality) live in the CNA:: namespace.

Note: the CNA_CNAEXT CMake option defaults to OFF, so this layer is not exercised by any current build or CI job.

📈
Implemented

Vertex & Index Buffers

VertexBuffer, DynamicVertexBuffer, IndexBuffer (16/32-bit), DynamicIndexBuffer. All four VertexPosition* types: VertexPositionColor, VertexPositionTexture, VertexPositionColorTexture, VertexPositionNormalTexture.

🌹
Implemented

Model System

Model::Draw with bone transforms, IEffectMatrices binding, and a full mesh/part rendering pipeline. Models load from .cnj descriptors, from .gltf/.glb directly, or from .xnb via ContentManager. CNA's actual model content path is gltf_to_cnj, an offline glTF 2.0 → .cnj Model/AnimationClip converter that is built unconditionally.

🎦
Implemented

SpriteFont

Full glyph data model, MeasureString, and SpriteBatch::DrawString with three overloads. Fonts loaded from .cnj descriptors naming a pre-rendered glyph atlas.

🎬
Partial

Media & Video Playback

Real: MediaPlayer genuinely plays songs through SDL3_mixer and exposes a real FFT spectrum and waveform via GetVisualizationData, captured from the live post-mix callback. VideoPlayer genuinely decodes video through FFmpeg (real libavcodec/libavformat/libswresample with PTS-driven pacing), plays the video's own audio track, and supports multi-track selection. The MediaLibrary catalogue is also real: it resolves your actual Music and Pictures folders through SDL_GetUserFolder, scans them recursively, parses ID3v2, Vorbis-comment, Opus and FLAC tags, probes durations, discovers album art, reads playlists and saves pictures to disk.

Known gaps: the three video translation units are excluded from the build entirely on Windows, Emscripten and Android — the headers still exist, so code calling Video or VideoPlayer compiles and then fails to link. Video playback is therefore native Linux/macOS only today. Note also that FFmpeg is a hard requirement on Linux and macOS, not an optional codec extra: CMake configuration fails without the libavcodec, libavformat, libavutil and libswresample development packages. Unrecognised video pixel formats render magenta rather than raising an error.

💾
Implemented (100%)

Storage

All 3 Storage types are fully functional: real std::filesystem IO, a hand-written glob matcher, and correct <root>/<displayName>/Player{N} namespacing. The async Begin*/End* pairs are implemented synchronously, which is the correct choice for desktop. Caveat: zero unit tests cover this namespace.

🔀
Renderer-dependent

Multisample Anti-Aliasing

Enabled via GraphicsDeviceManager: set PreferMultiSampling = true and MultiSampleCount on PresentationParameters before device creation. Real MSAA resolve is implemented on the Vulkan and SDL_GPU renderers. The WebGPU and Software renderers have no MSAA at all, and the 2D-only renderers do not apply.

🔍
Implemented (EasyGL only)

OcclusionQuery

Hardware occlusion queries are implemented on EasyGL, which is the renderer to use for GPU-driven visibility culling. They are not available on WebGPU, and the 2D-only renderers (SDL_Renderer, Direct2D, Canvas, HTML_DOM, Skia, Blend2D, FreeDirect, GDI, SVG_DOM and OpenVG) have no GPU query API at all.

⚡
Implemented (EasyGL, DIRECTX9)

Context-Loss Recovery

GraphicsDevice exposes DeviceLost and DeviceReset events following the XNA pattern. EasyGL implements real GL context-loss recovery (relevant on Android and some desktop compositors), and DIRECTX9 implements full device-lost and D3DPOOL_DEFAULT recovery. Other renderers do not.

Platform

SDL3 Foundation

SDL3 is the cross-platform foundation for windowing, input, audio, and surface lifecycle. CNA vendors SDL3 as a Git submodule - no system SDL packages are required.

🖥
Implemented

Windowing & Events

SDL3 manages window creation, resizing, and the OS event loop. CNA wraps this through GameWindow and the Game run loop.

🎵
Implemented

SDL3_mixer Audio

SDL3_mixer, vendored as a submodule, is the audio output path for SoundEffect, MediaPlayer/Song and the XACT player. Microphone is wired to real SDL3 audio capture streams.

📷
Implemented

SDL3_image Loading

SDL3_image is used for loading PNG, JPG, and other texture formats into Texture2D. Vendored alongside SDL3.

Rendering

Pluggable Renderers

CNA separates the game-facing API from the rendering implementation. A single CMake flag — -DCNA_GRAPHICS_RENDERER=<NAME> — selects the renderer at build time; all game code remains unchanged. There are 46 selectable renderers, and exactly one is compiled into a given build: there is no runtime dispatch and no runtime registry. The default is OPENGLES3 on Linux, WEBGL2 under Emscripten and SDL_RENDERER elsewhere. They share one interface family headed by IGraphicsRenderer, alongside ISpriteBatchRenderer, ITextureRenderer, IEffectRenderer and their siblings.

⚠

46 renderer identities is not 46 equally complete renderers. They range from fully pixel-verified 2D+3D paths through eleven deliberately 2D-only renderers that throw on every 3D call, to renderers that never present to a window at all (HEADLESS, STUB) and openly experimental ones (LLGL, WEBGPU, WICKED, SOKOL). Two cross-renderer caveats are worth knowing before you pick one: SupportsCapability() fails open — the base implementation returns true for everything except multi-stream vertex input, and DIRECTX9, DIRECTX11, DIRECTX12 and SDL_GPU never override it at all, so a true is not evidence; and because the choice is compile-time, exercising every renderer means a separate configure/build/test run for each.

💥
Production-ready (2D scope)

SDL_Renderer Renderer

The most portable 2D renderer, built on SDL3's own hardware-accelerated renderer. 3D calls throw by design rather than quietly drawing nothing, and its capability reporting is written to match what it can actually do. Selected with -DCNA_GRAPHICS_RENDERER=SDL_RENDERER.

🔸
Production-ready — most mature

EasyGL (OpenGL) Renderer

CNA's most mature renderer family and the default on Linux (as OPENGLES3) and under Emscripten (as WEBGL2). Shader-driven rendering through the easy-gl library: 13 GLSL programs covering all 9 effect families, per-vertex and per-pixel lighting, instancing, occlusion queries, anisotropic filtering, fog, and real GL context-loss recovery. Only 4 virtuals are left unoverridden, and it carries 239 CTest entries — more than any other renderer. Selected with -DCNA_GRAPHICS_RENDERER=OPENGLES3.

🔷
Partial

bgfx Renderer

Integration with the bgfx cross-platform graphics library, pulled in through CMake FetchContent. 4,367 LOC, 108 shader blobs and 114 CTest entries. Selected with -DCNA_GRAPHICS_RENDERER=BGFX.

Known gaps: shaders are built for GL/GLES/Vulkan/WebGPU only — no D3D or Metal, so 3D silently draws nothing on bgfx's default Windows and macOS renderers. DrawUserIndexedPrimitives corrupts geometry: the renderer never overrides CreateIndexBuffer32, so 32-bit indices are uploaded into a 16-bit buffer (every other 3D renderer implements this). Draw offsets are also ignored outside the wireframe path. Note too that bgfx.cmake is fetched at GIT_TAG master — the only unpinned dependency in the project.

🔸
Functional — near production

Vulkan Renderer

The second-most mature renderer after EasyGL, and the largest at 10,506 LOC with 138 CTest entries. 35 SPIR-V entry points across 8 effect paths, an MRT proxy, device-queried depth formats, a real stencil PSO, MSAA resolve, and mip blit cascades. Custom SPIR-V ShaderEffect and GetBackBufferData pixel readback both work. Selected with -DCNA_GRAPHICS_RENDERER=VULKAN.

Known gaps: see the Roadmap.

🖥
Functional — Windows-only

Direct3D 11 Renderer

4,521 LOC, Windows-only (hard-gated at CMake configure time). 5 state-object caches, MRT with deferred resolve, instancing, and a runtime D3DCompile path for custom shaders. Verified both from Linux through Wine + DXVK on a real GPU and on real Windows via the manual native-MSVC CI workflow, which also checks 20 HLSL shaders against a genuine D3DCOMPILER_47.dll. Selected with -DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/mingw-w64.cmake -DCNA_GRAPHICS_RENDERER=DIRECTX11.

Known gaps: draw offsets (startIndex/baseVertex) are ignored, SupportsCapability() is never overridden, and only 7 CTest entries cover it.

🖥
Partial — Windows-only

Direct3D 12 Renderer

6,819 LOC with a strong core: PSO and root-signature caches, a barrier-transition tracker, and the same DXBC shader blobs shared with DIRECTX9/DIRECTX11. Verified from Linux through Wine + vkd3d-proton and on real Windows via the manual native-MSVC workflow. Selected with -DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/mingw-w64.cmake -DCNA_GRAPHICS_RENDERER=DIRECTX12.

Known gaps: no scissor, no viewport, no stencil and no blend factor; MRT clears but never draws. SupportsCapability() is never overridden. Only 1 CTest entry covers this renderer — the thinnest coverage of any renderer that renders.

🌐
Experimental

WebGPU Renderer

An experimental renderer using native wgpu-native (pinned at v29.0.1.1). 7,110 LOC with a working 2D baseline and an early 3D draw path; 14 CTest entries. Selected with -DCNA_GRAPHICS_RENDERER=WEBGPU.

Known gaps: it is a backbuffer-only forward renderer — no render targets at all, no MSAA, no cube or 3D textures, no queries, no instancing, and non-functional stencil. It also claims 5 capabilities through SupportsCapability() that it does not actually have.

🧪
Test harness, not a renderer

Headless Renderer

Renders nothing by design — no window, no GPU, no graphics API calls at all. 1,545 LOC of bookkeeping instead: argument validation, resource-lifecycle tracking and draw-call counters, for fast CI runs of game logic with no display server or GPU driver. Selected with -DCNA_GRAPHICS_RENDERER=HEADLESS.

Be aware: ReadBackbuffer simply returns the last clear colour and discards the x/y coordinates. It is not a pixel oracle.

🖥
Functional (narrow)

Software Renderer

A genuine CPU rasterizer in 1,739 LOC: real edge functions, a real Z-buffer, and perspective-correct 1/w interpolation, all into a CPU-owned framebuffer — no GPU, window or display server involved. Useful for deterministic pixel tests on GPU-less machines. Selected with -DCNA_GRAPHICS_RENDERER=SOFTWARE.

Known gaps: TriangleList primitives only, no MSAA, and it claims 6 capabilities through SupportsCapability() that it does not have. Not a real-time renderer by design.

🖥
Functional (upper) — Windows-only

Direct3D 9 Renderer

6,902 LOC, Windows-only, and the renderer that uniquely targets pixel-exact XNA 4.0 authenticity — it is the one diffed against the 39-scene XNA oracle corpus at zero tolerance. 43 of its 45 overrides are real, with 72 verified SM2/SM3 shader blobs, full device-lost and D3DPOOL_DEFAULT recovery, and caps-validated MRT. 19 CTest entries. Selected with -DCNA_GRAPHICS_RENDERER=DIRECTX9.

Note: created 2026-07-14 — one of the newest renderers. SupportsCapability() is not overridden.

💥
Functional

SDL_GPU Renderer

6,683 LOC built on SDL3's GPU API, with a deferred/retained design: 23 SPIR-V blobs covering 9 effect families, real stencil support and MSAA resolve. 21 CTest entries. Selected with -DCNA_GRAPHICS_RENDERER=SDL_GPU.

Known gaps: it drives a Vulkan device only today, despite SDL_GPU's broader potential. SupportsCapability() is not overridden. Created 2026-07-15.

🔸
Functional — best 2D fidelity

FreeDirect (DirectDraw) Renderer

A DirectDraw-shaped 2D renderer in 1,178 LOC, fronting the sibling free-direct library. Despite the name it is genuinely cross-platform. It has a real CPU compositor with bilinear filtering, 4 distinct blend formulas, and real Wrap/Mirror addressing — the last of which is a genuine win over SDL_Renderer. 9 CTest entries. Selected with -DCNA_GRAPHICS_RENDERER=FREEDIRECT.

Scope: 2D only. Created 2026-07-15.

🖲
Functional

ASCII post-process effect

Quantizes any Texture2D or RenderTarget2D into a glyph and colour grid. This used to be a renderer; it is now a CNAEXT post-process effect, CNA::Graphics::AsciiPostProcessEffect, which is a strictly better arrangement: because it works through the public Texture2D::GetData() and SpriteBatch API rather than a renderer-internal type, it now runs on any renderer, including 3D-rendered sources. The old renderer could only quantize its own 2D SDL frame.

Note: it is deliberately not an XNA Effect subclass — it performs its own multi-step CPU readback and re-upload, so it costs a GPU→CPU readback per draw. Requires -DCNA_CNAEXT=ON. It is not a terminal/TTY renderer; no such renderer exists.

🌐
Mature but narrow — unverified

Canvas Renderer

An Emscripten-only 2D renderer in 1,177 LOC, driving the browser's HTML canvas through 11 EM_JS functions with careful un-premultiply and clip handling. Selected with -DCNA_GRAPHICS_RENDERER=CANVAS.

Important caveat: it has zero CTest entries — no automated test ever renders a Canvas pixel. The code reads as careful, but nothing verifies it. Created 2026-07-15.

Platform Support

Cross-Platform Architecture

CNA's SDL3 foundation makes it possible to target multiple operating systems and hardware platforms from a single codebase.

🔗
Supported

Linux (x86_64)

The primary development platform, with OPENGLES3 as the default renderer and the broadest CI coverage. macOS also has an automatic CI job of its own for the METAL renderer. FFmpeg video decoding is available on Linux and macOS, but not on Windows, Emscripten or Android.

🖥
Supported

Windows (x86_64)

Reached through a MinGW-w64 cross-toolchain as well as native MSVC. The DIRECTX9, DIRECTX11 and DIRECTX12 renderers are Windows-gated; they are verified from Linux through Wine + DXVK / vkd3d-proton on a real GPU, and DIRECTX11/DIRECTX12 are additionally verified on real Windows through a manual native-MSVC workflow.

Known gap: the full CnaTests suite cannot build on any Windows toolchain — roughly 10 files use POSIX ::setenv().

📱
Supported

Android

Genuinely wired through CMake and the Android NDK — sensors link against android, and Compass/Motion use a real NDK fusion of 5 sensors. Caveats: there is no Android CI and no CMake preset, and FFmpeg video is unavailable on this target.

🌐
Supported

Emscripten / Web

A real path, not an aspiration: a dedicated web CMake preset, an Emscripten SDL prebuilt tree, -sASYNCIFY/-sEXIT_RUNTIME test wiring, and the Emscripten-only CANVAS renderer alongside EasyGL/WebGL 2. The House 3D Demo and CNA Demo are playable in the browser today. Caveats: no Emscripten CI, and FFmpeg video is excluded on this target.

🖥
Not supported

macOS / iOS

Stated plainly: macOS gets minimal handling only, and there are zero iOS references in the codebase. Neither is a supported target today, and neither has CI.

Technology

Modern C++23 Codebase

⚡

C++23 Standard

CNA targets C++23 throughout. Requires GCC 12+, Clang 15+, or MSVC 2022 v17.8+.

📦

CMake Build System

CMake 3.20+ with vendored SDL3/SDL3_image/SDL3_mixer as Git submodules. Renderer selected with a single CMake flag.

🧪

Test Suite

GoogleTest unit suite (CnaTests): 6,818 GoogleTest case definitions across 433 test files, in 287 test .cpp files. By area: Graphics 1,627, CNA internals 553, Audio 493, Devices/Sensors 356, GamerServices 311, Input 232, Net 174, Content 158, plus roughly 700 for the core math types. Separately, 1,621 registered renderer pixel/smoke tests run under ctest, and roughly 436 of 559 example programs (78%) perform real GPU→CPU readback with exact-match assertions at zero tolerance, plus 17 golden PNGs. A compile-time CNAEXT purity check turns every non-XNA-tagged declaration into a [[deprecated]] warning under -Werror. See Verification & Known Issues.

Real gaps: Media and Storage have zero unit tests, and the CANVAS renderer has zero CTest entries.

⚙

Continuous Integration

Be aware that CI, while broader than it once was, is still thin relative to the project's surface. There are eight GitHub workflows: six trigger automatically on push/pull-request (a general test job, input tests, devices and sensors, 32-bit arithmetic, HTML_DOM headless-browser tests, and a macOS/Metal build), and the two Windows MSVC workflows are manual dispatch only. Several of the automatic ones are filtered to master/main and so stay dormant on the develop default branch. Roughly three-quarters of the 46 renderers have no CI coverage at all, there is no Android or Emscripten-build CI, and neither the full unit suite nor the GPU pixel suites are gated by CI — they are run locally.

sharp-runtime

A required sibling repo and a substantial project in its own right: a C++23 reimplementation of a .NET BCL subset at roughly 158,000 lines across 41 selectable modules, with over 14,000 tests. It implements System::* broadly — primitives, Collections (Generic, Immutable, Concurrent, Frozen, Specialized, ObjectModel), IO (plus Compression, Hashing, IsolatedStorage), Text (including a full System.Text.Json and Regex), Net (Sockets, Http, WebSockets), Threading (plus Tasks and Channels), Xml (plus Linq and XPath), Globalization (10 calendars), Numerics (including BigInteger), Diagnostics and Buffers. Only 5 non-trivial files reference NotImplementedException. Security.Cryptography covers hashing only — no asymmetric crypto, TLS or X.509, by design.

CNA

A modern C++ reimplementation of the XNA 4.0 API. 357 public XNA 4.0 types across 46 build-time selectable renderers, with 6,818 GoogleTest case definitions and a 39-scene XNA oracle corpus that the DIRECTX9 renderer matches exactly.
